## 실습 2 - AI에게 폴더 정리를 맡기고 검토하기

### 난잡한 바탕화면(또는 연습용 폴더)을 Claude Code와 정리하기 (60분)

이 실습의 목표는 AI가 파일을 "치우게" 하는 것이 아니라, **분류 계획을 먼저 내고 내가 승인하는 협업**입니다. 중요한 파일이 있거나 실제 바탕화면이 부담스러우면 방금 만든 `terminal-practice` 폴더에서만 연습합니다.

**Claude Code에 보낼 프롬프트 예시**

> 프롬프트: "현재 작업 폴더의 파일과 폴더를 읽고 정리 계획을 세워줘.
>
> 규칙:
> 1. 삭제 명령(rm 등)은 절대 실행하지 마.
> 2. 먼저 dry-run으로 파일별 '현재 위치 → 제안 위치' 목록과 분류 기준만 보여줘.
> 3. 이동은 내가 목록을 검토하고 '승인'이라고 답한 뒤에만 실행해.
> 4. 이름을 추측하지 말고, 확장자와 현재 이름을 근거로 분류해.
> 5. 실행 뒤에는 이동한 목록과 남은 파일 목록을 보여줘."

dry-run은 실제 변경 없이 "무엇을 할지" 미리 보여 주는 실행 계획입니다. AI가 먼저 `mv`를 실행하려 하면, "아직 실행하지 말고 dry-run 목록만 보여줘"라고 바로 중단시킵니다.

**AI 산출물 검토 체크리스트**

| 확인할 것 | 통과 기준 | 내 판단 |
| :--- | :--- | :--- |
| 파일 이동 전 dry-run | 각 파일의 현재 위치와 제안 위치가 목록으로 있다 | ☐ |
| 삭제 방지 | 삭제 명령·삭제 제안이 없고, 보류 파일은 그대로 둔다 | ☐ |
| 분류 기준 | 확장자·용도 등 읽을 수 있는 기준이 있고 애매한 파일은 질문한다 | ☐ |
| 경로 안전 | 작업 폴더 밖의 파일을 건드리지 않고, 중요한 폴더를 통째로 이동하지 않는다 | ☐ |
| 실행 후 확인 | `ls` 또는 목록으로 이동 결과와 남은 항목을 보여 준다 | ☐ |

**승인·수정 요청 예시**

> 프롬프트: "계획을 검토했어. .png와 .jpg만 images 폴더로 옮기고,
> 확장자를 알 수 없는 파일과 프로젝트 폴더는 그대로 둬.
> 삭제·이름 변경은 하지 마. 실행 후 이동 전후 목록을 비교해 보여줘."
