# [1.바이브코딩을 위한 작업대 마련하기] - 2. 내 작업대 상태 확인하기

---

## 내 작업대 상태 확인하기

```
Claude Code와 도구 상태 확인

$ node --version
v22.14.0 ✓

$ git --version
도구 준비 완료

오류는 다음 지시의 단서
```

### 개발 환경 설치

설치를 확인하기 전에, 필요한 도구가 같이 깔려 있어야 합니다. **Claude Code**(명령을 맡길 메인 도구), **Node.js와 npm**(웹 도구를 실행하는 환경), **Git**(변경 기록) 세 가지입니다. 이 중 Claude Code는 여러분이 이미 쓰고 있는 Claude Desktop 안에서 바로 실행할 수 있습니다.

두 길 중 하나를 고르세요. 어떤 길을 택하든, 마지막엔 직접 확인하는 단계로 이어집니다. "AI가 깔아줬다"에서 멈추지 않고, "내 컴퓨터에서 된다"를 눈으로 확인하는 것이 오늘의 목표입니다.

**🅰️ 빠른 길 - Claude Code에게 맡기기 (AI 네이티브)**

Claude Desktop을 켜고, 그 안의 Claude Code를 엽니다. 그리고 자연어로 환경 세팅을 맡깁니다.

> 프롬프트: "이 컴퓨터에서 웹 개발을 시작하려고 해.
> 내가 macOS/Windows 환경이야. (본인 OS로 바꿔 말합니다)
>
> 확인해 줄 것:
> 1. Node.js와 npm이 깔려 있는지, 깔려 있지 않다면 공식 방법으로 설치해 줘.
> 2. Git이 깔려 있는지, 없다면 설치해 줘.
> 3. 각각 버전을 출력해 줘.
>
> 설치가 끝나면, 각 도구의 버전 명령(node --version, npm --version, git --version) 결과를 보여줘."

🤔 **왜 "버전을 보여줘"라고 덧붙일까요?** AI가 "설치했습니다"라고 답해도, 그 말만으로는 내 컴퓨터에서 진짜로 되는지 알 수 없습니다. 버전 출력은 **AI의 주장을 내가 검증**하는 가장 단순한 방법입니다. 이 습관이 앞으로 모든 바이브 코딩의 기본이 됩니다.

**🅱️ 손으로 직접 설치하기 (기본기)**

도구가 어떻게 들어오는지 직접 보고 싶다면, 공식 문서의 방법으로 하나씩 깝니다. 공식 문서를 기준으로 삼는 이유는, 버전이 바뀌어도 가장 믿을 수 있는 출처이기 때문입니다.

**Node.js와 npm - nvm으로 관리합니다**: Node.js 자체를 한 번 고정 설치하지 않고 **nvm(Node Version Manager)** 으로 설치·전환합니다. 프로젝트마다 필요한 Node.js 버전이 다를 수 있으므로, `nvm use`로 버전을 바꿀 수 있고 `--lts`로 현재 LTS를 관리할 수 있습니다. 즉 한 프로젝트의 Node.js가 다른 프로젝트를 덮어쓰지 않게 돕습니다. npm은 nvm으로 설치한 Node.js에 함께 들어옵니다.

**권한 문제를 줄이는 이유도 있습니다.** macOS·Linux·WSL에서 Node.js를 시스템 위치에 직접 설치하면, 전역 패키지(`npm install -g ...`)를 설치할 때 쓰기 권한이 없어 `EACCES` 오류가 나고 `sudo`를 붙여야 하는 경우가 많습니다. 이 때문에 설치가 중단되는 학생도 많습니다.

nvm은 기본적으로 홈 디렉터리의 `~/.nvm` 아래에서 Node.js 버전과 실행 바이너리 디렉터리를 관리합니다. 내 계정이 쓸 수 있는 위치를 사용하므로, nvm으로 설치한 Node.js의 전역 npm 패키지는 보통 `sudo` 없이 설치할 수 있어 권한 충돌을 피하는 데 도움이 됩니다. (`sudo npm install -g`는 사용하지 않습니다.)

**macOS / Linux / WSL** — nvm 공식 저장소의 설치 스크립트를 실행합니다. 이 노트북 작성 시점의 공식 최신 릴리스는 **v0.40.5**입니다. 터미널을 닫았다가 다시 열고 다음을 실행합니다.

```bash
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.5/install.sh | bash
nvm install --lts
nvm use --lts
node --version
npm --version
```

`nvm install --lts`는 현재 LTS Node.js를 설치하고, `nvm use --lts`는 지금 이 터미널에서 그 LTS를 사용합니다. 다른 프로젝트가 특정 버전을 요구하면 그 프로젝트 폴더에서 예를 들어 `nvm install 22`와 `nvm use 22`처럼 전환합니다.

**Windows (PowerShell/명령 프롬프트)** — Unix용 nvm과 별개인 **nvm-windows** 공식 Releases에서 최신 `nvm-setup.exe`를 내려받아 설치합니다. 설치 뒤 새 터미널에서 다음처럼 LTS의 명시적 버전 번호를 설치·선택합니다(Windows용 nvm은 `--lts` 별칭을 제공하지 않습니다).

```powershell
nvm install <LTS-버전>
nvm use <LTS-버전>
node --version
npm --version
```

`<LTS-버전>`은 Node.js 공식 다운로드 페이지에 표시된 LTS 버전 번호로 바꿉니다. Windows에서는 관리자 권한이 필요한 경우가 있으므로, `nvm use`가 실패하면 관리자 권한으로 새 터미널을 열어 다시 실행합니다.

> **출처 확인 습관**: 설치 명령을 복사하기 전 링크의 태그와 릴리스 페이지를 함께 확인합니다. nvm은 업데이트되므로, 수업 중 더 최신 공식 릴리스가 보이면 그 태그의 install.sh URL을 사용합니다.

**uv**: uv 공식 설치 문서의 설치 명령으로 깝니다. (macOS/Linux는 `curl -LsSf https://astral.sh/uv/install.sh | sh`, Windows는 공식 문서의 PowerShell 명령.)

**Git**: Git 공식 다운로드에서 운영체제에 맞는 버전을 설치합니다.

**Claude Code**: Claude Code 공식 설치 문서를 기준으로 설치합니다. 터미널에서 `claude` 명령으로 불러옵니다.

**Claude Code 설치 명령**

macOS/Linux/WSL 터미널에서는 다음 명령을 실행합니다.

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

Windows PowerShell에서는 다음 명령을 실행합니다.

```powershell
irm https://claude.ai/install.ps1 | iex
```

또는 Node.js 22 이상이 설치되어 있다면 npm으로 설치할 수 있습니다.

```bash
npm install -g @anthropic-ai/claude-code
```

Claude Code는 Python 패키지가 아니므로 `uv tool install claude-code`로 설치하지 않습니다. uv는 Python 프로젝트·도구 관리용입니다.

설치 뒤에는 다음 명령으로 설치 여부를 확인하고 실행해 봅니다.

```bash
claude --version
claude
```

공식 문서 한 줄씩을 직접 치는 과정이 귀찮게 느껴질 수 있지만, 나중에 문제가 생겼을 때 "어디서부터 왔는지" 아는 힘이 됩니다.

### 확인 브릿지 - 어떤 길로 깔았든 내가 확인한다

두 길 모두, 설치가 끝났다고 넘어가지 말고 직접 터미널을 열어 버전을 확인합니다. 아래 명령은 다음 챕터 '작업대 상태표'의 첫 칸을 채우는 재료가 됩니다.

```bash
node --version
npm --version
git --version
```

숫자가 보이면 설치가 된 것입니다. `command not found`가 나오면, 그 한 줄을 그대로 복사해 AI에게 보여줍니다. (다음 섹션에서 이 방법을 다룹니다.)

설치 확인은 통과 의식이 아니라, 앞으로 AI에게 문제를 설명할 때 쓰는 **증거 수집**입니다. "안 돼요"라고 말하면 AI도 추측합니다. 반대로 "`node --version`을 입력했더니 `command not found`가 나왔습니다"라고 말하면 AI는 다음 행동을 좁힐 수 있습니다.

아래 명령은 여러분 컴퓨터의 터미널에서 실행합니다. (Claude Code도 이 터미널에서 `claude`를 입력해 실행합니다.)

```bash
pwd
node --version
npm --version
uv --version
git --version
claude --version
```

설치가 안 되어 있거나 명령이 동작하지 않으면, 그 결과 자체가 오늘의 학습 자료입니다. 실패 화면을 숨기지 말고 그대로 기록합니다.

### 작업대 상태표

아래 표를 자기 노트에 채웁니다. 빈칸은 본인 컴퓨터의 결과로 채워야 합니다.

| 확인 항목 | 내 터미널 출력 | 판단 | 다음 행동 |
| :--- | :--- | :--- | :--- |
| `pwd` | ____ | 현재 위치를 알 수 있는가 | ____ |
| `node --version` | ____ | 버전 번호가 나오는가 | ____ |
| `npm --version` | ____ | 버전 번호가 나오는가 | ____ |
| `uv --version` | ____ | 버전 번호가 나오는가 | ____ |
| `git --version` | ____ | 버전 번호가 나오는가 | ____ |
| `claude --version` | ____ | 버전 번호가 나오는가 | ____ |
| 프로젝트 폴더에서 Claude Code 실행 (`claude`) | ____ | 정상 실행되는가 | ____ |

**판단 기준 예시**

- `v20.11.1`처럼 버전 번호가 나오면 해당 도구는 실행됩니다. 숫자는 컴퓨터마다 다를 수 있습니다.
- `command not found`, `not recognized`, `No such file or directory`는 설치나 경로 문제일 수 있습니다.
- 오류를 만났다면 해결 전까지 무작정 여러 명령을 치기보다, 지금 나온 출력 한 줄을 복사해 AI에게 설명합니다.

### AI에게 오류를 설명하는 방식

설치 오류가 나오면 아래 틀로 AI에게 묻습니다. 핵심은 **환경, 실행한 명령, 실제 출력**을 분리해서 주는 것입니다.

```
나는 macOS/Windows 환경에서 웹 개발 작업대를 설정하고 있어.
터미널에서 아래 명령을 실행했어.

명령:
node --version

출력:
[여기에 실제 오류 메시지 붙여넣기]

내 목표는 Day 4 실습을 진행할 수 있게 Node.js와 npm 버전을 확인하는 거야.
원인을 추정하지 말고, 내가 먼저 확인할 순서 3가지만 알려줘.
```
