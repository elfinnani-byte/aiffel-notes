# [1.바이브코딩을 위한 작업대 마련하기] - 4. 바이브 코딩 루프 한 번 돌리기

## 바이브 코딩 루프 한 번 돌리기

이번 챕터가 오늘의 중심입니다. 설치와 파일 생성은 준비이고, 바이브 코딩은 여기서 시작됩니다.

바이브 코딩 루프는 네 단계입니다.

1. 만들 것을 자연어로 또렷이 말합니다.
2. AI가 코드를 생성합니다.
3. 여러분이 결과를 읽고 판단합니다.
4. 다시 지시해 수정합니다.

오늘은 작은 수정 하나로 이 루프를 경험합니다. 목표는 화려한 화면이 아니라, **AI 출력에 대해 근거 있는 재요청을 하는 것**입니다.

### 두 번째 요청: 도메인 섹션 추가

AI에게 아래처럼 다시 요청합니다. 첫 요청과 다른 점은 "무엇을 추가할지"와 "무엇은 건드리지 말지"를 함께 말한다는 점입니다.

> 프롬프트: "방금 만든 index.html을 수정해줘.
> 추가할 것:
> - 내 도메인에서 AI로 개선하고 싶은 반복 업무 3개를 목록으로 보여줘.
> - 각 항목은 한 줄 설명을 붙여줘.
>
> 지킬 것:
> - 기존 제목과 첫 문장은 유지해줘.
> - HTML 구조가 읽기 좋게 들여쓰기되어야 해."

🤔 **예측해보세요**: AI가 이 요청에서 실수할 만한 지점은 무엇일까요? 예를 들어 기존 문장을 바꾸거나, CSS를 추가하거나, 업무 3개가 도메인과 맞지 않을 수 있습니다.

```html
<!-- AI가 수정한 결과 예시입니다. 검토하면서 읽으세요. -->
<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>나의 첫 웹페이지</title>
</head>
<body>
  <h1>교육 운영 전문가 김아이펠</h1>
  <p>교육 현장에서 반복되는 안내 업무에 AI를 활용해 보고 싶습니다.</p>

  <section>
    <h2>AI로 개선하고 싶은 반복 업무</h2>
    <ul>
      <li>수강생 문의 분류: 자주 들어오는 질문을 주제별로 나눕니다.</li>
      <li>공지 초안 작성: 일정과 준비물을 빠뜨리지 않도록 초안을 만듭니다.</li>
      <li>피드백 정리: 설문 응답에서 반복되는 의견을 묶어 봅니다.</li>
    </ul>
  </section>
</body>
</html>
```

### 판단하고 재요청하기

AI 출력이 나왔으면 곧바로 적용하지 말고 아래 표로 판단합니다.

| 판단 항목 | 통과/수정 필요 | 재요청 문장 |
| :--- | :--- | :--- |
| 기존 제목과 첫 문장이 유지되었는가 | ____ | ____ |
| 업무 3개가 내 도메인에 맞는가 | ____ | ____ |
| 목록 설명이 현장에서 쓰는 말인가 | ____ | ____ |

재요청은 이렇게 씁니다.

> 프롬프트: "좋아. 다만 목록 3개가 내 실제 업무와 조금 달라.
> 아래처럼 바꿔줘.
> 1. [내 업무 1]
> 2. [내 업무 2]
> 3. [내 업무 3]"

이 한 번의 왕복이 오늘의 핵심 루프입니다. **지시 → 생성 → 판단 → 수정 지시**가 돌아갔다면, 개발 환경은 더 이상 설치 목록이 아니라 작업대가 됩니다.
