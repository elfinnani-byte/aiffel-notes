# 퀘스트 정리

[!info]
① 기존 AI : 텍스트만 처리하거나 이미지만 처리하는 전문 모델
      ↓ 문제 발생
② 현실의 업무는 `텍스트 + 이미지 + 음성` 모두 함께 사용한다.
③ 그래서 **멀티모달(Multimodal)** 이 등장
④ 그런데 컴퓨터는 이미지를 글처럼 이해하지 못한다.
⑤ **[[CLIP(Contrastive Language–Image Pre-training)|CLIP]]** 등장 : 이미지와 문장을 같은 의미 공간으로 보낸다.
⑥ 그래서 사진을 문장처럼 비교할 수 있게 된다.
⑦ 이것이 발전하여 **VLM(Vision Language Model), GPT-4o, Gemini 같은 네이티브 멀티모달** 모델


---

# STEP 1. 기존 AI는 하나만 잘했다.

먼저 과거의 AI를 생각해봅시다.

예를 들어

```
텍스트 AI → 문장을 읽는다. 요약한다. 번역한다.
```

반대로

```
이미지 AI → 고양이를 찾는다. 사람을 찾는다. 얼굴을 인식한다.
```

즉,

**각 AI가 한 가지 일만 잘했습니다.** 

---

# STEP 2. 그런데 현실은 그렇지 않다.

실제 업무에서는 세 가지를 함께 봐야 합니다.

보험회사라면

```
사고 사진 + 수리 견적서 + 상담 녹취
```

병원에서는

```
CT 영상 + 환자 차트 + 의사 음성
```

교육에서는

```
학생 발표 영상 + 발표 원고 + 학생 음성
```

즉 현실은

> 여러 종류의 정보를 동시에 봐야 합니다. 

---

# STEP 3. 그래서 멀티모달 AI가 등장했다.

- 멀티(Multi) = 여러 개
- 모달(Modality) = 정보의 형태

예를 들면 `텍스트, 이미지, 음성, 영상, 센서 데이터` 이 모든 것이 모달리티입니다. 

즉 멀티모달 AI는 `여러 종류의 정보를 → 한 번에 이해하는 AI` 입니다

---

# STEP 4. 그런데 문제가 생긴다.

컴퓨터 입장에서 문장은 글자입니다.

```
안녕하세요
```

반면 이미지는 수백만 개의 픽셀입니다.

```
□□□□□□□
□□□□□□□
□□□□□□□
```

컴퓨터는 `글 ≠ 사진` 이라고 생각합니다.

그래서 사진을 글처럼 이해하는 방법이 필요했습니다.

---

# STEP 5. CLIP이 등장했다.

여기서 **CLIP**이 나옵니다. 

자료에서 가장 중요한 모델입니다. 

CLIP은

이미지
↓
숫자 벡터

문장
↓
숫자 벡터

로 바꿉니다.

즉

```
사진

↓

[0.15, 0.82, ...]
```

```
문장

↓

[0.13, 0.79, ...]
```

둘 다 숫자로 변환합니다.

---

# STEP 6. 같은 공간에 놓는다.

이 부분이 CLIP의 핵심입니다.

예를 들어

사진

🐶

문장

"a photo of a dog"

둘을 같은 좌표 공간에 놓습니다. 

```
             고양이

                ●


강아지 사진 ●●●● 강아지 문장


                ●

             자동차
```

강아지 사진과 강아지 문장이 가까워집니다.

반대로

```
강아지 사진

↓

자동차 문장
```

은 멀리 떨어집니다.

---

# STEP 7. 이것을 대조학습(Contrastive Learning)이라고 한다.

학습할 때 맞는 짝은 가깝게 틀린 짝은 멀어지게 학습합니다. 
이것이 대조학습입니다.

예를 들면

```
🐶 → "a dog"

★★★★★ (가깝게)
```

하지만

```
🐶 → "an airplane"

★ (멀어지게)
```

됩니다.


---

# STEP 8. 왜 번역이 아니라고 할까?

많은 사람들이 `사진 → 사진 설명 생성 → LLM` 이라고 생각합니다.

하지만 자료에서는 이것이 핵심이 아니라고 설명합니다. 

실제 핵심은 `사진 → 표현(Representation) → 공유 의미 공간 → 추론`입니다.

즉 사진을 문장으로 번역하는 것이 아니라 사진과 문장을 같은 의미 공간으로 정렬하는 것입니다.


즉,

```
사진

↓

의미

↑

문장
```

으로 연결한 것입니다.

이전에는

```
사진 ≠ 문장
```

이었는데,

CLIP 이후에는

```
사진 ≒ 문장
(의미 기준으로 비교 가능)
```

이 되었습니다.


# STEP 9. 그럼 질문도 할 수 있지 않을까?(VLM으로 발전)

CLIP 이후 `이미지 + 언어`를 함께 다루는 **VLM(Vision-Language Model)** 이 발전합니다. 

이제 AI는 `사진을 보고 → 질문에 답하고 → 설명하고 → 추론`할 수 있게 됩니다.

---
### 그럼 질문도 할 수 있지 않을까?

CLIP이 할 수 있는 것은 `"사진과 문장이 얼마나 비슷한가?"` 였습니다.

예를 들면 `🐶 → 강아지인가?` 정도는 잘합니다.

그런데 사람들은 생각했습니다.

> "비교만 하지 말고 질문도 할 수 있으면?"

예를 들어 사진을 보여주고

```
이 사람이 무엇을 하고 있나요?

왜 위험해 보이나요?

빨간색 물건은 어디 있나요?
```

이런 질문도 하고 싶었습니다. 
하지만 CLIP은 대화를 하는 모델이 아닙니다.

---

### 그래서 LLM과 연결한다.

여기서 등장한 것이 **Vision-Language Model(VLM)** 입니다.
구조를 단순하게 그리면

```
사진
↓
이미지 인코더
↓
이미지 표현
↓
LLM
↓
답변
```

즉, 사진의 의미를 LLM에게 전달하는 것입니다. 그래서

```
사진
↓
"고양이가 창문 위에 앉아 있다."
↓
LLM
↓
"창밖을 바라보고 있습니다."
```

처럼 설명하거나 질문에 답할 수 있게 되었습니다. 
자료에서는 이런 방식을 **연결형** 구조의 대표적인 설계로 설명합니다. 

---

### 그런데 아직도 모델이 여러 개였다.

문제가 하나 남았습니다. 예를 들어 사용자가 음성으로

> "이 사진 설명해줘."

라고 말하면 예전 구조에서는

```
음성
↓
음성인식(STT)
↓
텍스트
↓
LLM
↓
텍스트 답변
↓
음성합성(TTS)
↓
음성 출력
```

처럼 여러 모델을 차례대로 거쳐야 했습니다.
이미지도 별도, 음성도 별도, LLM도 별도였습니다.
그래서 속도가 느리고, 중간 과정에서 정보가 일부 사라질 수도 있었습니다. 

---

# STEP 10. 그래서 하나로 합치자(네이티브 멀티모달 등장)

최근에는 생각이 바뀌었습니다.

> "왜 여러 모델을 거치지?"

> "처음부터 하나의 모델이 다 처리하면 되잖아."

그래서 나온 것이 **네이티브 멀티모달 모델**입니다.

```
텍스트, 이미지, 음성, 영상
↓
하나의 모델
↓
답변
```

즉, 중간에 `음성 → 텍스트 → LLM → 음성`처럼 여러 단계를 거치지 않고, 처음부터 다양한 입력을 하나의 모델이 함께 이해하도록 설계하는 것입니다. 자료에서도 이러한 방향을 **네이티브 멀티모달형**이라고 소개합니다.  

대표적인 예가 **OpenAI의 GPT-4o, Google의 Gemini** 입니다.

---

# 초보자가 꼭 기억해야 할 핵심 5가지

|핵심|한 줄 요약|
|---|---|
|① 기존 AI|텍스트와 이미지를 따로 처리했다.|
|② 멀티모달|여러 종류의 입력을 함께 이해한다.|
|③ CLIP|이미지와 문장을 같은 의미 공간으로 정렬한다.|
|④ 대조학습|맞는 짝은 가깝게, 틀린 짝은 멀게 학습한다.|
|⑤ 최신 AI|텍스트·이미지·음성을 하나의 모델에서 함께 처리한다.|

### 한 문장으로 정리

> **기존 AI는 텍스트와 이미지를 따로 이해했지만, CLIP은 이미지와 문장을 같은 의미 공간에 정렬하여 연결했고, 이 아이디어가 발전해 오늘날의 멀티모달 AI와 VLM, 그리고 GPT-4o와 Gemini 같은 네이티브 멀티모달 모델로 이어졌습니다.**

```
────────────────────────

텍스트 AI

이미지 AI

음성 AI

(모두 따로)


            │

            ▼

② CLIP
────────────────────────

사진와 문장을

같은 의미 공간으로 정렬


            │

            ▼

③ VLM
────────────────────────

사진

↓

LLM이 이해

↓

질문·답변 가능


            │

            ▼

④ 네이티브 멀티모달
────────────────────────

텍스트

이미지

음성

영상

↓

하나의 AI가 동시에 이해
```

# 비유하면 더 쉽습니다.

이 발전 과정을 **회의**에 비유해 보겠습니다.

### ① 과거 AI

각 부서가 따로 일합니다.

```
사진 전문가

문서 전문가

음성 전문가
```

서로 대화하지 않습니다.

---

### ② CLIP

드디어 모두 **같은 언어**를 쓰기 시작합니다.

사진 전문가도,

문서 전문가도,

"같은 좌표계"로 정보를 표현하므로 서로 비교할 수 있습니다.

---

### ③ VLM

이제 회의실에 **의사결정자(LLM)** 가 들어옵니다.

사진 전문가가 설명하고,

LLM이 그 정보를 바탕으로 질문에 답하고 추론합니다.

---

### ④ 네이티브 멀티모달

아예 전문가를 따로 둘 필요가 없어집니다.

한 사람이

- 사진도 보고,
    
- 문서도 읽고,
    
- 음성도 듣고,
    
- 영상을 이해하며
    

모든 정보를 한꺼번에 종합해서 판단하는 것과 비슷합니다.

---

## 핵심 한 줄

**CLIP은 "사진과 문장을 같은 의미로 연결하는 방법"을 제시했고, VLM은 그 연결된 정보를 LLM이 활용해 질문에 답하고 추론하도록 발전했으며, 네이티브 멀티모달 모델은 한 단계 더 나아가 텍스트·이미지·음성 등을 처음부터 하나의 모델 안에서 함께 이해하고 처리하도록 설계된 발전 형태입니다.** 이는 사용자가 올려주신 자료의 흐름과 일치합니다.

---

[!note] 왜 **정렬** 이라고  표현할까?

사실 대부분의 사람들이 **"정렬(Alignment)"**에서 막힙니다. 이유는 **공간(Embedding Space)**이라는 개념이 눈에 보이지 않기 때문입니다.

그림 없이 가장 쉬운 예로 설명해보겠습니다.

---

# 먼저 번역과 정렬의 차이

우리가 흔히 생각하는 방식은 **번역**입니다.

```
사진
   ↓
"강아지 사진입니다."
   ↓
LLM이 문장을 읽음
```

즉,

**사진을 먼저 문장으로 바꾼 후** 생각합니다.

---

그런데 CLIP은 이렇게 하지 않습니다.

```
사진
   ↓
숫자

문장
   ↓
숫자

↓

숫자끼리 비교
```

여기서 핵심은

> **사진을 문장으로 바꾸지 않는다.**

입니다. 

---

# "표현(Representation)"이란?

예를 들어

강아지 사진이 있다고 해봅시다.

사람은

> "강아지"

라고 바로 이해합니다.

하지만 컴퓨터는

```
255
123
85
...
```

같은 픽셀 숫자밖에 모릅니다.

그래서 AI는

사진을

```
[0.21, -0.53, 0.84, ...]
```

같은 **의미를 담은 숫자 벡터**로 바꿉니다.

이 숫자 벡터를

**표현(Representation)**

또는

**임베딩(Embedding)**

이라고 부릅니다. 

---

# 공유 의미 공간이란?

이제 강아지 사진과

"a photo of a dog"

문장을 각각 숫자로 바꿉니다.

```
강아지 사진

↓

[0.21, 0.31, 0.92]
```

```
"a photo of a dog"

↓

[0.19, 0.29, 0.91]
```

놀랍게도 숫자가 매우 비슷해집니다.
왜냐하면 **둘 다 "강아지"라는 같은 의미**를 담고 있기 때문입니다.

# 이것이 "공유 의미 공간"

이걸 좌표평면이라고 생각하면 쉽습니다.

```
                 자동차

                  ●


고양이 ●


강아지 사진 ●● 강아지 문장


              ●

             사과
```

여기서는

- 강아지 사진
    
- "강아지" 문장
    

이 거의 같은 위치에 있습니다.

반면 `강아지 사진`과 `자동차 문장`은 멀리 떨어져 있습니다.

# 이것을 왜 "정렬"이라고 부를까?

정렬이라는 말은 **같은 의미를 가진 것끼리 같은 위치에 모으는 것**입니다.

예를 들어 사진과 문장은 원래 완전히 다른 데이터입니다.

```
사진

■■■■■■

문장

I love dogs.
```

원래는 비교 자체가 안 됩니다. 
그런데 CLIP은

```
강아지 사진  → 📍 (3,5)

강아지 문장 → 📍 (3,4)
```

처럼 **같은 좌표 근처**에 오도록 학습합니다.
이것이 바로 **정렬(Alignment)** 입니다. 

---

# 그러면 추론은 어떻게 할까?

예를 들어 사진 하나를 넣었습니다.

```
🐶
```

사진은 `📍 (3,5)`라는 위치가 됩니다.

그리고 AI는 미리 준비한 문장들의 위치를 알고 있습니다.

```
"a dog"  📍 (3,4)

"a cat"  📍 (7,9)

"an airplane"  📍 (-2,8)
```

사진 위치와 가장 가까운 것은?

```
🐶 사진

↓

📍 (3,5)

↓

가장 가까운 문장

↓

"a dog"
```

그래서

> "이 사진은 강아지입니다."

라고 판단합니다.

---

# 그래서 자료에서 "번역이 아니라 정렬"이라고 하는 이유

많은 사람들이

```
사진

↓

설명문 생성

↓

LLM
```

이라고 생각합니다.

하지만 CLIP은

```
사진

↓

의미를 담은 숫자(표현)

↓

문장도 같은 숫자 공간으로 이동

↓

가까운 것끼리 비교

↓

판단
```

합니다.

즉,

**사진을 문장으로 번역하는 것이 아니라, 사진과 문장을 같은 의미 좌표계에 올려놓고 거리를 비교하는 것**입니다. 이것이 자료에서 말하는 **"정렬(Alignment)"**의 핵심입니다. 

### 한 문장으로 기억하면

> **정렬이란 "사진을 문장으로 바꾸는 것"이 아니라, 사진과 문장을 모두 같은 좌표계(공유 의미 공간)에 배치해서 같은 의미라면 서로 가깝게 위치하도록 만드는 것**입니다.
