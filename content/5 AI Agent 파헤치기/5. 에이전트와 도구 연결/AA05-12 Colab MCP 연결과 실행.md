## Colab MCP 연결과 실행

주간 보고서를 완성한 뒤, 팀원이 새로운 활용을 제안했다고 해 봅시다. "앞으로는 학습 시간 같은 기록도 모아서 평균을 보고 싶어요. 어떤 값을 계산했는지 다시 확인할 수 있게 남기면 좋겠어요." 앞에서 만든 업무 보고서에는 없던 새로운 계산 과업입니다. 대화에 답만 남겨 두면 며칠 뒤 같은 계산을 확인하기가 번거롭습니다. 입력값을 찾고, AI에게 다시 요청하고, 처음과 같은 방식으로 계산했는지도 맞춰야 합니다.

이번에는 입력 데이터, 계산 코드, 실행 결과, 설명을 한 문서에 남겨 보겠습니다. 이 일을 할 수 있는 문서가 **노트북(notebook)**입니다. Colab은 브라우저에서 이런 노트북을 작성하고 Python 코드를 실행하는 환경입니다. 여기에 MCP를 연결하면 평소 사용하던 Claude Code나 OpenCode에 요청하면서 Colab의 계산 과정을 함께 볼 수 있습니다.

앞에서 만든 보고서 Skill은 팀의 판단 기준을 재사용하는 데 쓰였습니다. 이번의 Colab은 계산을 실행하고 그 과정을 남기는 데 씁니다. 보고서에 계산이 필요하면 둘을 함께 활용할 수 있습니다. 먼저 아주 작은 계산으로 연결을 확인한 뒤, 입력을 바꾸어 다시 계산하는 경험까지 이어 가겠습니다.

### 노트북 문서와 런타임

먼저 다음 화면에서 왼쪽의 빈 사각형을 찾아보세요. 이 한 칸을 **셀(cell)**이라고 합니다. 노트북에는 Python을 적는 코드 셀과, 제목·설명 등을 적는 텍스트 셀을 둘 수 있습니다. 코드 셀을 실행하면 그 아래에 출력이 나타납니다. 따라서 "어떤 코드를 실행해서 이 숫자가 나왔는가"를 같은 자리에서 읽을 수 있습니다.

![Colab scratchpad의 첫 화면. 왼쪽에는 빈 코드 셀, 오른쪽 위에는 런타임 Connect 버튼이 있습니다](colab-mcp-start.png)<span class="img-caption">2026-09-06 강사가 제공한 Colab 첫 화면. 왼쪽 빈 셀과 상단의 노트북 이름 scratchpad, 오른쪽 위의 Connect를 찾아본다. 오른쪽 Gemini 패널은 Colab에 포함된 별도의 AI 대화 화면이다. 이번 실습의 요청은 평소 사용하는 Claude Code·OpenCode에 입력한다.</span>

브라우저에서 코드를 작성했다고 해서 Python이 실행되고 있는 것은 아닙니다. 코드를 실행할 **런타임(runtime)**이 필요합니다. 런타임은 Python을 실제로 실행하고, 실행 중 만든 변수와 설치한 라이브러리를 보관하는 환경입니다. 이 수업에서는 Colab이 제공하는 원격 실행 환경을 사용합니다.

예를 들어 노트북에 minutes = [20, 30, 40]이라고 적으면 문서에 코드가 저장됩니다. 이 셀을 실행해야 런타임 안에 minutes라는 변수가 만들어집니다. 런타임이 새로 시작되면 노트북에 코드는 그대로 보여도 변수는 아직 없을 수 있습니다. 문서에 적힌 코드와 실행 중인 상태를 구분하는 것이 노트북 사용의 출발점입니다. Colab의 노트북과 실행 환경에 대한 설명은 [공식 FAQ](https://research.google.com/colaboratory/faq.html)에서도 확인할 수 있습니다.

이제 MCP 연결까지 포함해서 역할을 나누어 보겠습니다. 다음은 요청이 거치는 프로그램을 학생의 작업 위치에 따라 나타낸 그림입니다.

```text
내 컴퓨터의 Claude Code 또는 OpenCode
          ↓ 도구 호출 요청
내 컴퓨터에서 실행하는 Colab MCP 서버
          ↓ 연결된 노트북 조작
Chrome의 Colab 노트북
          ↓ 코드 셀 실행
Colab 런타임의 Python
```

여기서 Colab MCP 서버는 내 컴퓨터에서 실행됩니다. 반면 노트북 셀에 적은 Python 계산은 Colab 런타임에서 실행됩니다. 앞에서 만든 weekly_records_server.py를 Colab 셀에 붙여 넣는 실습이 아닙니다. 새로운 MCP 서버를 로컬 호스트에 등록하고, 그 서버를 통해 브라우저의 노트북을 조작하는 실습입니다.

"셀을 하나 추가해 줘"라는 요청은 노트북 문서를 바꿉니다. "그 셀을 실행해 줘"라는 요청은 런타임에 계산을 시킵니다. 셀은 생겼는데 결과가 나오지 않았다면 두 동작 중 첫 번째까지만 된 것일 수 있습니다. 잠시 뒤 이 차이를 실제 화면에서 확인하겠습니다.

### Chrome과 로컬 실행 도구 준비

이 수업에서는 Google Chrome을 권장합니다. 기존 실습에서 Chrome으로 승인 창과 셀 실행까지 확인했습니다. 연결 도구는 컴퓨터의 기본 브라우저를 열 수 있으므로, Chrome을 기본 브라우저로 두면 같은 환경에서 따라가기 편합니다. 공식 저장소가 Chrome만 지원한다고 안내하는 것은 아닙니다. 수업에서 확인한 환경을 맞추기 위한 권장입니다.

내 컴퓨터의 Chrome에서 실습에 사용할 Google 계정으로 로그인합니다. 여러 계정을 쓰고 있다면 이후 저장할 노트북이 어느 계정에 들어갈지도 함께 확인해 두세요. 아직 일반 Colab 페이지를 열어 둔 것만으로 MCP 연결이 끝난 것은 아닙니다. 잠시 뒤 AI가 연결 도구를 호출해서 연 탭에서 연결을 승인합니다.

로컬 프로그램을 준비할 때 필요한 도구도 있습니다. Colab MCP 프로그램은 Python 3.13 이상을 요구합니다. 이것은 내 컴퓨터에서 MCP 서버를 실행하는 Python의 조건입니다. Colab 노트북 셀의 Python을 3.13으로 바꾸라는 뜻이 아닙니다. [프로젝트의 실행 조건](https://github.com/googlecolab/colab-mcp/blob/main/pyproject.toml)에 명시되어 있습니다.

아래 설정에서는 uv로 Colab MCP 프로그램의 실행 환경을 준비합니다. uvx는 uv에 포함된 명령으로, 도구가 필요한 패키지를 별도 환경에 설치하고 실행하게 해 줍니다. 또 공식 저장소에서 프로그램을 가져오기 위해 Git이 필요합니다. 앞에서는 uv sync와 uv run으로 우리가 만든 실습 프로젝트의 환경을 준비하고 실행했습니다. 이번에는 공개된 Colab MCP를 별도 도구로 실행하므로 uvx를 사용합니다. Colab MCP의 패키지를 업무 기록 프로젝트에 섞어 설치할 필요는 없습니다.

공식 [Colab MCP 저장소](https://github.com/googlecolab/colab-mcp)를 에이전트에게 전달하고 짧게 요청해 보세요.

> 이 Colab MCP를 지금 쓰는 도구에 연결해 줘. Chrome에서 노트북을 실행해 보고 싶어.

에이전트가 설치 여부와 공식 실행 방법을 확인하게 합니다. 학생이 볼 것은 명령을 얼마나 길게 생성했는지가 아니라 어느 호스트 설정을 바꿨고, 내 컴퓨터에서 서버가 실행될 준비가 됐는지입니다. 설정을 읽기 위해 호스트를 다시 시작하라는 안내가 있으면 따릅니다. 이미 다른 MCP 설정이 있다면 해당 서버를 추가하는 변경인지도 함께 살펴보세요.

> [!info]+ **수동으로 설정하기 — Colab MCP**
> Claude Code에서는 실습 프로젝트의 로컬 터미널에서 다음 명령을 실행합니다.
>
> ```bash
> claude mcp add --transport stdio --scope project colab-mcp -- uvx --python 3.13 git+https://github.com/googlecolab/colab-mcp
> ```
>
> 앞부분은 Claude Code에 colab-mcp라는 이름으로 로컬 서버를 등록합니다. --scope project는 이 프로젝트에서 사용하는 설정으로 남깁니다. -- 뒤는 실제로 서버를 시작할 명령입니다. uvx가 저장소의 도구를 실행하고, --python 3.13은 그 로컬 도구를 실행할 Python을 지정합니다. 필요한 Python이 없다면 uv가 내려받을 수 있습니다. 이 경로에서는 Git도 실행 가능해야 합니다. [Claude Code의 로컬 MCP 설정 안내](https://code.claude.com/docs/en/mcp#option-3-add-a-local-stdio-server)
>
> OpenCode는 앞의 호스트 연결 절에서 확인한 설치 계열에 맞춰 등록합니다. 다음 JSON은 V1용입니다. V1은 기존 설정의 mcp 객체 안에 서버 항목을 추가합니다. 이미 있는 다른 서버 설정을 이 예시 전체로 덮어쓰지 않도록 합니다. V2를 사용하는 학생은 이 예시 다음의 V2 설정을 사용합니다.
>
> ```json
> {
>   "mcp": {
>     "colab-mcp": {
>       "type": "local",
>       "command": ["uvx", "--python", "3.13", "git+https://github.com/googlecolab/colab-mcp"],
>       "enabled": true,
>       "timeout": 120000
>     }
>   }
> }
> ```
>
> type: "local"은 OpenCode가 내 컴퓨터에서 프로세스를 시작한다는 뜻입니다. command의 배열은 실행 프로그램과 그 인자를 순서대로 담습니다. enabled는 이 서버를 활성화합니다. timeout의 단위는 밀리초이므로 120000은 호스트 측에서 120초를 기다리는 설정입니다. 브라우저의 승인 단계에도 별도의 기다리는 시간이 있으므로, 이 숫자를 늘리면 모든 제한 시간이 함께 늘어나는 것은 아닙니다. [OpenCode MCP 설정 안내](https://opencode.ai/docs/mcp-servers/)
>
> OpenCode V2에서는 같은 실행 프로그램을 mcp.servers 아래에 등록합니다. V1의 enabled는 넣지 않습니다. 아래처럼 disabled를 생략하면 기본값 false로 연결을 활성화합니다. 앞의 호스트 연결 절에서 이미 V2 설정을 만들었다면 그 servers 객체 안에 colab-mcp 항목을 추가합니다.
>
> ```json
> {
>   "mcp": {
>     "servers": {
>       "colab-mcp": {
>         "type": "local",
>         "command": ["uvx", "--python", "3.13", "git+https://github.com/googlecolab/colab-mcp"],
>         "timeout": {"execution": 120000}
>       }
>     }
>   }
> }
> ```
>
> V2의 timeout은 세부 대기 시간을 담는 객체입니다. 위 execution은 도구 호출을 기다리는 시간을 120초로 지정합니다. 서버 시작과 도구 목록 읽기의 대기 시간은 각각 별도 항목이며 여기서는 기본값을 사용합니다. V1의 숫자형 timeout과 형태가 다른 점도 함께 확인하세요. V1과 V2 모두 같은 로컬 Colab MCP 프로그램을 실행하지만, 호스트가 서버 설정을 읽는 위치가 다릅니다. 두 JSON을 함께 추가하지 않고 현재 설치 계열의 설정을 사용합니다. V2의 구조는 [공식 V2 MCP 안내](https://opencode.ai/v2/docs/mcp-servers)에서 확인할 수 있습니다.
>
> 설정을 다시 읽게 한 다음, AI에게 Colab 연결을 요청합니다. 이 수동 경로도 다음의 승인·셀 실행까지 확인해야 완료됩니다.

### 브라우저의 MCP 연결 승인

서버 등록이 끝났다면 에이전트에 다음과 같이 요청합니다.

> Colab에 연결해 줘.

처음에는 open_colab_browser_connection이라는 연결 도구가 보일 수 있습니다. 이름을 외울 필요는 없습니다. 이 도구의 일은 Colab 탭을 열어 현재 로컬 서버와 노트북을 연결할 기회를 만드는 것입니다. 에이전트가 도구를 호출한 뒤 같은 컴퓨터의 Chrome에 열린 탭을 살펴봅니다.

아래 화면은 그 과정에서 실제로 확인한 승인 창입니다. 가운데 제목 Connect to a local Colab MCP server를 읽어 보세요. 여기서 승인하는 대상은 로컬 MCP 서버와 이 노트북의 연결입니다. 자신이 방금 요청한 연결인지 확인하고 Connect를 누릅니다. 브라우저가 별도의 로컬 네트워크 접근 허용을 묻는 경우에도 지금 요청한 로컬 연결인지 확인합니다.

![Colab MCP 연결 승인 창](colab-mcp-approval.jpg)<span class="img-caption">실제 연결 승인 화면. 가운데 Connect는 노트북과 로컬 MCP 서버를 연결한다.</span>

창의 안내에는 한 로컬 MCP 서버에 한 노트북 세션을 연결한다는 내용이 있습니다. 이 문맥에서 **세션(session)**은 현재 서버와 이어져 있는 노트북 연결을 가리킵니다. 탭을 여러 개 열었다고 해서 같은 서버가 그 모두를 동시에 조작할 준비가 된 것은 아닙니다. 이번에는 창의 Connect로 하나를 연결하고, 연결된 노트북을 확인하면서 진행합니다. 다른 선택지인 Cancel이나 Connect separate tabs로 경로를 나눌 필요는 없습니다.

첫 화면에도 Connect가 있었지요. 글자는 같지만 연결하는 대상이 다릅니다.

| 위치 | 연결하는 대상 | 연결 뒤 확인할 변화 |
| :--- | :--- | :--- |
| Colab 화면 오른쪽 위의 Connect | 노트북에서 코드를 실행할 런타임 | 코드 셀을 실행할 수 있는 상태 |
| 가운데 승인 창의 Connect | 현재 노트북과 로컬 Colab MCP 서버 | 에이전트가 연결된 노트북을 읽고 조작할 수 있는 상태 |

MCP 연결을 승인했어도 런타임이 준비되지 않았다면 계산은 아직 실행되지 않을 수 있습니다. 반대로 런타임에서 손으로 코드를 실행할 수 있어도 에이전트가 그 노트북을 조작할 연결은 없을 수 있습니다. 이제 브라우저에서 승인한 결과가 호스트까지 돌아왔는지 보겠습니다.

### 연결 뒤 달라지는 도구 목록

Colab 연결 전후에는 서버가 제공하는 도구 목록 자체가 달라질 수 있습니다. 연결하기 전에는 편집할 노트북이 아직 정해지지 않았습니다. 노트북과 연결되면 그 노트북의 내용을 읽거나 셀을 추가·실행하는 기능을 사용할 수 있게 됩니다. 이처럼 실행 중에 제공 기능의 목록이 바뀌는 것을 동적 도구 목록이라고 부릅니다.

이때 서버는 호스트에 "도구 목록이 바뀌었다"는 알림을 보냅니다. 호스트가 이를 받아 목록을 갱신해야 새 기능을 AI가 사용할 수 있습니다. 공식 Colab MCP 안내는 로컬에서 실행되는 클라이언트와 도구 목록 변경 알림 지원을 요구하며, 지원 예시에 Claude Code가 포함되어 있습니다. OpenCode에서는 현재 사용하는 버전에서 연결 후 편집·실행 기능을 사용할 수 있게 되는지 확인합니다. [공식 클라이언트 요구 사항](https://github.com/googlecolab/colab-mcp#supported-clients)

앞서 살핀 Tool Search와도 구분해 볼 수 있습니다. 여기서는 연결 상태에 따라 서버가 제공하는 기능이 바뀝니다. Tool Search는 제공 가능한 많은 기능 중 지금 필요한 도구 설명을 찾는 방식이었습니다. 검색 경로를 사용하는 호스트에서는 모든 도구 이름이 한꺼번에 대화에 나타나지 않을 수도 있으므로, AI에게 새로 연결된 노트북을 실제로 확인하게 해 보세요.

> 연결된 노트북 이름과 지금 들어 있는 셀을 확인해 줘.

답변의 노트북 이름이 Chrome 탭의 이름과 맞는지, 셀 내용도 맞는지 비교합니다. 이제 어느 노트북을 대상으로 다음 요청을 할지 확인했습니다. 연결 도구만 계속 사용할 수 있다면 셀 실행을 여러 번 요구하기보다 승인과 도구 목록 갱신부터 살펴봅니다.

### 계산 셀과 42 출력

첫 실행은 학생도 바로 결과를 판단할 수 있는 작은 계산으로 시작합니다.

> 연결된 노트북에 간단한 계산 셀 하나를 만들고 실행해 줘. 결과를 같이 확인하자.

AI가 다른 간단한 식을 선택해도 괜찮습니다. 아래는 기존 실습에서 실제로 추가하고 실행한 코드입니다. 같은 계산을 확인하고 싶으면 "37 더하기 5로 해 보자"라고 덧붙이면 됩니다.

```python
print(37 + 5)
```

Python이 37 + 5를 계산하고, print가 그 값을 셀 아래 출력으로 남깁니다. 예상되는 출력은 다음과 같습니다.

```text
42
```

![MCP로 추가한 계산 셀과 42 실행 결과](colab-mcp-result.jpg)<span class="img-caption">2026-09-06 실제 MCP 호출로 print(37 + 5) 셀을 추가·실행한 화면. 코드 아래의 42를 확인한다.</span>

이 기록에서는 add_code_cell로 코드를 담은 셀을 추가하고, run_code_cell로 실행했습니다. 첫 호출은 노트북에 내용을 쓰는 단계이고, 두 번째 호출은 Python 계산을 요청하는 단계입니다. 당시 Chrome의 실습용 scratchpad에서 출력을 확인했고, 새 연결에서도 승인 창의 Connect를 누른 뒤 같은 셀 추가·실행과 42 출력을 다시 확인했습니다.

학생의 화면에서는 세 가지를 따로 확인해 보세요. 우선 요청한 코드가 셀에 생겼는지, 다음으로 그 셀이 실행되었는지, 마지막으로 셀 아래 출력이 예상값과 맞는지를 봅니다. AI 답변에 "42입니다"만 쓰여 있고 노트북에 변화가 없다면, 지금 원하는 'Colab에서 계산하기'는 아직 확인하지 못한 것입니다.

기존 캡처는 당시 연결에서의 실행 증거입니다. 자신의 Claude Code·OpenCode에서도 실제 호출 결과와 노트북을 맞춰 보아야 현재 환경의 연결을 확인할 수 있습니다. 화면만 보고 AI가 어떤 과정을 거쳤는지 추측하기보다, 호스트의 도구 호출 기록과 셀의 변화를 함께 읽는 습관을 들여 봅시다.

### 입력을 바꾸며 계산 근거 읽기

42는 연결 확인에 충분하지만, 실제 보고서에서는 여러 관측값으로 숫자를 만듭니다. 먼저 주간 보고서의 업무 분류와 분리한 작은 학습 시간 예시로 계산 방식을 익혀 보겠습니다. 학습한 날에 기록한 시간이 20분, 30분, 40분이라고 해 봅시다. 합계는 90분이고 기록은 3개이므로, 기록 한 건당 평균은 30분이라고 예상할 수 있습니다.

> 학습 시간 몇 개로 평균을 계산해 보자. 입력과 계산 과정, 결과 설명을 노트북에 남겨 줘.

AI가 만든 셀을 읽어 봅니다. 위의 세 값을 사용하면 다음처럼 작성할 수 있습니다.

```python
minutes = [20, 30, 40]
average = sum(minutes) / len(minutes)
print(average)
```

첫 줄의 대괄호 안에는 여러 값을 차례로 담습니다. 이런 자료를 **리스트(list)**라고 합니다. minutes라는 이름을 붙여 두면 다음 줄에서 같은 값들을 다시 길게 적을 필요가 없습니다. 이번 리스트의 각 원소는 한 번 기록한 학습 시간이며 단위는 분입니다.

두 번째 줄은 평균의 뜻을 코드로 표현합니다. sum(minutes)는 기록한 시간을 모두 더해 90을 만듭니다. len(minutes)는 기록 수를 세어 3을 만듭니다. /로 나누면 30이고, 이 계산 결과를 average에 저장합니다. 마지막 줄이 그 결과를 출력합니다. Python에서는 이 나눗셈의 결과가 소수 형태로 표시되어 30.0이 나올 수 있습니다. 이는 30분이라는 예상과 같습니다.

이번에는 마지막 입력 40을 70으로 바꾸어 보세요. 실행하기 전에 바뀐 합계, 기록 수, 예상 평균을 직접 적어 봅시다. 어느 수는 바뀌고 어느 수는 그대로인지 생각하면 앞에서 읽은 평균 계산식을 다시 적용할 수 있습니다. 예상값을 적었다면 AI에게 값을 바꾸어 다시 실행하도록 요청하고, 입력과 출력 양쪽을 확인합니다.

> [!info]+ **예상값을 적은 뒤 계산 해설 확인하기**
> 합계가 90에서 120으로 바뀌고 기록 수는 여전히 3개이므로 평균은 40분이 됩니다. 따라서 새 출력은 40.0입니다. 이 변화는 세 관측값 중 하나가 30분 늘어났기 때문에 전체 평균은 10분 늘어난 것으로도 설명할 수 있습니다.
>
> 이전의 30.0이 그대로라면 값을 바꾼 셀과 계산 셀을 올바른 순서로 실행했는지도 살펴봅니다. 코드를 고친 상태, 실행한 상태, 새 출력을 보고 있는 상태가 서로 일치하는지 확인해 보세요.

여기서 계산 코드가 맞는 것과 숫자의 의미가 맞는 것은 별개입니다. 이 예시의 30분은 기록이 있는 세 번의 평균입니다. 일주일 중 기록이 없는 나머지 날도 0분으로 보아 나누면 다른 숫자가 나옵니다. 어떤 평균을 보고할지는 관측 대상과 팀의 기준에 따라 정해야 합니다. Colab은 선택한 계산을 실행해 주지만, "기록이 없는 날을 어떻게 다룬다"는 기준까지 숫자만 보고 정해 주지는 않습니다.

또 기록이 아예 없는 주라면 어떨까요? 빈 리스트의 길이는 0이므로 위 코드 그대로는 0으로 나누게 됩니다. 이때 먼저 결정할 것은 예외 처리를 얼마나 길게 쓸지가 아니라, 자료가 없음을 보고서에서 어떻게 표현할지입니다. "관측 없음"으로 적을지, 입력을 요청할지 기준을 정한 뒤 AI에게 그 동작을 구현하게 합니다. 데이터가 없는 상태를 평균 0분과 같은 뜻으로 처리해도 되는지도 생각해 보세요.

이후 실제 업무 지표를 계산할 때는 이 예시의 숫자를 업무 기록의 값으로 바꾸고, 단위·분모·누락 처리 기준을 함께 남깁니다. 앞에서 만든 팀 보고서 Skill에는 완료·진행·위험의 기준이 들어 있습니다. 그 안에 없는 평균 계산 규칙까지 이미 정해져 있다고 가정하지 않습니다. 반복해서 같은 지표를 보고하게 된다면, 그때 합의한 지표 정의와 좋은 결과 예시를 관련 Skill에 담아 재사용할 수 있습니다.

### 노트북 보관과 다시 실행

계산 결과를 확인했으니, 다음 사람이 다시 확인할 수 있도록 남길 차례입니다. 실행 결과 캡처의 상단에는 Cannot save changes와 Copy to Drive가 보입니다. 이번 연결에서 열린 scratchpad는 임시 노트북입니다. 계산이 성공했다는 사실과 노트북을 내 계정에 보관했다는 사실은 구분해야 합니다.

보관할 결과가 있으면 Copy to Drive로 복사하고, 내용을 알아볼 수 있는 제목을 붙입니다. 단순히 "결과는 30"이라고 적기보다 입력의 단위와 평균의 뜻도 텍스트 셀에 남겨 보세요. 나중에 노트북을 읽는 사람이 같은 코드를 실행해 같은 계산을 확인할 수 있어야 합니다.

저장한 노트북을 다시 열었을 때도 셀은 위에서부터 실행하는 편이 이해하기 쉽습니다. 예를 들어 첫 셀에서 minutes를 만들고 두 번째 셀에서 평균을 계산했다면, 새 런타임에서 두 번째 셀만 실행할 때 minutes를 찾지 못할 수 있습니다. 첫 셀은 변수를 준비하고 다음 셀은 그 변수를 사용하기 때문입니다. 셀 아래에 과거 출력이 보이더라도 지금 런타임에서 방금 계산한 결과와는 구분합니다.

노트북을 복사해 다른 탭으로 옮겼다면 에이전트가 조작 중인 노트북도 다시 확인하세요. 파일을 저장하거나 복사한 일이 기존 MCP 세션의 대상을 자동으로 바꿨다고 생각하지 않습니다. 연결 중에는 대상 탭과 로컬 MCP 프로세스를 유지하고, 실습을 마칠 때 필요한 결과를 보관한 뒤 연결을 종료합니다.

연결 도구는 연결용 임시 값을 담은 URL을 만들므로, 그 전체 주소를 과제·채팅·공개 캡처에 붙이지 않습니다. 결과를 남길 때는 사용한 호스트와 Chrome, 연결 뒤 실제로 호출한 기능 하나, 계산 셀과 출력을 기록하면 됩니다. 노트북에 숫자가 나온 근거를 보여 주는 데 연결용 임시 주소는 필요하지 않습니다.

### 계산 기록에서 공유 자료로

이제 AI에게 요청한 계산을 대화 밖의 노트북에서 실행하고, 입력을 바꾸어 결과를 다시 확인했습니다. 이 경험을 정리할 때는 "Colab이 연결됐다"에서 한 걸음 더 나아가, 로컬 MCP 서버가 어느 노트북을 조작했고, Python은 어디에서 실행되었으며, 어떤 입력으로 어떤 결과가 나왔는지 설명해 보세요.

이번에는 작은 데이터를 직접 넣었지만 실제 팀의 원자료는 Google 스프레드시트에 있을 수 있습니다. 다음에는 그 공유 표를 프로그램이 읽도록 접근 권한을 준비하겠습니다. Colab MCP 연결을 위해 다음 절의 Google Workspace용 credential JSON을 새로 만들 필요는 없습니다. 여기서는 Colab 로그인과 브라우저의 MCP 연결 승인을 사용했습니다. 다음 절에서는 내가 만든 Google API 앱에 계정 자료 접근을 허용하는 별도의 과정을 다룹니다. Colab에 로그인한 상태가 그 앱의 접근 동의까지 대신해 주는 것은 아니라는 점을 이어서 살펴봅시다.
