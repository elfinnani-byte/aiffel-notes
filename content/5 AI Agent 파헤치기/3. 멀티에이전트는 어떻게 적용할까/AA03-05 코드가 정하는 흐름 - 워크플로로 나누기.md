## 코드가 정하는 흐름: 워크플로로 나누기

기준선 실행(A)의 기록에서 탐색과 수정이 한 세션에 함께 남았다면, 이제 그 두 행동을 분리하되 문제와 검증 조건은 그대로 둡니다. 건물 보수 현장을 떠올려 봅니다. 구조조사팀이 먼저 균열을 살피고 보고서를 넘기면, 시공팀은 그 보고서를 바탕으로 보수에 들어갑니다. 워크플로 실행(B)은 이 순서와 인계 내용을 현장이 아니라 파이썬 코드가 미리 고정하는 구성입니다. `locator`는 읽기와 검색만 하며 파일 경로, 함수나 클래스 이름, 진단을 구조화된 보고로 남깁니다. 그 보고를 받은 `fixer`가 새 세션에서 수정합니다. 어느 단계가 먼저 실행되고 다음에 무엇을 받을지는 파이썬 코드가 정합니다.

이 분리는 역할 이름을 늘리는 일이 아닙니다. 탐색 결과가 `locate_report`로 다음 단계에 전달되는지, 탐색 담당이 파일을 고치지 않는지, 수정 담당이 그 근거를 이용하는지가 비교 대상입니다. `arms.py`의 워크플로 실행(B)은 locator에 12턴, fixer에 18턴을 줍니다.

`arms.py`에서 워크플로 실행(B)을 수행하는 핵심 호출 부분을 옮기면, 먼저 호출한 결과에서 만든 `locate_report`가 다음 호출의 프롬프트에 들어가는 흐름을 확인할 수 있습니다.

```python
loc, err_loc = await asyncio.wait_for(_run_once(
            f"Bug report:\n\n{problem}\n\nLocate the likely cause.",
            ClaudeAgentOptions(cwd=str(repo), model=MODEL, max_turns=12,
                               system_prompt=SYS_B_LOCATE, permission_mode="bypassPermissions",
                               allowed_tools=["Read", "Grep", "Glob"])), 900)
        if err_loc:
            extra["locator_error"] = err_loc
        locate_report = (getattr(loc, "result", "") or "").strip()
        extra["locate_report"] = locate_report[:2000]
        msg, err = await asyncio.wait_for(_run_once(
            f"Bug report:\n\n{problem}\n\nLocator report from a previous agent:\n{locate_report}\n\n"
            "Apply the minimal fix.",
            ClaudeAgentOptions(cwd=str(repo), model=MODEL, max_turns=18,
                               system_prompt=SYS_B_FIX, permission_mode="bypassPermissions")), 1200)
        if err:
            extra["error"] = err
```

첫 호출의 `loc`에서 보고서를 꺼내 변수에 저장하고, 두번째 호출은 그 변수의 내용을 프롬프트로 받습니다. 따라서 두 세션이 같은 대화를 공유하는 것이 아니라, 코드가 정한 보고서만 다음 단계로 건너갑니다.

```bash
.venv/bin/python arms.py B sympy__sympy-24909
```

워크플로 실행(B)의 결과 파일을 기준선 실행(A)의 파일과 나란히 엽니다. 실행 시간이 짧거나 길다는 사실만으로 좋고 나쁨을 판단하지 않습니다. locator의 진단이 수정 위치와 이어지는지, 수정 뒤 검증을 시도했는지, 실패했다면 어느 단계의 기록이 끊겼는지를 봅니다.

```bash
cat runs/B-sympy__sympy-24909/result.json
cat runs/B-sympy__sympy-24909/changes.diff
```

같은 인스턴스에서 기준선 실행(A)과 워크플로 실행(B)의 `resolved`, `invalid`, `num_turns`, `wall_s`, `cost_usd`를 읽습니다. 워크플로 실행(B)의 숫자는 두 호출의 기록이 합쳐진 값입니다. 따라서 기준선 실행(A)의 25턴과 워크플로 실행(B)의 12+18턴을 같은 예산이라고 읽으면 안 됩니다. 여기서 비교할 수 있는 것은 흐름을 나눴을 때 남는 근거와 실패의 모습이며, 예산이 다른 실행의 숫자 하나만으로 우열을 정할 수 없습니다.
