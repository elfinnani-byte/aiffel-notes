## PRD로 시작하는 바이브코딩

이번에는 완성된 앱의 코드를 따라 치는 대신, **PRD를 개발 도우미에게 전달하고 여러분의 선택에 맞는 앱을 만듭니다.** 이처럼 원하는 동작을 자연어로 요청하고 실행 결과를 보며 고치는 방식을 이번 실습에서 **바이브코딩**이라고 부릅니다.

[카드뉴스 워크플로 설계 키트 내려받기](https://github.com/SunCreation/agent-building-practice/releases/download/v5.0.0/card-news-workflow-kit.zip)를 누르고 압축을 푸세요. 이 키트는 **완성 앱이나 실행 프로그램이 아니라, 앱을 만들기 위한 설계 문서 묶음**입니다. 개발 도우미에서 압축을 푼 폴더를 열고 `PRD.md`를 먼저 읽게 합니다. 파일을 받기 전에 같은 v5.0.0의 [PRD 원문](https://github.com/SunCreation/agent-building-practice/blob/v5.0.0/card-news-workflow-kit/PRD.md)으로 요구사항을 확인해도 됩니다.

PRD가 요구하는 흐름은 주제 입력 → 넓은 조사 → 사용자 정보 선택 → 심층 조사와 편집 판단 → 스토리보드 승인 → 이미지와 글자 제작 → 검수·부분 수정·내려받기입니다. 특히 사용자가 자료나 방향을 고를 때는 작업을 기다리게 하고, 답변을 받은 뒤 앞선 제작을 이어가야 합니다. 단순히 문구를 한 번 생성하는 화면과 다른 점입니다.

폴더를 연 뒤 첫 요청은 짧게 시작하세요.

> PRD.md를 끝까지 읽고 이 카드뉴스 앱을 함께 만들어 줘. 구현 전에 아직 정하지 않은 것을 2~3개씩 물어봐 줘. 추천과 이유를 보여주고, 내가 답한 결정은 DECISIONS.md에 기록해 줘.

첫 질문에서는 구현 언어와 **실행 엔진**, 즉 앱 안에서 AI 작업을 수행할 도구를 정합니다. **SDK**는 코드에 연결하는 개발 도구 묶음이고, **CLI**는 터미널 명령으로 실행하는 도구입니다. 언어는 Python, TypeScript, Rust 등 여러분이 다루고 싶은 것을 고를 수 있습니다. 실행 엔진은 Claude Agent SDK, Claude CLI, OpenCode CLI 중 하나로 시작합니다. 검색 수단이 실제 계정에서 사용 가능한지, 카드 비율과 결과 보관 위치는 어떻게 할지도 정합니다. 잘 모르겠다면 개발 도우미에게 선택지별 차이를 짧게 설명하게 하세요.

> 내 환경에서 사용할 수 있는 언어와 엔진을 비교해 줘. 연결에 추가 작업이 필요하면 함께 설명해 줘.

이때의 질문은 **앱을 만드는 여러분에게 개발 도우미가 묻는 질문**입니다. 나중에 완성할 웹앱이 '어떤 독자에게 전달할까요?'라고 묻는 것은 **카드뉴스를 만드는 사용자에게 제작 에이전트가 묻는 질문**입니다. 두 질문이 나타나는 곳과 저장할 내용은 다릅니다.

결정을 기록했다면 화면과 API의 연결부터 확인합니다. API는 웹 화면이 서버에 요청하는 약속입니다. 예를 들어 주제를 보내면 프로젝트가 생기고, 조사를 시작하면 작업 ID가 돌아오며, 화면은 그 ID에 해당하는 진행 상태를 보여줍니다. PRD의 API 표는 초안이므로 개발 도우미가 선택한 언어에 맞춰 입력·출력과 오류를 API_SPEC.md에 정리하게 합니다.

> 주제 입력부터 후보 선택과 질문 답변까지 먼저 만들어 줘. `API_SPEC.md`에 연결 방식을 기록하고, 모의 데이터는 화면에 표시해 줘.

개발 도우미가 안내한 실행 방법으로 서버를 켜고 브라우저에서 `http://127.0.0.1:8765`를 여세요. 기본 포트가 이미 사용 중이라면 안내받은 다른 포트를 사용합니다. 화면에 'AI 최신소식'을 입력한 뒤 후보를 고르고, 질문에 답하는 흐름을 확인하세요. 새로고침했을 때 후보·선택·대기 질문이 유지되는지도 봅니다. 이 단계에서 보이는 예시 후보를 실제 최신 조사 결과로 판단하면 안 됩니다.

화면이 이어지면 실제 엔진 연결을 요청합니다.

> 선택한 엔진으로 실제 조사와 답변 후 이어가기를 연결해 줘. 검색 실패를 표시하고, 실제 연결을 확인한 결과를 기록해 줘.

실제 조사에서는 실행 시점을 기준으로 한 기간과 출처가 보이는지 확인합니다. 그다음 사용자 선택과 답변이 후속 원고에 반영되는지 봅니다. 이미지 생성은 Antigravity 작업자로 실제 한 장을 만들고 파일을 확인한 뒤, 전체 카드 제작으로 넓힙니다. 마지막으로 글자 배치, 부분 수정, 내려받기를 연결하고 `ACCEPTANCE.md`의 조건을 하나씩 확인합니다.

한 번에 완성을 요청하기보다 **작은 흐름을 실행하고 관찰한 문제를 다음 요청에 담는 것**이 이번 바이브코딩의 진행 방식입니다. '버튼을 눌렀는데 계속 대기 중이다', '새로고침하면 선택한 기사가 사라진다'처럼 실제로 본 상황을 알려주세요. 개발 도우미는 그 상황을 재현해 고치고, 여러분은 브라우저에서 원하는 동작이 되었는지 확인합니다.

### 실행 가능한 참고 구현

직접 만든 앱과 비교할 수 있도록 [Python 참고 구현](https://github.com/SunCreation/agent-building-practice/tree/main/card-news-agent)과 [실행 ZIP](https://github.com/SunCreation/agent-building-practice/releases/download/v5.1.5/card-news-agent.zip)을 제공합니다. 이 구현은 **Claude CLI로 실제 조사와 원고 작성을 하고, Antigravity CLI로 카드별 내용에 맞는 삽화를 생성하는 버전**입니다. SDK·OpenCode 연결까지 구현됐다는 뜻은 아닙니다. [실행 검증 기록](https://github.com/SunCreation/agent-building-practice/blob/main/card-news-agent/VALIDATION.md)에서 확인 범위를 먼저 살펴보세요.

> [!info]+ **참고 구현 실행 방법**
> 압축을 풀고 `pyproject.toml`과 `run.py`가 있는 폴더에서 실행합니다. Python 3.11 이상과 uv, 로그인된 `claude`·`agy` CLI가 필요합니다.
>
> ```bash
> uv sync --locked
> uv run playwright install chromium
> uv run run.py
> ```
>
> 브라우저에서 `http://127.0.0.1:8765`를 열고 'AI 최신소식'을 입력합니다. 후보 선택 → 독자 질문 → 기획 승인 → 이미지 제작 → 검수 → 최종 승인 순서로 진행합니다. 같은 포트가 사용 중이면 `uv run run.py --port 8766`으로 바꾸고 브라우저도 `http://127.0.0.1:8766`으로 여세요.

참고 구현은 카드별 제목·본문에 맞는 구체적인 삽화를 생성하며 최종 카드는 1080×1350으로 렌더링합니다. 글자와 그림을 분리해 모두 보이게 배치하고, 다른 비율이 필요하다면 자신의 PRD에 추가하고 구현하세요. 참고 구현을 그대로 제출하는 대신, 자신의 선택에 따라 무엇이 달라졌고 실제로 어떻게 동작했는지 설명합니다.

실행 중에는 **작업 진행 내역**을 펼쳐 실제 검색어, 원문 읽기와 결과 수신을 확인합니다. 토글을 닫아도 기록은 쌓입니다. 생성 중인 공개 텍스트의 최근 제목·후킹·본문 요약도 표시합니다. 경과 시간과 서버 응답 확인을 함께 보고, 초안 표시를 검증 완료로 해석하지 않습니다.

첫 카드의 후킹은 별도 호출로 먼저 설계합니다. 독자 관심 → 서로 다른 후보 두 개 → 근거와 과장 위험 비교 → 하나 선정 → 그 문구로 첫 카드 작성 순서입니다. 뒤 카드는 첫 카드가 만든 궁금증을 실제 자료로 해소해야 합니다. 기획 화면에서 텍스트 피드백으로 다시 작성하고, 수정안을 확인한 뒤 제작을 승인할 수 있습니다.

### 다음 단계로 넘어가기 전

| 확인 단계 | 직접 남길 증거 |
| :--- | :--- |
| 화면 연결 | 모의 자료 표시, 후보 선택, 새로고침 후 유지되는 질문 화면 |
| 실제 엔진 연결 | 검색·원문 읽기 기록, 선택한 후보, 답변이 반영된 원고 |
| 제작 연결 | 실제 생성 이미지 한 장, 스토리보드 승인 후 제작된 카드 5장 |
| 수정·내보내기 | 카드 하나의 수정 전후, 나머지 카드 유지 여부, 내려받아 연 ZIP |

**참고 구현과 목표 PRD의 차이도 확인하세요.** 제공된 v5.1.5 구현은 독자 질문을 항상 만들며, 제목·본문을 바꾸면 이미지 생성 요청도 달라져 해당 카드의 삽화가 다시 생성될 수 있습니다. '이미 알려 준 독자는 다시 묻지 않기'와 '텍스트만 고칠 때 그림 유지하기'는 자신의 앱에서 별도로 확인하고 보완할 항목입니다. 참고 구현을 실행했다는 사실만으로 PRD 전체를 통과 처리하지 않습니다. [해당 버전의 구현](https://github.com/SunCreation/agent-building-practice/blob/v5.1.5/card-news-agent/app.py)
