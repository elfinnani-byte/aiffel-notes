## 나만의 워크플로로 확장하기

카드뉴스 제작에서 만든 흐름을 자신이 자주 하는 작업에 적용해 보세요. 회의 기록을 실행 항목으로 정리하거나, 학습 자료에서 복습 문제를 만들거나, 여러 공고를 비교해 지원 준비 목록을 만드는 작업도 좋습니다. **반복해서 겪는 불편 하나와 확인 가능한 결과물 하나**를 고르면 시작하기 쉽습니다.

먼저 카드뉴스 PRD에서 무엇을 가져오고 무엇을 바꿀지 정합니다. 자료를 조사하고, 후보를 비교하고, 선택에 따라 결과물을 만드는 흐름은 재사용할 수 있습니다. 카드 수나 이미지 배치처럼 카드뉴스에만 필요한 조건은 자신의 과제에 맞게 바꾸세요.

| 설계할 부분 | 자신의 작업에 대해 정할 내용 |
| :--- | :--- |
| 입력 | 사용자가 무엇을 넣는가? 자료·목적·조건 중 결과를 만드는 데 필요한 것만 정합니다. |
| AI 판단 | AI가 어떤 정보를 추리고, 어떤 후보를 비교하며, 무엇을 제안하는가? 판단의 근거도 결과에서 확인할 수 있게 합니다. |
| 사람 결정 | 목표나 취향에 따라 결과가 달라지는 지점은 어디인가? 이미 입력한 조건은 다시 묻지 않고, 꼭 필요한 선택만 요청합니다. |
| 도구 행동 | 선택 이후 실제로 무엇을 검색·작성·저장하는가? 외부에 보내거나 게시하는 작업이 있다면 실행 전에 검토할 결과와 실행 조건을 정합니다. |
| 검수와 산출물 | 어떤 상태면 사용할 수 있는 결과인가? 원문과의 일치, 빠진 내용, 형식 등을 확인하고 수정할 수 있게 합니다. |

예를 들어 '학습 자료로 복습 문제 만들기'라면 자료와 학습 범위를 입력받고, AI가 핵심 개념과 문제 후보를 제안하게 할 수 있습니다. 학생은 복습할 개념이나 난도를 고르고, 앱은 문제와 해설을 작성합니다. 마지막에는 해설의 근거가 자료에 있는지 확인하고, 수정한 문제를 저장하도록 설계하면 됩니다. 이때 선택 화면은 모든 단계에 넣기보다 학생의 결정이 필요한 곳에만 둡니다.

설계가 정해지면 수정한 PRD 전체를 코딩 에이전트에 전달해 구현하세요. 첫 실행에서 원하는 결과가 나오지 않으면 코드 설명을 길게 요청하기보다 **실제 입력, 기대한 결과, 나온 결과의 차이**를 알려주고 다시 실행합니다.

> 카드뉴스 PRD를 학습 자료로 복습 문제를 만드는 워크플로로 바꿔 구현해 줘. 핵심 개념을 제안하고 내가 선택하면 문제와 근거가 있는 해설을 만들어 줘. 자료가 부족하면 부족한 부분을 표시해 줘.

완성 후에는 본인이 사용할 자료로 한 번 실행하고, 자료 부족이나 모호한 요청처럼 잘 풀리지 않는 경우도 확인하세요. 오류를 숨기거나 그럴듯한 내용으로 채우는 대신, 현재 상태를 보여주고 입력 보완이나 재실행으로 이어지는지 살펴봅니다.

제출물에는 다음 내용을 담으면 됩니다.

- **구현 결과:** 실행할 수 있는 앱 또는 프로젝트와 간단한 실행 방법.
- **PRD의 결정:** 해결할 불편, 기대 산출물, 사람이 결정하는 지점을 반영한 PRD.
- **실행 증거:** 실제 입력부터 선택과 결과까지 확인할 수 있는 화면·기록·산출물.
- **실패와 개선:** 기대와 달랐던 사례 하나와 바꾼 점, 다시 실행한 결과. 아직 해결하지 못했다면 남은 문제와 다음 수정 방향.

기능 수를 늘리기보다, 자신이 다음 작업에서도 다시 사용할 수 있는 흐름을 완성하는 데 집중하세요.

카드뉴스 한 편의 검수까지 끝낸 뒤 확장을 시작합니다. 새 앱을 처음부터 크게 만들기보다 입력·판단·결과 중 필요한 부분을 바꾸어 **정상 입력 한 번과 자료 부족 입력 한 번**을 실행하세요. 확장이 끝나지 않았다면 카드뉴스 실습의 완료 범위와 확장의 미완료 범위를 따로 제출합니다.

제출 폴더에는 `README.md`(실행 방법), `PRD.md`와 `DECISIONS.md`(선택 이유), `API_SPEC.md`(화면과 서버의 약속), 실행 화면·결과 파일, 검증 기록을 모읍니다. 다음 Day 40에서는 여기서 발견한 사용자 결정·도구 권한·실패 사례를 내 도메인의 자동화 설계에 반영합니다.
