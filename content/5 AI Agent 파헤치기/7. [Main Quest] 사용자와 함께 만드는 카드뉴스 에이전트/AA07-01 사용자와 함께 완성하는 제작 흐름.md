## 사용자와 함께 완성하는 제작 흐름

Day 38에서 정한 명세·상태·완료 조건을 이번에는 사람이 선택하며 사용하는 웹앱에 적용합니다. 앞서 만든 하네스 코드를 반드시 가져와야 하는 것은 아닙니다.

이번 실습에서는 'AI 최신소식'을 입력하면 자료를 조사하고, 사용자의 선택을 받아 카드뉴스를 완성하는 웹 앱을 만듭니다. AI가 후보를 찾아도 어떤 소식을 다룰지는 사용자가 고릅니다. 카드별 기획을 확인한 뒤 제작을 시작하고, 완성된 결과에서는 원하는 카드만 수정할 수 있게 합니다.

**워크플로**는 입력부터 결과물까지 이어지는 작업의 흐름입니다. **에이전틱 워크플로**는 AI가 조사 결과와 사용자 답변을 바탕으로 다음 행동을 판단하고, 검색이나 파일 생성 같은 도구를 사용하며 작업을 이어가는 흐름을 뜻합니다. 이번 앱에서는 사람의 선택과 검토도 그 흐름의 일부입니다.

앱의 요구사항을 정리한 **PRD(Product Requirements Document, 제품 요구사항 문서)** 전체를 코딩 에이전트에 전달해 구현합니다. 코드를 한 줄씩 따라 쓰기보다, 필요한 동작을 설명하고 브라우저에서 결과를 확인하면서 고치는 방식으로 진행하세요. 구현 언어와 실행 엔진 등 PRD에서 미정으로 둔 사항은 추천 이유를 듣고 선택합니다. PRD를 전달한 것만으로 앱이 완성되는 것은 아니며, 실제 조사와 이미지 생성까지 연결해 실행해야 합니다.

완성할 앱의 흐름은 다음 일곱 단계입니다.

1. **주제 입력과 넓은 조사:** 사용자가 'AI 최신소식'을 입력하면 실행 시점 기준 최근 7일의 자료를 조사합니다. 기준 시각과 기간을 보여주고, 자료가 부족하면 기간을 넓힐지 묻습니다.
2. **정보 선택:** 서로 다른 소식의 제목·요약·날짜·원문을 살펴보고 다룰 후보 1~3개를 고릅니다. 이 선택이 이후 제작의 범위가 됩니다.
3. **심층 조사와 편집 판단:** AI가 선택한 소식의 원문과 근거를 확인하고 독자·형식·관심을 끌 표지 문구를 제안합니다. 답에 따라 결과가 크게 달라질 때만 선택지를 보여주며, 이미 받은 답은 다시 묻지 않습니다.
4. **카드별 기획 검토:** 보통 5~8장의 역할·제목·핵심 문장·출처·그림 계획을 확인합니다. 이런 카드별 설계도를 스토리보드라고 합니다. 사용자는 변경을 요청하거나 기획을 승인합니다.
5. **이미지와 글자 제작:** 승인된 기획에 맞춰 이미지를 만들거나 사용 조건을 확인한 이미지를 고릅니다. 최종 글자는 이미지와 별도로 배치해 한국어 줄바꿈과 가독성을 조정합니다.
6. **검수와 부분 수정:** 사실과 출처가 맞는지, 글자가 잘리거나 읽기 어렵지 않은지 확인합니다. 수정할 카드를 지정하면 승인된 다른 카드를 유지하면서 해당 부분을 고칩니다.
7. **승인과 내려받기:** 최종 결과를 승인하고 카드별 PNG, 전체 ZIP, 출처와 이미지 사용 기록을 받습니다.

진행 중에는 현재 작업과 결과를 화면에서 확인할 수 있어야 합니다. 사용자 답변을 기다리는 상태는 정상적인 과정이며, 검색이나 이미지 생성이 실패했다면 원인과 재시도 방법을 보여주어야 합니다. 새로고침 뒤에도 선택과 진행 상태를 이어갈 수 있는지도 확인합니다.

이번 튜토리얼의 목표는 카드뉴스 한 편과 함께 **선택에 따라 작업을 이어가는 제작 흐름**을 만드는 것입니다. 먼저 제공된 PRD로 이 흐름을 구현한 다음, 입력 자료·AI의 판단·사람의 결정·최종 산출물을 바꾸어 자신이 자주 하는 작업으로 확장합니다.

### 시작 전에 확인할 준비

이 노트북은 읽고 따라가는 실습 안내입니다. 실제 구현과 실행은 개발 도우미·터미널·브라우저에서 진행합니다. 개발 도우미는 앱의 코드를 만들고 고치는 도구이며, 완성한 앱이 조사에 사용하는 실행 엔진과는 역할이 다릅니다.

- 작업 폴더를 열 수 있는 개발 도우미와 로컬 터미널·브라우저를 준비합니다.
- 조사 엔진 하나와 Antigravity 이미지 작업자를 사용할 수 있는 계정·인증·도구 권한을 확인합니다. 개발 도우미에 로그인했다고 앱의 실행 엔진까지 인증되는 것은 아닙니다.
- 짧은 조사 요청으로 실제 검색과 원문 읽기를 확인하고, 이미지 한 장을 생성해 열어 봅니다. 설치 여부만으로 연결 성공을 판단하지 않습니다. 참고 구현의 설치 조건은 3절에 있습니다.
- 사용할 도구의 이용 한도와 과금 방식을 확인하고, 처음에는 소식 1개·카드 5장으로 전체 흐름을 연결합니다. 한도나 인증 문제로 막히면 모의 자료로 화면 작업을 계속하되, 실제 조사·생성의 미완료 여부를 기록합니다.

완료 여부는 **① 실제 자료로 카드뉴스 한 편 내려받기 ② 질문 대기와 실패 후 재개 확인 ③ 내 작업에 맞게 바꾼 흐름 실행**으로 판단합니다. 각 단계의 화면과 결과 파일을 남겨 마지막 제출에 사용하세요.
