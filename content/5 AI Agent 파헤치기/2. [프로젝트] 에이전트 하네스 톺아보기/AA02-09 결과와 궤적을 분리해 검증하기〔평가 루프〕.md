## 결과와 궤적을 분리해 검증하기〔평가 루프〕

최종 패치가 맞았다는 사실만으로 검색 낭비, 우연한 성공, 과도한 권한 사용을 구분할 수 없습니다. 평가 루프는 최종 패치가 과업을 해결했는지와 그 결과에 이른 검색·편집·실행 궤적이 적절했는지를 분리해 확인합니다.

### 구성요소와 결과를 따로 측정합니다

SWE-agent의 ACI ablation은 검색, 편집, 관측 형식처럼 인터페이스 구성요소를 바꾸고 결과를 비교할 수 있음을 보였습니다. (Yang 외, 학회 논문(NeurIPS 2024), [arXiv:2405.15793](https://arxiv.org/abs/2405.15793), SWE-bench Lite ablation 결과이며 모델·저장소·실행 조건 밖으로 일반화하지 않습니다) 같은 모델이라도 무엇을 읽고 어떤 형식으로 행동했는지를 고정해야 구성요소의 기여를 물을 수 있습니다. 이 결과는 SWE-bench Lite와 논문에 적힌 실행 조건의 결과입니다. 다른 모델이나 저장소에서도 같은 구성요소가 같은 기여를 한다고 해석해서는 안 됩니다.

[SWE-bench](https://www.swebench.com/)는 실제 GitHub 이슈와 저장소로 코딩 에이전트를 측정하는 벤치마크입니다. 실제 GitHub 이슈와 저장소를 묶고 FAIL_TO_PASS와 PASS_TO_PASS 테스트로 최종 패치를 채점합니다. (Jimenez 외, 학회 논문(ICLR 2024 Oral), [arXiv:2310.06770](https://arxiv.org/abs/2310.06770), 12개 Python 저장소의 2,294개 문제를 실행 기반 테스트로 채점하며 contamination 검증과 다른 언어 일반화에는 한계가 있습니다) 이는 문제를 푸는 루프와 채점하는 루프를 구분할 근거를 제공합니다. 그러나 테스트 통과는 유지보수 품질 전체와 같지 않으며, 정적 문제에는 contamination 위험도 남습니다.

SWE-bench Verified는 12개 저장소에서 인간 검증한 500개 문제를 제공하는 공식 데이터셋 카드입니다. (Princeton NLP, 공식 데이터셋 카드, SWE-bench_Verified, 사후 PR 테스트 행동을 정답 대리물로 두며 검수자 수와 합의 절차는 확인하지 못했습니다) 이 등급은 해결 가능성 검토의 근거이며, 특정 하네스가 더 낫다는 근거는 아닙니다.

### SWE-agent를 평가 기능으로 다시 봅니다

| 기능 재조명 | 확인할 기록 | 1차 근거 |
| :--- | :--- | :--- |
| SWE-agent 평가 루프 | 문제 설명·저장소, trajectory, patch, 테스트 결과를 같은 실행 단위에 남겨 결과와 경로를 함께 검토합니다. | SWE-agent 공개 저장소와 실행 기록, ACI 논문을 확인합니다. |

trajectory는 모델의 의도나 패치의 정답성을 스스로 증명하지 않습니다. 다만 어느 검색이 먼저 있었는지, 테스트 실패 뒤 무엇을 편집했는지, 어떤 명령이 실행됐는지를 1차 근거로 남깁니다. 다음 행동을 바꾼 관측인지, 같은 탐색을 반복했는지, 승인한 권한이 과도했는지를 이 기록에서 다시 확인합니다.

### 통과 결과만으로는 충분하지 않습니다

정적 벤치마크의 테스트 통과는 장기 유지보수, 설명 가능성, 코드 검토, 의존성 변화 대응을 모두 재지 못합니다. 공개된 문제와 해답이 학습 또는 도구 설정에 섞였을 가능성도 비교를 흐릴 수 있습니다. 그러므로 결과 점수와 함께 실행 환경, 모델, 권한 정책, 비용, 승인 횟수, trajectory를 남기고 실제 검토를 별도로 합니다. 어떤 trajectory 신호가 좋은 하네스를 가리는지가 아직 남은 질문입니다.

이제 일곱 도구를 기능 수가 아니라 내 병목을 해결하는 증거로 다시 배열할 수 있습니다.
