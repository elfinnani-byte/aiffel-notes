# [AI Agent 파헤치기] - 2. 화면에서 하네스의 경계 먼저 관찰하기

## 화면에서 하네스의 경계 먼저 관찰하기

제품 설명만 읽어 두지 않고, 지금 쓰는 도구가 요청을 받는 순간부터 무엇을 보여 주는지 직접 관찰합니다. Claude Code는 Anthropic이 만든 터미널용 코딩 에이전트입니다. 터미널 안에서 저장소를 읽고 파일을 고치고 명령을 실행합니다. opencode는 오픈소스 터미널 코딩 에이전트로, 여러 모델 제공자를 설정에서 골라 쓸 수 있습니다. 이번 관찰은 Claude Code 또는 opencode 가운데 이미 사용하는 하나에서만 합니다. 설치, 로그인 변경, 확장 연결, 파일 수정은 이번 범위에 넣지 않습니다.

읽기 전용 과업 하나면 충분합니다. 현재 작업 폴더의 파일 목록을 읽는 요청이나 공개 문서 한 건을 요약하는 요청이 알맞습니다. 결과의 좋고 나쁨을 평가하는 시간이 아니라, 요청의 입구와 실행 경계를 화면에서 찾는 시간입니다.

### 관찰 전에 범위를 작게 정합니다

작업 폴더는 기존 과업 자료와 분리한 간단한 fixture가 있는 곳으로 정합니다. fixture는 개발자들이 오래전부터 써 온 테스트 용어입니다. 뜻은 "무엇을 시험할 때마다 결과가 똑같이 나오도록 미리 준비해 둔 고정된 자료"입니다. 요리 교실에서 매번 같은 재료를 미리 다져 두는 것과 비슷합니다. 재료가 그때그때 다르면 어떤 차이가 실력이고 어떤 차이가 재료 탓인지 구분할 수 없습니다. 관찰도 마찬가지입니다. 도구의 행동을 보려면 자료가 늘 같아야, 달라진 것이 자료가 아니라 도구라는 말을 할 수 있습니다. 이 관찰에서는 공개 문서 한 건 또는 내용이 알려진 작은 텍스트 파일 한 건이면 충분합니다. 비밀값, 개인 자료, 실제 저장소, 수정이 필요한 파일은 이 관찰의 대상이 아닙니다.

관찰 메모에는 도구 이름과 버전, 작업 폴더의 위치, fixture의 종류를 먼저 남깁니다. 이 정보는 나중에 같은 화면을 다시 볼 때 관찰 조건을 구분하게 합니다.

### 화면에서 다섯 신호를 찾습니다

첫째 관찰은 **입력**과 **도구 호출**입니다. 요청을 입력한 위치와, 도구가 파일 읽기나 검색 같은 행동을 알린 위치를 봅니다. 이 두 신호는 행동 포맷이 화면에서 어떤 순서와 단위로 드러나는지 보여 줍니다. 요청 문장만 보이고 행동이 보이지 않으면, 대표 행동은 아직 확인하지 못한 것으로 남깁니다.

둘째 관찰은 **관측 축약**과 **기록 위치**입니다. 긴 출력 일부를 접거나 요약하는 표시가 있는지, 현재 대화와 세션 목록, 작업 기록, 로그 가운데 실행 결과가 어디에 남는지 봅니다. 관측 축약은 컨텍스트 관리과 연결되고, 기록 위치는 경험과 스킬 축적 및 반성에 필요한 흔적과 연결됩니다. 화면에서 실제로 보이는 위치만 남깁니다.

셋째 관찰은 **승인 신호**입니다. 도구가 읽기 밖의 행동을 하기 전에 어떤 승인 신호를 보여 주는지 봅니다. 승인 창, 허용 선택지, 실행 예정 명령, 권한 설정 안내가 보이면 그 문구와 위치를 남깁니다. 아무 신호가 보이지 않으면 이번 읽기 요청에서는 승인 신호를 확인하지 못했다고 남깁니다. 이 신호는 권한과 보안의 경계를 보여 줍니다.

이번 실행에서 확장 기능을 열거나 추가하지는 않습니다. 다만 화면에 도구 연결, 플러그인, MCP, 설정 파일 같은 단서가 보이면 관측한 사실과 아직 확인하지 못한 범위를 나누어 남깁니다. 단순성이 필요한지와 평가 루프가 어디에서 닫히는지는 이 짧은 관찰만으로 결론 내리지 않습니다.

### 시범: 한 바퀴를 처음부터 끝까지

이 시범은 Claude Code CLI 2.1.220에서 새 작업 폴더 `~/obs-lab`을 열고 진행한 실제 실행입니다. 폴더에는 공개 문서 한 건을 받아 둔 `notes.txt`만 있습니다. 버전 번호는 화면에 표시된 값을 그대로 관찰 조건으로 남깁니다.

**첫 걸음. 대화창에 요청을 입력합니다.**

```text
이 폴더의 파일 목록을 보여 줘
```

요청 문장은 대화 흐름 안에 남고, 응답 본문과 구분되어 표시됩니다. 결과 목록의 내용보다 요청이 들어간 화면의 위치를 먼저 봅니다.

**둘째 걸음. 도구 호출이 화면에 나타납니다.**

요청을 넣으면 응답이 만들어지는 동안 도구 호출 영역이 표시됩니다. 이 실행에서 Claude Code는 파일 목록을 Bash로 조회했습니다. 화면에는 다음과 같은 호출이 보입니다.

```text
● Bash(ls -la /Users/admin/obs-lab)
    List files in obs-lab
```

Claude Code의 공식 문서는 파일 탐색에 Glob, 파일 읽기에 Read를 안내하지만, 이 요청에서 모델은 Bash의 ls -la를 골랐습니다. 화면에 나타난 도구 이름과 명령이 이번 실행의 사실입니다. 도구를 고른 주체가 모델의 판단이었다는 점이 첫 번째 관찰입니다.

**셋째 걸음. 도구의 결과가 돌아옵니다.**

```text
total 8
drwxr-xr-x   4 admin  staff   128 Sep  2 01:36 .
drwxr-xr-x@ 171 admin  staff  5472 Sep  2 01:38 ..
drwxr-xr-x   4 admin  staff    128 Sep  2 01:37 .omc
-rw-r--r--   1 admin  staff    32 Sep  2 01:36 notes.txt
```

원본 명령의 출력이 그대로 돌아옵니다. 이 원본이 세션 기록에 남는다는 사실이 컨텍스트 관리의 재료가 됩니다. 지금은 네 줄이라 그대로 두지만, 출력이 길어지면 이 절 뒤에 나오는 관측 축약이 개입할 자리입니다.

**넷째 걸음. 최종 응답이 완성됩니다.**

```text
`/Users/admin/obs-lab` 내용:

- `notes.txt` — 32바이트 파일
- `.omc/` — OMC 상태 디렉터리 (숨김)
```

모델은 도구 결과를 읽고 사람을 위한 요약을 만들었습니다. 요청, 도구 호출, 도구 결과, 요약이 한 세션에 순서대로 남습니다. 이 네 층이 하네스가 화면에 보여 주는 실행의 흔적입니다.

**이 실행에서 승인 창은 나타나지 않았습니다.**

이 요청은 읽기만 하므로 승인 없이 진행됐습니다. 승인 창이 없었다는 사실은 남기되, 설정 파일에 어떤 허용 규칙이 있는지는 열어 보지 않았으므로 미확인으로 둡니다. 관측 축약 표시와 세션 기록 위치도 이 화면에서 보인 범위만 기준으로 합니다.

**완성된 관찰 메모는 다음과 같습니다.**

> 조건: 도구는 Claude Code CLI 2.1.220, 작업 폴더는 `~/obs-lab`, fixture는 공개 문서를 받아 둔 `notes.txt` 한 건.
> 입력 — 요청은 대화창에 들어가고 응답과 구분되어 남았습니다.
> 도구 호출 — Bash(`ls -la`)가 화면에 표시되었습니다. 공식 문서가 안내하는 Glob/Read가 아니라 모델이 Bash를 골랐습니다.
> 관측 — 원본 `ls` 출력 네 줄이 그대로 돌아왔습니다. 축약 표시는 이 실행에서 확인하지 못했습니다.
> 승인 — 이 읽기 요청에는 승인 창이 없었습니다. 설정의 허용 규칙은 미확인입니다.
> 기록 — 세션에 요청부터 요약까지 순서대로 남았습니다.

이 해석에서 아직 쓰지 않는 문장이 있습니다. "이 도구는 읽기가 안전하다"는 해석이 그것입니다. 안전 판정에는 권한 규칙 확인이 필요하지만 이번 관찰은 그 규칙을 열어 보지 않았습니다. 화면에 보인 것과 보이지 않은 것을 나누는 것이 이번 관찰의 결과이고, 해석은 뒤의 기능 절들이 근거를 모아 줍니다.

이 시범을 마치면 같은 형식으로 자신의 도구와 파일에서 관찰을 시작할 수 있습니다. 이 시범 기록의 뼈대는 뒤의 비교표와 실험에서 쓰는 관찰 로그 형식에도 그대로 이어집니다.

### 관찰 기록은 사실과 해석을 나눕니다

기록에는 화면이나 로그에서 확인한 내용만 넣습니다. 도구와 버전, 작업 폴더와 fixture는 관찰 조건으로 남깁니다. 요청이 들어간 곳과 화면에 나타난 도구 호출은 행동 포맷의 신호로 남깁니다. 세션 또는 로그가 남은 곳과 관측 축약 표시는 컨텍스트 관리, 경험, 반성과 연결합니다. 실행 전 승인 신호는 권한과 보안에 연결합니다. 화면에 보인 연결 또는 설정 단서는 확인한 사실로, 이번 실행에서 보이지 않은 기능은 한계로 구분합니다.

같은 내용이라도 어떻게 적느냐에 따라 사실과 해석이 갈립니다. 파일 목록을 요청했더니 목록이 화면에 나오고 승인 창은 뜨지 않았다면, "파일 목록 요청에 승인 없이 읽기가 실행되었습니다. 관측한 사실: 화면의 파일 목록. 미확인: 설정 파일의 권한 규칙"처럼 한 줄로 남깁니다. 여기서 "이 도구는 읽기가 안전하다"는 해석까지 내리지는 않습니다. 이 관찰만으로 안전을 단정하는 의미로 해석해서는 안 됩니다. 화면에 보인 것과 보이지 않은 것을 나누는 것이 이번 관찰의 결과이고, 해석은 뒤의 기능 절들이 근거를 모아 줍니다.

이 기록은 도구 전체를 판정하는 증명이 아닙니다. 짧은 실행 하나에서 보인 경계와 보이지 않은 경계를 구분하는 출발점입니다. 요청이 어디로 들어갔는지, 행동과 기록이 어떻게 보였는지, 읽기 밖의 행동 앞에서 무엇이 보였는지라는 질문을 들고 다음 기능별 소개로 갑니다.
