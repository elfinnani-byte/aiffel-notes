## 막힌 작업을 하네스 기능 질문으로 바꾸기

하네스는 에이전트의 작업능력을 끌어올려주는 좋은 시스템입니다. 하지만 지금도 우리가 작업을 할 때는 잘 되는 작업과 그렇지 않은 작업들이 있습니다. 여기서 잘 되는 것과 안되는 것의 차이는 어디서 나타나는 것일까요?

![[Pasted image 20260902103903.png]]

하네스는 모델이 일을 하는 동안 요청, 도구, 기록, 승인, 관측을 연결하는 실행 환경입니다. 모델의 답변 능력만으로는 이 환경의 차이를 설명할 수 없습니다. 같은 모델도 행동을 적는 형식, 남겨 둘 문맥, 허용된 권한이 달라지면 다른 결과를 냅니다.

### 맡기는 일이 막히는 곳은 어디일까요?

하네스 기능 지도는 도구의 등급표가 아닙니다. 맡길 일이 멈춘 이유를 찾는 지도입니다. 행동 포맷은 모델이 읽고, 고치고, 실행하는 행동을 실패하기 어렵게 적게 합니다. 컨텍스트 관리은 긴 작업에서 무엇을 남기고 무엇을 줄일지 정합니다. 경험과 스킬 축적은 한 번 해결한 일을 다음 작업에 다시 씁니다. 반성은 실행 결과를 살펴 다음 행동을 고칩니다. 단순성은 필요한 구성만 남겨 운영 부담을 줄입니다. 권한과 보안은 읽기, 수정, 실행의 경계와 승인 방식을 정합니다. 평가 루프는 결과가 맞았는지 어떤 근거로 확인할지 정합니다.

이 일은 어디서 막히는가라는 질문으로 시작합니다. 행동이 애매한가, 문맥이 넘치는가, 경험이 재사용되지 않는가, 승인이 많은가, 결과를 어떻게 증명할까를 차례로 묻습니다. 이어서 그 병목을 줄일 기능이 무엇인가를 묻습니다. 마지막으로 그 기능이 실제로 작동했다는 기록을 어디에서 확인할 수 있는가를 묻습니다. 이 세 질문은 제품 설명보다 먼저 맡길 일의 경계를 드러냅니다.

### 기능 지도와 비교 카드는 다른 일을 합니다

일곱 기능은 맡길 일의 병목을 진단하는 섹션 제목입니다. 반면 비교 카드의 여섯 칸은 도구 화면과 문서를 같은 방식으로 관찰하기 위한 기록 항목입니다. 기능 지도에서 컨텍스트 관리이 중요하다고 판단한 뒤에도, 카드에서는 상태와 대표 행동이 실제로 어떻게 보이는지 확인합니다.

| 카드 칸  | 관찰할 내용                                      |     |
| :---- | :------------------------------------------ | --- |
| 입구    | 요청이 들어가는 화면, 명령, 연결 지점을 확인합니다.              |     |
| 상태    | 세션, 대화, 작업 기록이 남는 위치를 확인합니다.                |     |
| 대표 행동 | 읽기, 검색, 수정, 실행 가운데 화면에서 확인한 행동을 적습니다.       |     |
| 권한 경계 | 읽기 밖의 행동 전에 승인이나 제한이 보이는지 확인합니다.            |     |
| 1차 근거 | 실행 기록, 설정, 공식 문서처럼 나중에 다시 열 수 있는 근거를 연결합니다. |     |
| 한계    | 이번 관찰만으로 확인하지 못한 범위를 구분합니다.                 |     |

다음에서는 이미 익숙한 도구 화면에서 이 카드의 경계부터 관찰합니다. 입력이 들어가는 곳, 도구가 행동을 알리는 곳, 기록과 승인 신호가 남는 곳을 보면 기능 지도가 추측이 아니라 관찰이 됩니다.
