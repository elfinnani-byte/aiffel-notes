## 모니터링 — 사용량과 상태 보기

맡긴 일이 많아질수록 얼마나 쓰고 있는지를 보는 일이 중요해집니다. OpenClaw는 이 질문에 답하는 화면을 채팅 안과 명령줄 양쪽에 두었습니다. 이 절에서는 앞 절에서 만든 WebChat 세션을 다시 열고 직접 확인합니다. 새로 설치하는 것은 없습니다.

측정의 단위부터 정리합니다. 토큰은 모델이 글을 주고받는 양을 세는 단위입니다. 입력과 출력이 각각 세고, 비용은 이 양에서 계산됩니다. 세션 단위 숫자와 모아 둔 전체 요약은 다른 질문에 답합니다. 지금 대화가 얼마나 커졌는지와 지금까지 얼마를 썼는지를 나누어 보는 습관이 이 절의 목표입니다.

### 채팅에서 바로 봅니다

WebChat에서 지금 세션의 상태를 확인합니다. 슬래시로 시작하는 명령을 대화창에 그대로 입력합니다.

```text
/status
```

상태 카드가 답으로 옵니다. 세션 토큰과 추정 비용이 적히고, 인증 방식에 따라 현재 모델 제공사의 사용량 창 요약이 함께 보입니다. ([docs/concepts/usage-tracking](https://docs.openclaw.ai/concepts/usage-tracking))

사용량 표시는 토글로 바꿉니다. 인수 없이 입력할 때마다 끄기, 토큰, 자세히의 순서로 순환합니다.

```text
/usage
/usage tokens
/usage full
/usage cost
```

각 자리가 보여 주는 것은 문서가 정확히 구분합니다. 토큰 자리는 입력과 출력을 한 줄로 보입니다. 자세히 자리는 모델, 추론 수준, 빠른 처리와 느린 처리, 컨텍스트 창, 비용을 보여 줄 수 있는 만큼 보입니다. 비용 요약은 세션 기록을 모아 계산한 로컬 비용 정리입니다. ([docs/concepts/usage-tracking](https://docs.openclaw.ai/concepts/usage-tracking))

![[Pasted image 20260904161019.png]]

컨텍스트 창에서 현재 세션이 쓴 분량과 최근 실행 사용량을 확인합니다.

입력 토큰과 출력 토큰 중 어느 쪽이 큰지, 대화가 길어지면서 어느 쪽이 빨리 불어나는지가 다음 대화를 얼마나 이어 붙일지 판단하는 재료가 됩니다.

### 명령줄에서 편 씁니다

터미널에서 같은 정보를 표로 봅니다. 게이트웨이가 살아 있는지와 사용량을 함께 확인합니다.

```bash
openclaw status --usage
```

제공자별 사용량과 할당량을 정리해서 보여 줍니다. 이어서 인증 프로필의 상태를 봅니다.

```bash
openclaw models status
```

인증 방식별 프로필과 제공자별 사용량 창 요약이 표시됩니다. 온보딩에서 고른 인증 경로가 여기서 다시 등장하는지 확인합니다. 연결이 죽었거나 인증이 만료된 프로필이 있다면 이 표에서 먼저 보입니다.

### 구독 창과 API 비용은 같은 숫자가 아닙니다

사용량 화면을 읽을 때 인증 경로에 따라 숫자의 뜻이 달라지는 것을 정리해 둡니다. API 키로 쓰는 모델은 호출마다 계산한 추정 비용을 보여 줍니다. 구독 로그인으로 쓰는 모델은 남은 한도 비율을 제공사의 사용량 창 형태로 보여 줍니다. 같은 화면의 숫자라도 하나는 돈이고 하나는 남은 양입니다. ([docs/concepts/usage-tracking](https://docs.openclaw.ai/concepts/usage-tracking))

온보딩에서 두 경로를 고르며 열쇠를 누가 갖고 있느냐가 인증 경로의 차이라는 점을 보았습니다. 그 차이는 사용량 화면에도 그대로 나타납니다. API 키 경로는 OpenClaw가 키를 갖고 있으므로 비용을 OpenClaw가 계산해 보여 줍니다. 구독 경로는 한도 창을 제공사가 계산해 알려 줍니다. 어느 경로로 접속했는지 모른 채 숫자만 보면 남은 비율을 남은 돈으로 잘못 읽을 수 있습니다. 접속 경로와 숫자의 뜻은 함께 읽어야 합니다.

### 운영용 관측 도구가 따로 있습니다

지금까지 본 화면은 내 세션을 내가 보는 도구입니다. 여러 사람이 함께 쓰는 설비에는 관측이 더 필요해지고, OpenClaw는 그런 운영용 도구를 따로 갖추고 있습니다. OpenTelemetry로 지표를 밖으로 내보내거나 Prometheus로 모아 보거나, audit(감사 기록)로 누가 무엇을 승인했는지 이력을 남기는 도구들입니다. 오늘은 이런 도구가 존재하고 운영용이라는 것까지만 알아 둡니다.

문제를 보고할 때 쓰는 진단 번들도 있습니다. 로컬에서 압축 파일 하나로 상태와 로그를 모아 주는데, 개인정보를 가려 주더라도 로그 요약이 들어 있으므로 함부로 나누지 않고 비밀 자료처럼 다뤄야 합니다. 제품이 스스로 보내는 통계는 하루 한 번 버전 확인이 전부이고, 기능 사용 통계는 동의하기 전까지 꺼져 있습니다. 내 사용량 관찰, 문제 분석 자료, 제품 개선 통계는 목적과 개인정보 경계가 다른 세 가지라는 구분이 오늘의 정리입니다. ([docs/gateway/diagnostics](https://docs.openclaw.ai/gateway/diagnostics), [docs/gateway/telemetry](https://docs.openclaw.ai/gateway/telemetry))

### 보는 법을 알았으니 손을 늘려 봅니다

이번 절까지 상태와 비용을 확인하는 감각이 생겼습니다. 다음 절에서는 사람이 기억하지 않아도 되도록 반복되는 일을 예약해 봅니다. 그다음 브라우저를 움직이고 기기의 눈을 쓰고 메일함을 지키는 확장 기능들을 지도처럼 둘러봅니다.
