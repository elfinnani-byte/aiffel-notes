# [AI Agent 파헤치기] - 4. 텔레그램으로 부리기

## 텔레그램으로 부리기

채널(channel)은 메시지 서비스와 Gateway를 잇는 연결입니다. Telegram을 채널로 붙이면 폰에서 보낸 메시지가 Gateway에 도착합니다. 봇 토큰은 봇을 대신해 Telegram에 접속하는 비밀값입니다. 채팅창, 화면 공유, 메모에는 토큰을 적지 않습니다. 이 절에서는 수업용 봇을 만들고, 첫 메시지를 보낸 계정을 승인합니다. ([docs/channels/telegram](https://docs.openclaw.ai/channels/telegram))

Telegram에서는 BotFather라는 서비스가 제공되고 있습니다. 바로 사용자가 AI 봇을 손쉽게 만들 수 있게 제공해주는 기능입니다.

Telegram에서 `@BotFather`를 찾아 접솝합니다. 대화창에 `/newbot`을 보내고, 화면 안내에 따라 표시 이름과 bot으로 끝나는 봇 이름을 입력합니다. 발급 화면의 토큰을 복사해 안전한 비밀 보관 위치에 둡니다. 토큰이 대화에 남았다면 BotFather에서 새 토큰을 발급하고 이전 토큰은 쓰지 않습니다. ([docs/channels/telegram](https://docs.openclaw.ai/channels/telegram))

### Gateway에 토큰을 연결합니다

터미널에서 아래 명령의 큰따옴표 안을 방금 보관한 토큰으로 바꿉니다. Telegram은 `channels login` 명령으로 연결하지 않고 설정에 토큰을 넣은 뒤 Gateway를 시작합니다. ([docs/channels/telegram](https://docs.openclaw.ai/channels/telegram))

```bash
openclaw config set channels.telegram.botToken "여기에_봇_토큰"
openclaw gateway
```

Gateway가 이미 실행 중이면 수업 환경의 재시작 방법으로 다시 시작합니다. 폰에서 새 봇 대화창을 열어 짧은 인사말 하나를 보냅니다.

### 누가 말 걸었는지 구분합니다

채널은 열려 있어도 바로 누구나 대화하는 곳은 아닙니다. Telegram의 기본 DM 정책인 페어링(**pairing**)은 첫 메시지를 보낸 계정을 승인 대기 목록에 올리고, 승인된 계정만 봇과 대화하게 하는 규칙입니다. 입구는 열려 있지만 문은 잠긴 상태이며, 페어링 승인이 열쇠입니다.

첫 메시지를 보낸 뒤 터미널에서 대기 코드를 읽고 승인합니다.

```bash
openclaw pairing list telegram
openclaw pairing approve telegram <코드>
```

승인 전 대기 중인 코드만 1시간 뒤 만료됩니다. 한 번 승인하면 이후에는 코드 없이 대화가 이어집니다. 승인이 안 된 채 시간이 지난 경우에만 새 코드를 받아 다시 승인합니다. 승인하지 않은 계정의 메시지에는 봇이 답하지 않습니다. Telegram 계정을 사람 이름으로 추측하지 말고, 승인 목록의 계정으로 구분합니다.

소유 계정 하나만 쓰는 봇은 numeric Telegram ID를 허용 목록에 넣는 `allowlist` 정책으로도 입구를 제한할 수 있습니다. 모든 계정을 받는 `open` 정책은 제한된 도구만 둔 공개 봇에만 맞습니다. ([docs/channels/telegram](https://docs.openclaw.ai/channels/telegram))

### 다른 입구에도 같은 문을 둡니다

오늘은 Telegram만 연결합니다. Discord와 Slack도 같은 순서로 열 수 있습니다. 토큰은 비밀로 보관하고, 대화할 계정의 범위를 먼저 제한합니다.

Discord는 개발자 포털에서 애플리케이션을 만든 뒤 **Bot** 탭에서 봇을 만듭니다. 같은 탭의 **Reset Token**으로 토큰을 발급하고, **Privileged Gateway Intents**에서 Message Content Intent를 켭니다. **OAuth2 URL Generator**에서 `bot`과 `applications.commands` 범위를 골라 서버에 초대합니다. 토큰은 환경 변수로 둔 설정 파일을 `openclaw config patch --file ./discord.patch.json5`로 등록한 뒤 Gateway를 시작합니다. ([docs/channels/discord](https://docs.openclaw.ai/channels/discord))

Slack은 `Create New App`에서 **From a manifest**를 골라 워크스페이스와 manifest JSON을 넣어 앱을 만듭니다. 앱을 만든 뒤 App-Level Token에 `connections:write`를 더해 발급하고, **Install to Workspace**에서 Bot User OAuth Token을 받습니다. 두 토큰은 설정 파일을 `openclaw config patch --file ./slack.socket.patch.json5`로 등록합니다. 기본 전송 방식인 Socket Mode는 공개 Gateway 주소가 필요 없습니다. ([docs/channels/slack](https://docs.openclaw.ai/channels/slack))

채널이 열렸습니다. 이제 무엇을 허용하고 무엇을 막을지 봅니다.
