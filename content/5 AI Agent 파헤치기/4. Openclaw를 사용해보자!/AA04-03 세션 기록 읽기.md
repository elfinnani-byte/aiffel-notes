## 세션 기록 읽기

WebChat에서 주고받은 직접 메시지는 기본적으로 하나의 이어지는 대화인 main session(메인 세션)으로 들어갑니다. 이 대화의 표준 키는 `agent:<agentId>:main`이며, 웹 앱에서는 Home 화면으로 엽니다. 대화의 연속성은 화면만이 아니라 설정·세션·워크스페이스에 남는 정보와 함께 읽습니다.

### 설정파일을 구분해 봅니다

`~/.openclaw/`는 설정, 자격 증명, 세션을 보관하는 위치입니다. 기본 설정 파일은 `~/.openclaw/openclaw.json`입니다. 에이전트별 기록은 ~`/.openclaw/agents/<agentId>/agent/openclaw-agent.sqlite`에 세션 행·대화 기록·에이전트별 실행 상태로 남고, `~/.openclaw/agents/<agentId>/sessions/`에는 이전 형식의 이전 입력과 보관·지원용 자료가 남습니다.

워크스페이스는 이와 분리합니다. 기본 워크스페이스는 `~/.openclaw/workspace`이며, 파일 도구가 상대 경로를 해석하는 기본 작업 폴더입니다. 이곳의 `MEMORY.md`에는 오래 남길 사실과 결정이, `memory/` 폴더에는 날짜별 메모가 놓입니다. 실제 파일은 `memory/2026-09-04-제목.md`처럼 날짜에 제목이 붙은 이름으로 만들어집니다. 설정 파일, 세션 기록, 워크스페이스는 같은 파일이 아니며 각자 역할이 다릅니다.

### WebChat 뒤의 변화를 관찰합니다

터미널에서 `~/.openclaw/` 아래를 열고 설정 파일과 에이전트별 디렉터리 이름을 먼저 찾습니다. 개인 대화와 자격 증명은 복사하거나 공유하지 않습니다. 이어서 WebChat의 Home에서 짧은 대화를 한 번 더 보낸 뒤, 같은 위치에서 세션 저장소와 워크스페이스의 파일 이름·수정 시각을 다시 비교합니다.

워크스페이스 메모의 색인 상태는 다음 명령으로 살핍니다.

```bash
openclaw memory status
```

### 말보다 실행 기록을 먼저 봅니다

대화 화면의 답변은 작업이 끝났다는 인상을 줄 수 있습니다. 그러나 실제 도구 호출과 파일 변경은 세션 저장소와 워크스페이스의 기록을 함께 보아야 읽힙니다. OpenClaw에서는 Home의 이어지는 대화, 에이전트별 SQLite 기록, 워크스페이스의 메모를 나란히 놓고 어느 대화가 어떤 흔적을 남겼는지 확인합니다. 답변 문장만으로 완료를 판단하지 않고, 기록의 경로와 변화도 함께 근거로 삼습니다.

세션 기록 안에서 "말한 것"과 "한 것"은 서로 다른 줄로 저장됩니다. 모델이 낸 줄(assistant)에는 말한 문장(text)과 하겠다고 요청한 도구 호출(toolCall)이 함께 남고, 실제로 실행한 결과는 별도의 결과 줄(toolResult)에 남습니다. 요청과 결과는 각자 붙은 번호(toolCallId)로 짝지어집니다. 완료 여부를 묻는다면 문장이 아니라 결과 줄을 보아야 합니다.
