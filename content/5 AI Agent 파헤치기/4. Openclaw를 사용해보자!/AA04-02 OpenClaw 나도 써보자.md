## OpenClaw 나도 써보자

이제 OpenClaw를 직접 깔아 봅니다. OpenClaw는 한 덩어리 명령이 아니라 여러 부품으로 이루어져 있습니다. 그중 첫 번째가 **게이트웨이**(Gateway)입니다. 게이트웨이는 채널 연결을 오래 유지하는 실행 과정입니다. 기본적으로 내 컴퓨터의 `127.0.0.1:18789`에서 연결을 받습니다. `127.0.0.1`은 이 컴퓨터 안에서만 접속한다는 뜻입니다.

오늘은 OpenClaw를 연습용 환경에 설치하고, onboard(**온보딩**)으로 첫 설정을 마친 뒤 WebChat에서 한 문장을 보냅니다. 온보딩은 처음 실행에 필요한 선택을 대화형으로 받는 과정입니다. 설치 결과는 버전·진단·응답 화면에 남습니다.

### 시작 위치와 버전을 먼저 확인합니다

이 실습은 오늘 처음 만드는 연습 폴더에서만 진행합니다. 실제 업무 저장소, 홈 디렉터리의 설정 폴더, 개인 파일이 있는 위치에서는 진행하지 않습니다. 새 터미널을 열고 연습 폴더를 만든 뒤 들어갑니다.

```bash
mkdir -p ~/openclaw-lab && cd ~/openclaw-lab
```

`-p`는 이미 있어도 오류를 내지 않는 옵션입니다. 이어서 현재 위치와 Node 버전을 확인합니다.

```bash
pwd
node --version
```

공식 설치 문서는 Node `22.22.3+`, `24.15+`, `25.9+`를 요구하며 Node 26을 권장합니다. 화면의 버전과 수업 자료에 적힌 권장 버전을 대조합니다. 범위에 맞지 않으면 Node를 억지로 바꾸지 말고, 아래의 실패 경로로 이동합니다.

격리는 폴더 이름만으로 완성되지 않습니다. OpenClaw는 실습 폴더 안에서 설치해도 설정과 상태를 홈 폴더의 `~/.openclaw/` 아래에 모으고 자격 증명도 이곳에 저장합니다. 그래서 수업용 계정·수업용 키만 사용하고, 온보딩 화면에서 실제 업무 계정이나 비밀값을 요구하면 입력을 멈춥니다. 설치 뒤 이 폴더에 어떤 파일이 생겼는지 직접 열어 확인합니다.

### 설치와 온보딩을 한 번씩 실행합니다

공식 README는 macOS·Linux·WSL2에는 `install.sh`, Windows에는 `install.ps1`을 안내합니다. npm은 운영 체제와 관계없이 같은 명령으로 설치할 수 있고, 설치할 버전을 지정할 수도 있습니다. 노트북 환경이 섞인 수업에서는 npm 경로를 공통 절차로 사용합니다.

npm에서 공식 패키지를 설치합니다. 아래 명령의 `--allow-scripts=openclaw`는 npm의 lifecycle script 허용 옵션입니다.

```bash
npm install -g openclaw@latest --allow-scripts=openclaw
openclaw --version
```

두번째 명령은 설치된 버전을 확인합니다. `latest`는 설치 시점의 최신 버전을 받아 오므로, 화면에 보이는 숫자는 설치한 날짜에 따라 다를 수 있습니다.

이어서 온보딩과 관리 서비스를 함께 실행합니다.

```bash
openclaw onboard --install-daemon
```

데몬은 터미널 창을 계속 열어 두지 않아도 백그라운드에서 실행되는 관리 서비스입니다. 이 옵션은 대화형 설정과 데몬 설치를 함께 수행합니다. macOS에서는 LaunchAgent, Linux/WSL2에서는 systemd 사용자 서비스로 설치될 수 있습니다.

온보딩 화면에서는 수업용 인증 경로만 고릅니다. 공식 문서에 나오는 경로는 `ANTHROPIC_API_KEY`를 쓰는 API 호출과, 같은 호스트에서 로그인한 Claude Code를 재사용하는 `claude-cli`입니다. 코딩 에이전트 구독 계정을 연결해도 Claude가 구독으로 완벽하게 동작하는 것은 아닙니다. OpenClaw는 내부적으로 Claude CLI를 실행해, 로그인해 둔 Claude Code 세션을 대신 사용합니다. 그래서 요금과 한도는 구독에서 차감되지만 실제 호출은 CLI를 거칩니다. 반대로 API 키 경로는 OpenClaw가 직접 키를 들고 호출하므로 종량 과금입니다. API 키 값을 메모나 화면 캡처에 남기지 않습니다.

### 실행 상태를 세 곳에서 확인합니다

온보딩을 마쳤다고 바로 채널을 연결하지 않습니다. 다음 명령을 순서대로 실행합니다.

```bash
openclaw doctor
openclaw gateway status
```

`doctor`는 구성 진단 명령입니다. 경고와 오류가 있으면 마지막 줄만 보고 성공으로 판단하지 않습니다. 통과한 항목과 남은 항목을 화면 그대로 읽는 것이 진단의 목적입니다. `gateway status`에서는 게이트웨이의 실행 상태를 봅니다. 둘 중 하나라도 실패하면 그 시점에서 멈춥니다.

진단이 끝났으면 웹 대화 화면으로 옮깁니다. **WebChat**은 OpenClaw가 자체적으로 제공하는 대화 화면입니다. 실행 중인 게이트웨이가 이 화면을 내 컴퓨터의 `http://127.0.0.1:18789` 주소에서 내어 놓고, 브라우저가 게이트웨이와 WebSocket 연결을 유지한 채 이력과 메시지를 주고받습니다. **WebSocket**은 브라우저와 서버가 연결을 끊지 않고 메시지를 계속 주고받는 통신 방식입니다. 화면은 저절로 열리지 않습니다. `openclaw dashboard` 명령을 실행하면 기본 브라우저에서 이 주소가 열립니다. 게이트웨이가 멈춰 있으면 화면이 열려도 새 메시지를 보낼 수 없습니다. 브라우저에서 화면을 열고 다음처럼 무해한 한 문장을 보냅니다.

> 이 메시지를 받았다면 `연결 확인`이라고만 답해 주세요.

주소를 추측해 입력하거나 외부 네트워크에 포트를 열지 않습니다. 기본 주소의 외부 접속은 공식 문서에서 권장하지 않으며, 원격 접속에는 별도의 승인 절차가 필요합니다.

원격에서 이 화면에 들어가야 할 때 공식 문서가 안내하는 길은 **Tailscale** 연결입니다. Tailscale은 내 기기들을 하나로 묶어 사설망처럼 쓰게 해 주는 도구입니다. OpenClaw는 게이트웨이를 127.0.0.1에 둔 채 Serve 기능으로 사설망 안에서만 쓰는 HTTPS 주소를 붙이고, Funnel 기능으로 공개 주소를 만들 수도 있습니다. 텔레그램 연결과는 다른 길입니다. 텔레그램은 에이전트가 메시지를 받을 새 창구를 여는 것이고, 이쪽은 이미 떠 있는 WebChat 화면을 다른 기기에서도 쓰게 하는 길입니다. ([docs.openclaw.ai/gateway/tailscale](https://docs.openclaw.ai/gateway/tailscale))

### 생긴 상태를 열어 봅니다

설치와 온보딩 뒤에는 상태가 남습니다. 상태와 설정은 홈 폴더의 `~/.openclaw/` 아래에 모입니다. 온보딩 완료 화면, `doctor` 출력, `gateway status` 출력에서 이 경로가 표시되는지 확인하고, 다음 명령으로 직접 엽니다.

```bash
ls -la ~/.openclaw
```

폴더 이름과 보이는 파일·하위 폴더 이름이 설치가 남긴 흔적입니다. 파일 내용에 토큰, 키, 개인 대화가 보이면 내용을 복사하거나 공유하지 않습니다. 화면에 표시된 경로만 따라갑니다. 화면에 없는 경로를 검색하거나 추측으로 만들어 열지 않습니다.

### 실행 상태를 확인하고 수업이 끝날 때 멈춥니다

`openclaw --version`, 온보딩 완료 화면, `openclaw gateway status`, WebChat 첫 응답을 차례로 살핍니다. 각 결과에서 화면에 나타난 버전, 상태, 응답이 설치가 끝났다는 증거입니다. 설치·온보딩·진단이 실패했다면 `openclaw --version`으로 설치 여부부터 다시 확인합니다. WebChat에서 응답을 받지 못했다면 게이트웨이 상태와 오류 문구를 함께 봅니다.

### 수업이 끝날 때 멈추는 법

데몬으로 띄웠다면 다음 명령으로 멈춥니다.

```bash
openclaw daemon stop
```

게이트웨이를 터미널에서 직접 실행했다면 그 터미널에서 Ctrl-C를 누릅니다. 이어서 다음 명령을 실행해 멈췄는지 확인합니다.

```bash
openclaw gateway status
```

프로그램을 멈춰도 상태 디렉터리와 설정 파일은 지우지 않는 한 남습니다. 위치는 다음 명령으로 확인합니다. 기본 설정 파일은 `~/.openclaw/openclaw.json`입니다.

```bash
openclaw config file
```

마무리에서는 프로그램을 끄고, 수업용 토큰과 인증 경로의 보관 위치와 접근 가능 범위를 다시 살핍니다.
