## 코딩 에이전트에게 같은 흐름을 맡긴다

앞 실습에서는 화면에서 흐름을 만들었습니다. 이번에는 같은 흐름을 코딩 에이전트에게 맡깁니다. 맡긴다는 말은 명령을 대신 실행하는 데서 끝나지 않습니다. 결과와 실행 기록을 누가 확인했는지도 함께 정합니다. 화면에서 5분쯤 걸릴 일을 에이전트가 30초 만에 정리해도, 그 속도만으로 결과를 믿지는 않습니다.

n8n 화면의 Settings → n8n API에서 API 키를 발급합니다. API 키는 워크플로 목록 조회와 생성, 삭제, 실행 기록 조회에 사용됩니다. 터미널에서는 `npx @n8n/cli`로 설치 없이 CLI를 실행합니다. 이어서 인스턴스 주소와 API 키를 설정하고 워크플로 목록을 확인합니다.

```bash
npx @n8n/cli config set-url https://n8n.vibemakers.kr
npx @n8n/cli config set-api-key <발급한 API 키>
npx @n8n/cli workflow list
```

공식 스킬은 워크플로 조회와 생성, 활성화, 실행 기록 확인, 연결 정보 관리, `--jq`로 값 고르기를 지원합니다. Claude Code, Cursor, Windsurf는 공식 스킬 설치를 지원합니다. opencode와 Antigravity는 같은 CLI를 도구로 사용합니다. 다음 명령으로 스킬을 전역 설치하면 코딩 에이전트가 CLI의 작업 범위를 알 수 있습니다.

```bash
npx @n8n/cli skill install --global
```

코딩 에이전트에는 연결 확인, 정의 검토, 생성, 기록 조회의 순서를 한 요청에 담습니다. 요청에는 생성 전에 검토할 내용을 분명히 적습니다.

> 먼저 `workflow list`로 이 인스턴스의 연결 상태를 확인해 줍니다. 이어서 Manual Trigger → HTTP Request(`https://en.wikipedia.org/api/rest_v1/page/summary/N8n`) 워크플로 정의를 `wf.json`으로 만들고, 생성 명령을 실행하기 전에 JSON의 노드와 연결을 보여 줍니다. 확인했다는 답을 받은 뒤 생성합니다. 생성 뒤에는 실행 기록을 찾아 상태코드와 원 응답을 보여 줍니다.

에이전트는 `workflow create --file=wf.json`으로 워크플로를 생성할 수 있습니다. 이 JSON에는 `name`, `nodes`, `connections`, `settings`가 들어갑니다. `nodes`에는 노드의 id, 이름, 종류, 버전, 위치가 들어갑니다. `connections`에는 노드 사이의 연결이 들어갑니다. 에이전트가 보여 준 JSON에서 두 노드의 이름과 URL, 연결을 검토한 뒤에만 생성을 승인합니다. 에이전트가 보여 준 JSON을 검토하는 순간에는, 짧은 JSON 한 줄이 외부 요청으로 이어진다는 긴장감이 생깁니다. 생성 뒤에는 화면에서 같은 이름의 워크플로와 실행 기록을 열어 노드와 연결을 다시 대조합니다.

실행 기록도 에이전트에게 요청할 수 있습니다.

> 방금 실행을 찾아 상태코드와 원 응답을 보여 줍니다.

에이전트는 `execution list`와 `execution get <실행 ID>`로 기록을 찾아 상태코드와 원 응답을 보여 줄 수 있습니다. CLI에는 새 수동 실행을 시작하는 명령이 없으므로, Manual Trigger 워크플로의 첫 실행은 n8n 화면에서 수행합니다. 이후 실행 기록을 조회합니다. 상태코드와 원 응답이 어느 노드 출력에 보이는지는 화면에서 다시 확인합니다. 에이전트는 CLI 호출과 워크플로 생성·조회를 맡습니다. 학생은 생성 결과와 실행 근거를 확인합니다. 이 구분이 업무를 어디까지 맡길지 판단하는 근거가 됩니다.

### 한 걸음 더: MCP로 실행 기록까지 확인합니다

n8n은 MCP 서버도 제공합니다. 인스턴스 설정에서 MCP 서버를 활성화하면 코딩 에이전트에게 n8n의 작업을 더 넓게 맡길 수 있습니다. MCP로는 `execute_workflow`와 `test_workflow`를 사용해 워크플로 실행까지 맡길 수 있습니다. 이는 CLI에 새 수동 실행을 시작하는 명령이 없다는 앞의 한계와 대비됩니다. MCP 활성화와 연결의 구체적인 절차는 이 강의 범위에서 다루지 않습니다.

MCP에서는 SDK 코드를 `validate_workflow`로 먼저 검증할 수 있습니다. 실측에서는 두 노드 워크플로 코드가 `valid: true`를 반환했습니다. 이어서 `create_workflow_from_code`로 워크플로를 만들 수 있습니다. `execute_workflow`에 manual 모드를 지정해 실행하면 실행 기록이 `success`로 남습니다. `get_workflow_execution`으로 실행 기록을 조회하면 각 노드의 실행 상태와 HTTP Request가 돌려준 JSON을 확인할 수 있습니다. MCP가 보여 준 JSON도 원 응답과 대조해 확인합니다.

다음 섹션에서는 요약을 해석으로 다룹니다. AI가 만든 문장을 원 응답과 나란히 놓고, 무엇이 보존되고 무엇이 달라졌는지 확인합니다.
