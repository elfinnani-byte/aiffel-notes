# [AI Agent 파헤치기] - 2. 자동화와 워크플로 — 규칙을 정하고 그래프를 잇는다

## 자동화와 워크플로 — 규칙을 정하고 그래프를 잇는다

자동화에 맡길 일을 고를 때는 먼저 규칙을 확인합니다. 일을 설명하면서 "무조건", "항상", "매번"을 쓸 수 있다면 규칙이 비교적 선명합니다. 새 문의에 접수 번호를 붙이는 규칙을 정합니다. 매일 아침 전날 매출을 표에 옮기는 규칙을 정합니다. 첨부가 없는 신청서에는 안내를 보내도록 정합니다. 이런 일은 조건과 결과를 이어 적을 수 있습니다.

반대로 "친절하게 답합니다"나 "중요한 메일부터 봅니다"에는 사람의 판단이 들어갑니다. 규칙인지 시험하려면 낯선 동료에게 일을 가르친다고 상상합니다. 동료가 "이 경우에는 어떻게 하나요"라고 물었을 때 "알아서 해주세요."라고 답하게 된다면, 그 부분은 아직 규칙이 아닙니다. 자동화는 빈틈을 알아서 메우는 마술이 아닙니다. 빈틈까지 적어 둔 조리법처럼 작동합니다.

업무는 한 번의 행동으로 끝나지 않는 경우가 많습니다. 문의를 받고 분류합니다. 답을 고르고 기록합니다. 필요한 경우 담당 부서로 넘기도록 정합니다. 이처럼 여러 행동을 연결한 설계도를 그래프라고 설명합니다. 그래프에는 행동을 나타내는 점과 흐름을 나타내는 화살표가 있습니다. 조건에 따라 길이 갈라지며, 실행 기록도 각 흐름에 남습니다.

그래프가 순서를 정하는 워크플로에서는 사람이 경로를 미리 정합니다. 새 문의를 분류합니다. 환불 관련 문의는 담당 부서로 보냅니다. 나머지는 일반 답변 흐름으로 보냅니다. Anthropic은 워크플로를 "미리 정의된 코드 경로로 LLM과 도구가 조율되는 시스템"으로 정의합니다. 따라서 워크플로의 핵심은 모델이 자유롭게 움직이는 데 있지 않습니다. 정해 둔 경로와 분기, 그리고 검토할 수 있는 기록에 있습니다. (출처: [Anthropic, Building effective agents](https://www.anthropic.com/research/building-effective-agents))

다음 행동을 정하는 방식은 세 국면으로 나뉩니다. 사람이 하나씩 시키는 국면에서는 사람이 대화에서 다음 요청을 선택합니다. 그래프가 순서를 정하는 국면에서는 미리 만든 연결 규칙이 다음 행동을 선택합니다. 모델이 다음을 고르는 국면에서는 연결된 도구 가운데 필요한 도구를 모델이 선택합니다. 같은 요약 업무라도 책임의 경계와 확인할 기록이 달라집니다.

그림은 세 국면을 다섯 가지 질문으로 비교하는 틀을 보여 줍니다.

도구 소개 페이지에서는 기능 수가 먼저 보입니다. 연결 가능한 서비스 수나 모델 이름은 쉽게 확인합니다. 그러나 기능 수는 업무의 위험과 무관합니다. 연결이 많아도 입력을 어디서 읽었는지 알 수 없다면 잘못된 요약을 고치기 어렵습니다. 반대로 기능이 적어도 읽기 전용 공개 데이터를 받아 검토용 초안을 만드는 일에는 더 안전할 수 있습니다.

비교할 때는 다섯 가지 질문을 사용합니다. **통제**는 누가 시작, 중지, 승인, 쓰기 권한을 정하는지 확인합니다. **관측**은 입력, 도구 호출, 응답, 실패 지점을 기록으로 되짚을 수 있는지 확인합니다. **이식성**은 프롬프트, 연결 규칙, 코드, 비밀값을 다른 환경으로 옮길 때 무엇을 다시 준비해야 하는지 확인합니다. **비용**은 구독, 모델 처리량, 실행 횟수처럼 어떤 단위로 요금이 계산되는지 확인합니다. **데이터 경로**는 입력, 로그, 모델, 결과, 비밀값이 어느 서비스와 저장 위치를 지나는지 확인합니다.

예시 업무를 하나 정합니다. 매일 아침 공개 데이터에서 정보를 읽고 세 문장으로 요약을 받습니다. 공개 데이터는 개인 정보가 없는 공개 API라고 가정합니다. 같은 업무라도 세 국면에 놓으면 확인할 내용이 달라집니다.

| 놓아 보는 국면 또는 제품 | 통제는 시작·수정·전송을 승인하는 주체를 확인합니다. | 관측은 원문 응답, 요약, 실패 기록의 위치를 확인합니다. | 이식성은 설정·프롬프트·비밀값을 옮길 때 남는 내용을 확인합니다. | 비용은 매일 실행을 세는 단위와 공유 한도를 확인합니다. | 데이터 경로는 요청·로그·요약·비밀값의 이동 위치를 확인합니다. |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 사람이 하나씩 시킴 | 사람은 매일 대화에서 요청합니다. 예약과 연결 기능이 있다면 켜고 끄는 권한을 확인합니다. | 요약과 별도로 공개 데이터의 원문 응답을 저장하거나 다시 열 수 있는지 확인합니다. | 대화 지시와 연결 설정을 다른 계정이나 도구로 옮길 수 있는지 확인합니다. | 플랜의 사용량 한도와 연결 도구 사용량이 같은 한도인지 확인합니다. | 공개 데이터, 대화 내용, 연결 도구 입력이 각각 어느 제공자에게 전달되는지 확인합니다. |
| 그래프가 순서를 정함 | 정해 둔 시각의 실행과 요약 전송을 수정하거나 멈추는 권한을 확인합니다. 발송은 별도 승인을 거치게 설정합니다. | 각 실행의 요청, 응답, 분기, 오류를 실행 기록에서 확인합니다. | 워크플로를 내보낸 뒤에도 비밀값을 다시 넣어야 하는지와 버전 차이를 확인합니다. | 하루 한 번의 전체 워크플로 실행이 어떤 단위로 계산되는지 확인합니다. | 호스팅 위치, 실행 로그, 외부 모델, 공개 API 사이의 데이터 이동을 확인합니다. |
| 모델이 다음을 고름 | 일정 설정, 코드 변경, 파일 저장, 메시지 발송에 필요한 승인 경로를 각각 확인합니다. | 실행 명령, 코드 변경, 표준 출력, 오류를 사람이 재현할 수 있는지 확인합니다. | 저장소의 코드와 환경 변수 가운데 다른 컴퓨터에서 다시 준비할 내용을 확인합니다. | 계정 사용량, 모델 처리량, 실행 환경 비용을 각각 확인합니다. | 공개 데이터 요청, 로컬 파일, 환경 변수, 모델 입력, 저장소의 연결 경로를 확인합니다. |

표는 제품의 승자를 가리는 도구가 아닙니다. 확인하지 않은 전제를 드러내는 도구로 사용합니다. 대화 도구, 흐름 도구, 개발 도구를 비교할 때 제품 이름을 행에 더할 수 있습니다. 다만 공식 문서에서 확인하지 못한 가격, 연결 수, 기능 차이는 **미확인**으로 남겨 둡니다. 코드가 저장소에 있어도 실행 환경과 비밀값을 재현하지 못하면 업무 전체를 옮길 수 없습니다.

그래프 기반 도구도 이름만으로 판단하지 않습니다. 워크플로 전체가 한 번 실행된 일을 execution이라고 부르는 도구가 있는가 하면, 노드 하나하나에 과금을 매기는 도구도 있습니다. 따라서 과금 표의 숫자만 나란히 두고 비교하지 않습니다. 대화 모델과 도구를 연결해 완료에 필요한 도구를 모델이 고르게 하는 노드를 갖춘 도구도 있습니다. 이것은 통제가 필요 없다는 뜻이 아닙니다. 연결한 도구와 실행 기록에서 확인할 요청·응답을 더 분명히 살펴야 한다는 뜻입니다.

이제 이 질문들을 화면에서 직접 확인합니다. 다음 섹션에서는 그래프형 도구 가운데 하나인 n8n을 골라, 트리거, 연결, 실행 기록이 어떻게 그래프로 이어지는지 살펴봅니다.
