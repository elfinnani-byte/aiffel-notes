# [AI Agent 파헤치기] - 3. 워크플로 도구를 인스턴스에서 관찰한다

## 워크플로 도구를 인스턴스에서 관찰한다

반복 업무를 덜어 줄 도구를 검색하면 화면마다 전혀 다른 세계가 펼쳐집니다. ChatGPT나 Claude 같은 대화창에서는 말로 요청을 건네고, 대화의 맥락을 바탕으로 다음 행동을 정합니다. 답이 곧바로 돌아오는 장면은 친숙하지만, 그 판단이 어떤 연결을 거쳤는지는 대화창 밖에서 살펴야 합니다.

Zapier는 널리 쓰이는 노코드 자동화 서비스입니다. 수천 개 앱을 미리 정한 '트리거(이런 일이 일어나면) → 액션(이렇게 한다)' 규칙으로 연결합니다. 연결한 앱 수와 실행 횟수인 task를 기준으로 이용료가 달라지므로 비용과 실행 기록을 함께 살펴야 합니다. 
Make는 구 Integromat이라는 이름으로도 알려진 시각적 시나리오 편집기입니다. 흐름을 그래프처럼 그리고 필터·반복·에러 처리 분기를 시나리오 안에서 조립합니다. 연산량인 operation 단위로 비용이 매겨지므로, 같은 흐름도 무엇을 얼마나 실행했는지 관찰할 재료가 됩니다. 두 서비스에서는 다음 행동을 사람이 미리 정한 규칙이 대신 수행합니다. 이 점에서 같은 층에 놓이지만, n8n에서는 그래프를 내 눈으로 들여다보고 나중에는 직접 띄워 볼 수도 있습니다.

n8n이나 Node-RED 같은 그래프형 도구에서는 노드와 선이 다음 행동과 데이터의 이동 경로를 화면에 드러냅니다. 코드를 쓰거나 코딩 에이전트에게 일을 맡기는 방식에서는 코드·터미널·저장소가 그 역할을 나누어 가집니다. 더 세밀한 규칙을 정할 수 있지만, 흐름과 기록을 한 화면에서 모두 보기는 어려울 수 있습니다. 이 스펙트럼을 훑은 뒤에는 다음 행동을 누가 정하는지, 그 과정이 어디까지 보이는지, 무엇에 비용이 붙는지를 비교할 수 있습니다.

이 수업의 관찰 도구로는 n8n을 고릅니다. n8n은 2019년 베를린에서 태어난 워크플로 자동화 도구입니다. 이름은 노드와 오토메이션을 합친 nodemation에서 왔고, 노드를 잇는 그래프가 곧 실행되는 구조 자체가 이름의 출발점입니다. 화면에서 노드라 부르는 블록을 연결해 흐름을 그리면, 그 그래프가 그대로 돌아갑니다. 메일, 폼, 스프레드시트, 채팅 같은 외부 서비스와 공개 API를 노드로 묶을 수 있고, 실행할 때마다 어느 노드가 무엇을 주고받았는지 기록이 남습니다. 그래프가 화면에 그대로 보이므로 흐름과 데이터의 이동을 눈으로 따라갈 수 있습니다. 관찰 학습에 알맞은 이유입니다.

n8n의 성장도 이 구조를 보여 줍니다. 2025년 한 해에만 GitHub 별이 11만 개 넘게 늘었고, 월간 활동 사용자가 170만을 넘었습니다. AI 에이전트 노드를 앞세워 빠르게 커뮤니티를 넓히는 중입니다. 사용 규모가 곧 신뢰라는 뜻은 아닙니다. 다만 많은 사람이 같은 도구로 흐름을 만들고 기록을 남긴다는 사실은, 배운 내용을 강의 밖에서도 써먹을 생태계가 있다는 뜻입니다.

n8n은 또 선택의 폭을 넓혀 줍니다. 소스 코드가 공개된 fair-code 방식이라, 나중에 내 컴퓨터나 서버에 직접 띄워 볼 수 있습니다. 클라우드 서비스가 문을 닫아도 내 환경에서 흐름을 계속 돌릴 수 있다는 뜻입니다. 수업에서는 이미 마련된 인스턴스에 접속하므로, 설치 없이 계정을 만들면 첫 워크플로를 바로 조립할 수 있습니다.

처음에는 공개 정보를 읽는 짧은 흐름을 만듭니다. 화면에서 설계한 흐름과 실행 뒤에 남은 기록을 나란히 보면, 도구가 보여 준 사실과 아직 확인하지 못한 사실을 구분할 수 있습니다. 검색 결과에서 이름만 보던 도구가 연결된 선과 응답 데이터로 움직이는 순간을 만나게 됩니다.

![n8n 편집 화면에서 Manual Trigger와 HTTP Request 노드를 연결한 모습](n8n-editor-manual-trigger-http.png)<span class="img-caption">그림: Manual Trigger에서 시작해 Wikipedia 요약을 요청하는 HTTP 노드까지 연결한 n8n 워크플로. 편집 화면의 연결선과 Execute workflow 버튼이 사람이 정한 순서와 수동 실행 지점을 드러냅니다.</span>

수업용 n8n 접속 주소는 [https://n8n.vibemakers.kr](https://n8n.vibemakers.kr) 입니다. 계정은 다음 설문 폼에서 만듭니다. 브라우저로 [https://n8n.vibemakers.kr/form/ea2d73cf-9bdd-4340-ac92-3a2a2a5e5bcf](https://n8n.vibemakers.kr/form/ea2d73cf-9bdd-4340-ac92-3a2a2a5e5bcf) 를 열면 먼저 아이디와 비밀번호를 물어보는데, 처음 설문 진입용으로 안내받은 `modu`와 `labs`를 입력합니다. 폼을 제출하면 수업용 계정이 만들어지고, 그 계정으로 접속 주소에 로그인합니다. 로그인 뒤 화면에 표시되는 버전은 그대로 기록해 둡니다. 개인 가입, 초대 수락, 비밀번호 설정처럼 인증 방법을 추정하여 진행하지 않습니다. 로그인에 실패했을 때 여러 방식으로 계정을 만들려 하면, 수업 계정의 권한 경계와 기록이 흐려질 수 있습니다. 멈춘 화면, 오류 문구, 접속한 주소를 남기는 편이 더 정확한 관측입니다.

새 워크플로 화면에서 `Manual Trigger`와 `HTTP Request`를 찾아 연결합니다. `Manual Trigger`는 `Execute Workflow`로 실행할 때에만 흐름을 시작하므로, 첫 실행의 출발점이 눈앞에 보입니다. `HTTP Request`의 주소에는 인증 없이 읽을 수 있는 `https://en.wikipedia.org/api/rest_v1/page/summary/N8n`를 넣습니다. 두 노드를 이은 뒤 실행하면, 그래프로 설계한 흐름이 공개 API를 읽고 결과를 돌려줍니다.

실행이 끝나면 실행 목록에서 방금 흐름의 기록을 엽니다. `HTTP Request` 노드의 출력에는 HTTP 상태코드와 서버가 돌려준 원 응답이 함께 보입니다. 응답에서 `title`, `description`, `timestamp`, `content_urls` 필드를 찾습니다. 처음 실행이 성공하면 선으로만 보이던 흐름이 실제 데이터를 가져왔다는 사실을 기록으로 확인하게 됩니다. 실행 기록은 워크플로 전체가 한 번 실행된 단위이므로, 노드 화면과 실행 한 건을 구별해 살핍니다.

다음 표에는 화면에서 확인한 내용을 남깁니다.

| 관찰 질문 | 확인한 화면 위치 또는 값 |
| :--- | :--- |
| Manual Trigger와 HTTP Request 노드를 찾았는가 |  |
| 실행은 어디에 기록되는가 |  |
| 원 응답은 어디에 보이는가 |  |

이 연결 방식은 설문 폼의 응답을 스프레드시트로 옮기는 흐름으로 이어질 수 있습니다. 정해진 시각에 공개 API를 읽어 요약을 남길 수도 있습니다. 새 메일이나 폼 접수를 감지해 알림을 보내거나, 웹페이지의 변화를 확인하는 흐름으로 넓힐 수도 있습니다. 화면에 노드가 있다는 사실과 실제 업무를 맡겨도 된다는 판단은 같지 않습니다. 연결할 서비스의 권한, 실패 뒤에 남는 기록, 사람이 다시 확인할 지점을 함께 살펴야 합니다.

다음 섹션에서는 같은 흐름을 코딩 에이전트에게 맡겼을 때 규칙과 기록이 어디에 남는지 관찰합니다. 그래프에서 확인한 질문을 코드와 터미널로 옮겨 비교합니다.
