# [4.프로젝트 AI 에이전트 도구 - 내 AI를 더 강하게] - 3. 스킬 - 반복 작업을 AI에게 외워 두기

---

## 스킬(Skill) - 반복하는 일을 AI에게 '외워' 두기

### 문제: 매번 같은 설명을 다시 하고 있지 않나요?

AI에게 "우리 브랜드 톤으로 정리해 줘", "이 형식으로 보고서 만들어 줘"를 **매번 처음부터 설명**하고 있다면 - 지겹고, 그때그때 결과도 달라집니다. 이걸 **재프롬프트(re-prompting) 문제**라고 합니다.

### 스킬 = 재사용하는 '플레이북'

**스킬(Skill)** 은 자주 하는 작업을 **한 번 적어 두고 계속 꺼내 쓰는 설명서**입니다. 기술적으로는 그냥 **폴더 하나**입니다 - 그 안에 `SKILL.md`라는 파일에 **"무엇을, 언제 쓰는지"** 를 적어 두면, AI가 관련된 일을 만났을 때 **알아서 꺼내 씁니다.** (출처: [Claude Platform Docs, "Agent Skills"](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview))

특히 영리한 점은 **켜 두어도 거의 공짜**라는 것입니다. AI는 평소엔 스킬의 **이름과 한 줄 설명만** 알고 있다가(약 30~50 토큰 - '토큰'은 AI가 읽고 쓰는 글자 단위이자 곧 요금 단위입니다. 자세한 건 뒤 하네스 섹션에서 봅니다), 정말 필요할 때만 본문을 읽습니다. 그래서 수십 개를 켜 둬도 느려지지 않습니다.

예를 들면 - "내가 쓴 글을 **우리 서비스 말투로** 다듬는 법"을 스킬로 만들어 두면, 다음부터는 "말투 스킬 써서 다듬어 줘" 한마디면 됩니다.

### SKILL.md는 실제로 어떻게 생겼나

스킬 폴더 안 `SKILL.md`는 두 부분입니다 - 맨 위 **머리말(이름·설명)** 과 그 아래 **본문(실제 지시)**. 예를 들어 "우리 서비스 말투로 안내문 다듬기" 스킬은 이렇게 생겼습니다.

```
---
name: tone-polish
description: 사용자용 안내 문구를 우리 서비스 말투(정중하고 짧게)로 다듬을 때 사용
---

# 우리 서비스 말투로 다듬기

1. 한 문장은 40자 이내로 끊는다.
2. "~해야 합니다"보다 "~해 주세요"처럼 부탁형으로 쓴다.
3. 전문용어는 괄호로 짧게 풀어 준다.
4. 마지막에 도움받을 곳(고객센터 링크)을 붙인다.
```

핵심 원리는 **점진 공개(progressive disclosure)** 입니다. AI는 평소 머리말의 `name`과 `description`만(수십 토큰 수준) 훑고 있다가, 지금 하는 일이 그 설명과 맞을 때만 본문 전체를 읽어 옵니다. 그래서 스킬을 수십 개 켜 둬도 평소엔 거의 공짜이고, 필요한 순간에만 '펼쳐집니다'. `description`을 잘 쓰는 게 중요한 이유가 여기 있습니다 - AI가 **언제 이 스킬을 꺼낼지** 를 그 한 줄로 판단하니까요. (출처: [Claude Platform Docs, "Agent Skills"](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview))

### 남들이 이미 만들어 둔 스킬들

스킬은 내가 직접 쓸 수도 있지만, 잘 만들어진 걸 가져다 쓰는 게 더 빠를 때가 많습니다. 가장 유명한 건 Anthropic이 만든 '문서 스킬' 네 개예요. 파워포인트(pptx), 엑셀(xlsx), 워드(docx), PDF. claude.ai에서 "이 자료로 발표 슬라이드 만들어 줘"라고 하면 뒤에서 조용히 이 스킬들이 돌아가는데, 마크다운을 흉내 낸 가짜가 아니라 서식까지 갖춘 진짜 .pptx·.xlsx 파일을 뽑아 줍니다. 사실 Claude의 문서 생성 기능이 통째로 이 스킬들 위에서 돌아가고, 소스도 공개돼 있어서 '잘 만든 스킬은 어떻게 생겼나'의 교본으로 자주 인용됩니다.

그 밖에도 쓸 만한 게 많습니다. 새 스킬을 만들 때 형식을 잡아 주는 '스킬 만드는 스킬', 앞서 배운 MCP 서버를 설명만 주면 짜 주는 'MCP 빌더', 브랜드 가이드라인을 지키게 하는 스킬 같은 것들이죠. Anthropic 공식 저장소에 예시가 모여 있고, 커뮤니티가 올린 것도 수백 개입니다.

딱 하나 조심할 것. 스킬은 결국 'AI에게 주는 지시문 + 실행 코드'라, 출처가 불분명한 걸 함부로 켜면 위험합니다. 내가 만들었거나 공식 저장소에서 온 것 위주로 쓰고, 남의 스킬은 안에 뭐가 들었는지 한 번 열어 보고 쓰세요. (출처: [Anthropic, "Agent Skills" 공식 문서](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview); [anthropics/skills 저장소](https://github.com/anthropics/skills))

### 매번 설명하기 싫다면 - 규칙 파일(AGENTS.md·CLAUDE.md)

스킬과 비슷하지만 더 기본이 되는 게 있습니다. AI에게 **"우리 프로젝트는 이런 규칙이야"를 매번 설명하기 지겨울 때**, 그걸 파일 하나에 적어 두는 것입니다. 흔히 `AGENTS.md` 또는 `CLAUDE.md`라고 부르고, 공식 설명은 이걸 **"에이전트를 위한 README"** 라고 합니다. 많은 도구가 대화를 시작할 때 이 파일을 자동으로 먼저 읽으므로(단, **Claude Code는 CLAUDE.md만 자동으로 읽습니다**), 여기 적은 건 **매번 처음부터 아는 지식**이 됩니다. (출처: [agents.md 공식 스펙](https://agents.md/))

무엇을 적으면 유용할까요?

- **프로젝트 개요** - 이게 무슨 서비스인지 한두 줄
- **자주 쓰는 명령** - 실행·테스트 방법(설명보다 명령어를 먼저)
- **규칙·컨벤션** - 폴더 구조, 스타일 등
- **하지 말 것** - "이 폴더는 건드리지 마" 같은 금지사항

흐름 하나 - 예전엔 도구마다 파일 이름이 제각각이었는데, 2025년 여러 회사가 모여 **AGENTS.md라는 공통 표준**을 만들었습니다(수만 개 프로젝트가 채택). 스킬이 '반복 작업의 플레이북'이라면, 컨텍스트 파일은 **'프로젝트의 상시 안내문'** 입니다. 짧고 명령어 중심으로 쓰는 게 좋습니다.

### 헷갈리지 않기 - MCP vs 스킬 vs 규칙

셋이 비슷해 보이지만 역할이 다릅니다. 이 결정 규칙이면 충분합니다. (출처: [Totalum, "Claude Code Skills in 2026: The Complete Guide"](https://www.totalum.app/blog/claude-code-skills-totalum))

| 내가 원하는 것 | 무엇을 쓰나 |
| :--- | :--- |
| AI에게 **새 능력·연결**을 주고 싶다 (내 DB·도구에 붙이기) | **MCP** |
| AI가 **항상 이런 식으로** 행동하게 하고 싶다 | **규칙** (프로젝트 설정 파일: CLAUDE.md / AGENTS.md) |
| **반복하는 다단계 작업**을 자동화하고 싶다 | **스킬(Skill)** |

한 문장으로: **스킬은 선반에서 꺼내 쓰는 '방법서', 규칙은 프로젝트의 '상시 안내문', MCP는 도구를 꽂는 '어댑터'입니다.** 서로 경쟁이 아니라 함께 씁니다.

### 미니 퀴즈 - MCP? 스킬? 규칙?

아래 상황에 무엇이 맞을지 골라 보세요.

| 상황 | MCP / 스킬 / 규칙 |
| :--- | :--- |
| AI가 우리 회사 DB를 직접 조회하게 하고 싶다 | |
| "보고서는 항상 우리 양식으로"를 늘 지키게 하고 싶다 | |
| "경쟁사 조사 → 표로 정리"라는 다단계 작업을 매번 반복한다 | |

**정답 보기**

- DB에 연결(새 능력) → **MCP**
- 항상 이렇게(행동 규칙) → **규칙(CLAUDE.md / AGENTS.md)**
- 반복하는 다단계 작업 → **스킬(Skill)**

새 능력=MCP, 항상=규칙, 반복 작업=스킬. 이 세 갈래만 기억하면 됩니다.
