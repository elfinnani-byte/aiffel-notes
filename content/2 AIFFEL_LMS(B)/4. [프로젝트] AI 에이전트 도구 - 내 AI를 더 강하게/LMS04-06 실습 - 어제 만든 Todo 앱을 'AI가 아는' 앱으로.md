# [4.프로젝트 AI 에이전트 도구 - 내 AI를 더 강하게] - 6. 실습 - 어제 만든 Todo 앱을 'AI가 아는' 앱으로

## 실습 - 어제 만든 Todo 앱을 'AI가 아는' 앱으로

지난 시간에 우리는 에이전트에게 시켜 **Todo 앱**을 만들었습니다. 오늘 배운 것은 읽고 끝내면 남지 않으니, 그 Todo 앱을 재료로 범용 AI를 **'내 앱을 아는 전용 조수'** 로 바꾸는 걸 직접 해 봅시다.

방향은 이 강의가 앞서 짚은 흐름 그대로입니다 - **앱에 명령줄 도구(CLI)를 갖추고 그 사용법을 규칙 파일에 적어 두면**, AI가 그 명령을 직접 돌려 내 데이터를 읽고 다룹니다. 거기에 스킬로 반복 작업을 외워 두면 끝이죠.

**이 실습에서 하는 것**

- 앱에 **CLI**(`todo list`·`summary` 같은 명령)를 갖추고, `AGENTS.md`(규칙 파일)에 사용법을 적는다.
- AI에게 그 **CLI를 실제로 돌리게** 해 내 할 일 데이터를 읽는다(이때 **권한 승인**을 관찰하고, 위험 작업 전 **커밋**으로 되돌릴 지점을 만든다).
- `SKILL.md`를 하나 만들어, 매번 반복하던 정리 작업을 **한 번 적어 재사용**한다.
- (덤) 같은 걸 **MCP로 붙이면** 어떻게 다른지 짧게 체험한다.

준비물은 지난 시간에 **로컬에 만든** Todo 앱 폴더(데이터가 `todo.db` 같은 내 컴퓨터 파일에 저장되는 형태)와, 지금 쓰는 에이전트형 도구(Claude Code·Cursor 등) 하나면 됩니다. 클라우드 DB로 만들었다면 이 실습은 로컬 파일 기준으로 읽어 주세요.

### 1단계 - 앱에 '명령줄 사용법(CLI)'을 붙이기

지난 시간에 만든 Todo 앱은 아마 화면(웹)으로 쓰는 형태일 겁니다. 그런데 AI가 다루기 가장 편한 창구는 화면이 아니라 **명령줄(CLI)** 이에요. 화면은 사람이 클릭하라고 있는 거라 AI가 붙잡기 번거롭지만, 명령줄은 "명령어를 쳐서 결과를 글로 받는" 방식이라 AI가 그대로 실행하고 읽기 좋거든요.

다행히 앱을 새로 만들 필요는 없습니다. 할 일을 추가·조회·완료하는 **로직은 이미 앱 안에 들어 있으니**, 그걸 터미널에서 부를 수 있는 **작은 입구(진입점) 하나만** 더 얹으면 됩니다. 데이터도 앱이 쓰던 그 파일(`todo.db`)을 그대로 씁니다 - 새 데이터를 만드는 게 아니라, 같은 데이터를 여는 문을 하나 더 다는 셈이죠.

CLI를 한 줄로 정리하면, 프로그램에 "무엇을 할지"를 화면 클릭 대신 **명령어 + 값** 으로 전달하는 방식입니다. 예를 들어 `node todo.js add "우유 사기"`에서 `add`가 명령, `"우유 사기"`가 넘겨주는 값이에요.

그래서 AI에게 이렇게 부탁합니다 - "우리 Todo 앱의 **기존 로직을 재사용해서** 터미널에서 쓸 `todo` 명령을 만들어 줘. `add`(추가)·`list`(목록)·`done`(완료)·`summary`(오늘 완료 요약) 네 개면 돼. 데이터는 지금 쓰는 `todo.db`를 그대로 쓰고, 앱 코드를 갈아엎지 말고 얇은 진입점만 더해 줘." 그러면 이렇게 동작합니다(이하 편의상 `todo …`로 줄여 씁니다. AI가 실제로 만든 파일명은 `cli.js`처럼 다를 수 있으니, 나온 이름으로 바꿔 쓰면 됩니다).

```
$ node todo.js list
[x] 1. 발표 자료 초안 작성하기
[ ] 4. 헬스장 PT 예약 변경 문의하기
```

(앱이 파이썬이면 `python todo.py list`처럼, 쓰는 언어에 맞는 진입점이 생깁니다. 형태만 다를 뿐 원리는 같아요.) 한 가지 - `summary`가 '오늘 완료'를 세려면 완료한 **시각**이 데이터에 있어야 합니다. 지난 시간 앱에 완료 날짜가 없으면, AI에게 "완료 시각도 기록하게 해 줘"를 함께 부탁하세요.

이제 이 사용법을 앱 폴더 **맨 위(루트)** 의 규칙 파일에 5~10줄로 적어 둡니다. 파일 이름은 도구를 탑니다 - **Cursor** 등은 `AGENTS.md`를 그대로 읽고, **Claude Code**는 `CLAUDE.md`만 자동으로 읽습니다(그래서 `CLAUDE.md`로 만들거나 `CLAUDE.md` 첫 줄에 `@AGENTS.md`를 적어 불러오면 됩니다).

```
# Todo 앱

## 개요
할 일을 추가·완료·조회하는 1인용 앱.

## 명령
- 목록: node todo.js list
- 추가: node todo.js add "<내용>"
- 완료: node todo.js done <번호>
- 오늘 완료 요약: node todo.js summary

## 규칙
- 데이터는 todo.db에 저장한다. UI 문구는 존댓말로.

## 하지 말 것
- todo.db(실데이터)를 직접 지우거나 덮어쓰지 말 것.
```

다 적었으면 **새 대화를 열고** "이 프로젝트 어떻게 실행해?"라고 물어보세요. AI가 방금 적은 명령을 **먼저 읽고 답하면** 성공입니다. 대화를 리셋해도 이 파일은 자동으로 읽히니, 같은 설명을 두 번 안 해도 됩니다.

### 2단계 - AI에게 그 CLI를 실제로 돌리게 하기

이제 진짜 재미있는 부분입니다. AI에게 이렇게 시켜 보세요 - **"오늘 할 일 목록 좀 보여 줘."** 규칙 파일을 읽은 AI는 스스로 `node todo.js list`를 **실행**해서 그 출력을 가져옵니다. 복사·붙여넣기 없이, AI가 내 앱을 직접 돌려 **실제 할 일 데이터**를 읽는 거죠. 소스 코드가 아니라 실제 할 일 데이터를 보는 것이 핵심입니다.

**여기서 권한을 관찰하세요.** 명령을 실행하기 직전, 도구가 **"이 명령을 실행해도 될까요?"** 를 물어볼 겁니다. `list`·`summary`처럼 읽기만 하는 건 승인하세요. 그리고 한 번은 **일부러** 위험한 걸 시켜 보세요 - "todo.db 파일을 지워 줘." 승인창이 뜨면 **거부**하고, 규칙 파일의 '하지 말 것'과 연결해 '내가 문지기'라는 감을 익히세요. 그리고 뭔가 시키기 전에 `git commit`으로 되돌릴 지점을 먼저 만들어 두면, 잘못돼도 그 지점으로 되돌아갈 수 있습니다(앞 시간의 Git).

왜 CLI로 할까요? 앞서 본 '요즘 흐름' 그대로입니다 - AI는 `node`·`git` 같은 명령을 이미 알고 있어서, 무거운 연결을 새로 세우지 않고 **있는 명령을 그냥 부르는** 게 가볍고 빠릅니다.

### 3단계 - 반복 작업을 스킬로 외워 두기

이 단계는 Claude Code 기준입니다. Cursor 등 다른 도구는 스킬 위치가 다르니 개념만 봐도 됩니다.

매번 똑같이 시키는 일이 있죠 - "오늘 완료한 것만 뽑아 커밋 메시지 형식으로 정리해 줘" 같은. 이걸 스킬로 만들어 둡니다. 앱 폴더의 `.claude/skills/todo-summary/SKILL.md`에 이렇게 적으면 됩니다(Claude Code는 이 경로의 스킬을 자동으로 찾습니다).

```
---
name: todo-summary
description: 오늘 완료한 할 일을 커밋 메시지 형식으로 요약할 때 사용
---

# 오늘 완료 요약

`node todo.js summary`를 실행하고, 그 출력을 그대로 보여준다.
```

핵심은 스킬이 직접 데이터를 뒤지는 게 아니라, **앞서 만든 CLI를 대신 불러 준다** 는 것입니다. 그다음 **다른 대화에서** "요약 스킬 써서 오늘 한 일 정리해 줘"라고만 하면, AI가 이 스킬을 알아서 꺼내 `todo summary`를 돌리고 결과를 정리합니다 - 앞서 배운 **점진 공개** 가 실제로 동작하는 순간이죠. (스킬 폴더를 처음 만들었다면 도구를 한 번 재시작해야 인식됩니다.)

### 덤(시간 남으면) - 같은 걸 MCP로 붙이면?

CLI 대신 MCP로도 붙일 수 있습니다. 파일시스템 MCP 서버를 하나 등록하면 AI가 앱 폴더를 읽죠 - 설정은 대개 이렇게 생겼습니다.

```json
{
  "mcpServers": {
    "todo-files": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/내-Todo앱-경로"]
    }
  }
}
```

붙여 두면 "우리 앱 소스에서 할 일을 어떻게 저장하는지 설명해 줘" 같은 걸 시켜 볼 수 있습니다. 다만 직접 해 보면 차이가 느껴질 거예요. 이 서버는 **파일(소스)** 을 읽는 데는 좋지만, 데이터가 담긴 `todo.db`는 이진 파일이라 **내용까지 세어 주진 못합니다.** 방금 CLI로 한 "오늘 완료 몇 건" 같은 건 결국 앱의 명령(`todo summary`)을 돌려야 나오죠.

그래서 오늘 배운 판단이 여기서 그대로 쓰입니다 - **혼자 작은 앱이면 CLI + 스킬이 가볍고, 여럿이 쓰고 권한·기록을 챙겨야 하면 MCP.** 도구가 아니라 상황이 고릅니다.

규칙 파일로 CLI 사용법을 알려 주면 AI가 `todo list`를 직접 돌리고, 스킬이 그 CLI(`todo summary`)를 대신 불러 실제 내 데이터를 정리해 줍니다.

### 정리 - 오늘의 결과물

아래를 갖추면 이 실습은 끝입니다.

- 앱에 CLI(`list`·`summary` 등) + 규칙 파일(`AGENTS.md`, Claude Code면 `CLAUDE.md`)에 사용법
- AI가 그 CLI를 직접 실행해 내 할 일 데이터를 읽음(권한 승인창을 한 번은 거부, 위험 작업 전 `git commit`)
- `SKILL.md` 1개(Claude Code 기준) - 다른 대화에서 한마디로 발동, 스킬이 CLI를 대신 호출
- (덤) 같은 걸 MCP로도 붙여 보고 CLI와 비교

마지막 확인 - **범용 AI가 내 Todo 앱을 아는 조수로 바뀐 지점은 어디였나요?** (규칙 파일? CLI 실행? 스킬?) 그 감각이 오늘의 핵심입니다.
