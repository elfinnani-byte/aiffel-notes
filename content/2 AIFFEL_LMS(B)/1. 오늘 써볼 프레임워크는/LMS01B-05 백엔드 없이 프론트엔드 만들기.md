# [1.오늘 써볼 프레임워크는?] - 5. 백엔드 없이 프론트엔드 만들기

---

## 주방이 아직 안 열렸어도 홀부터 영업한다 - 백엔드 없이 프론트엔드 만들기

![[food-stall-market-vietnam.jpg]]
*출처: Wikimedia Commons, "Food stall in the Bắc Hà Sunday market, Vietnam." 노점은 본점 주방이 완성되기를 기다리지 않는다 — 재료와 손맛만 있으면 손님에게 음식을 낼 수 있다. 프론트엔드도 마찬가지다: 백엔드가 완성되기를 기다릴 필요 없이, 가짜 데이터로 먼저 화면을 돌려볼 수 있다.*

지금까지 우리는 프레임워크가 무엇인지, 어떻게 고르는지를 배웠습니다. 하지만 프레임워크를 고르고 나면 곧바로 한 가지 현실과 부딪힙니다.

> "화면은 만들고 싶은데, 데이터를 어디서 가져오죠? 백엔드 API가 아직 없는데요."

이 질문에 대한 답이 이 섹션의 주제입니다. **백엔드 없이도 프론트엔드를 만들고, 실제로 쓰는 것처럼 테스트하는 방법** — 이것은 실무 개발자가 매일 쓰는 기술이자, AI 코딩에서 가장 빠르게 프로토타입을 만드는 열쇠입니다.

### 프론트엔드와 백엔드 - 식당의 '홀'과 '주방'

먼저 프론트엔드와 백엔드가 어떤 관계인지, 식당 비유로 정리하겠습니다. 지난 시간에 잠깐 소개했지만, 이번에는 두 쪽이 **어떻게 데이터를 주고받는지**까지 봅니다.

| 식당 | 웹서비스 | 하는 일 |
| :--- | :--- | :--- |
| 홀(hall) | **프론트엔드** | 손님이 직접 보고 만지는 공간입니다. 메뉴판을 보고, 주문하고, 음식을 받습니다 |
| 주방(kitchen) | **백엔드** | 손님이 보지 못하는 곳에서 재료를 저장하고, 요리하고, 완성된 음식을 냅니다 |
| 서빙 창구 | **API** | 홀과 주방 사이의 연결점입니다. 주문을 전달하고, 완성된 음식을 내보냅니다 |
| 주문서 양식 | **JSON** | 주문과 서빙에 쓰는 공통 형식입니다. "번호: 3, 메뉴: 불고기, 수량: 2"처럼 정해진 규격으로 씁니다 |

**홀에서 주방에 주문을 넣는 방법 - HTTP 요청**

프론트엔드가 백엔드에 데이터를 요청할 때는 **HTTP 요청**이라는 방식을 씁니다. 브라우저가 백엔드 서버에 "이 데이터 주세요"라고 물어보고, 서버가 JSON 형식으로 답합니다.

```js
// 프론트엔드가 백엔드에 "전문가 목록을 주세요"라고 요청하는 코드
const response = await fetch('https://내서비스.com/api/experts');
const experts = await response.json();
// experts = [{ name: '김민준', specialty: '형사' }, { name: '이서연', ... }]
```

이 한 줄이 실행되면 브라우저는 백엔드 서버에 요청을 보내고, 서버가 보낸 JSON을 JavaScript 객체로 바꿔 줍니다. 그 객체를 컴포넌트에 넘겨 화면을 그립니다.

**문제는**: 이 코드가 작동하려면 `https://내서비스.com/api/experts`에 응답하는 백엔드가 **이미 있어야** 합니다. 백엔드가 없으면 `fetch`는 실패하고, 화면은 비어 있습니다.

> 💡 **그래서 질문이 됩니다** — "백엔드가 없으면 프론트엔드를 아예 못 만드는 건가?" **아닙니다.** 가짜 데이터를 쓰면 됩니다. 이것을 **목업 데이터(mock data)** 라고 부릅니다.

### API가 하는 일 - 자동 교환수

![[telephone-switchboard-operators-1922.jpg]]
*출처: Wikimedia Commons, "Telephone switchboard operators, ca 1922 (MOHAI 5108)." 1920년대 전화 교환수 — 발신자와 수신자 사이에서 수동으로 선을 꽂아 연결했다. 오늘날 API는 이 교환수의 역할을 자동으로 한다 — 프론트엔드의 요청을 백엔드의 올바른 처리기로 연결해 준다.*

**API(Application Programming Interface)**는 프로그램끼리 대화하는 창구입니다. 식당 비유에서는 "서빙 창구"에 해당합니다. 손님이(프론트엔드가) 창구에 "전문가 목록 주세요"라고 말하면, 창구 뒤의 주방(백엔드)이 데이터를 꺼내 건네줍니다.

API에서 중요한 것은 **약속된 형식**입니다. 식당의 주문서에 "번호, 메뉴, 수량" 칸이 정해져 있듯이, API에도 요청과 응답의 형식이 정해져 있습니다. 이 형식이 맞아야 양쪽이 대화가 됩니다. 웹에서 가장 널리 쓰이는 형식이 **JSON(JavaScript Object Notation)** 입니다.

```json
// 백엔드가 보내주는 JSON 응답의 예
{
  "experts": [
    { "id": 1, "name": "김민준", "specialty": "형사", "years": 15 },
    { "id": 2, "name": "이서연", "specialty": "민사", "years": 12 }
  ],
  "total": 2
}
```

이 JSON을 받은 프론트엔드는 `experts` 배열을 순회하며 컴포넌트를 그립니다. 핵심은: **화면이 데이터 구조를 알고 있으면, 데이터가 진짜든 가짜든 똑같이 그려진다**는 것입니다. 이것이 목업 데이터가 작동하는 이유입니다.

### 목업 데이터(Mock Data) - 가짜지만 진짜처럼 쓰는 데이터

목업 데이터는 **진짜 API가 보내줄 것과 같은 구조의 가짜 데이터**를 코드 안에 직접 적어두는 것입니다. 백엔드가 없어도, 화면이 진짜 데이터가 있는 것처럼 동작합니다.

**왜 이것이 유용한가 - 실무에서 매일 쓰는 이유**

- **백엔드를 기다리지 않습니다**: 백엔드 개발이 완료되기를 기다릴 필요 없이 프론트엔드를 먼저 만듭니다. 실무에서는 이것을 **병렬 개발**이라고 부르며, 프론트엔드 팀과 백엔드 팀이 동시에 일하는 것이 기본입니다.
- **디자인과 인터랙션을 먼저 검증합니다**: 데이터가 어떻게 들어올지 알면, 화면 배치와 상호작용을 백엔드 없이도 테스트할 수 있습니다.
- **AI 코딩에서 특히 강력합니다**: AI에게 "이 데이터로 화면을 만들어줘"라고 하면, 백엔드 연결 없이도 완성된 화면을 즉시 볼 수 있습니다.
- **나중에 진짜 API로 쉽게 바꿉니다**: 목업 데이터의 구조를 진짜 API 응답과 맞춰두면, 한 줄만 바꿔서 교체할 수 있습니다.

**코드로 보기 - 목업 데이터로 전문가 목록 만들기**

```js
// mockData.js — 가짜 데이터를 진짜 API 응답과 같은 구조로 만듭니다

// ★ 핵심: 이 구조를 진짜 API 응답과 똑같이 맞춰둡니다
const mockExperts = [
  { id: 1, name: '김민준 변호사', specialty: '형사전문', years: 15,
    bio: '서울중앙지검 특수부 출신. 경제사범 사건 주요 실적.' },
  { id: 2, name: '이서연 변호사', specialty: '민사전문', years: 12,
    bio: '대형 로펌 파트너. 부동산 분쟁 주요 실적.' },
  { id: 3, name: '박정훈 변호사', specialty: '가사전문', years: 8,
    bio: '가족법 전문. 상속 및 이혼 분쟁 다수 해결.' },
  { id: 4, name: '최유진 변호사', specialty: '행정전문', years: 10,
    bio: '전 공무원 출신. 행정소송 및 인허가 분야.' },
  { id: 5, name: '정태영 변호사', specialty: '지재권전문', years: 14,
    bio: '특허법인 출신. 기술 거래 및 IP 자문.' },
];

export default mockExperts;
```

이 데이터를 컴포넌트에서 쓰면, 화면은 진짜 API에서 온 데이터처럼 보입니다.

```jsx
// ExpertList.jsx — 목업 데이터를 화면에 그립니다
import mockExperts from './mockData';

function ExpertList() {
  // ★ 지금은 가짜 데이터를 직접 씁니다
  const experts = mockExperts;

  // 나중에 백엔드가 생기면 이 한 줄만 바꿉니다:
  // const [experts, setExperts] = useState([]);
  // useEffect(() => {
  //   fetch('/api/experts').then(r => r.json()).then(setExperts);
  // }, []);

  return (
    <div className="expert-grid">
      {experts.map(expert => (
        <ExpertCard key={expert.id} {...expert} />
      ))}
    </div>
  );
}
```

지금 주석 처리된 `fetch` 부분을 보세요. 백엔드가 생기면, `mockExperts`를 가져오는 한 줄을 `fetch('/api/experts')`로 바꾸기만 하면 됩니다. **나머지 화면 코드는 하나도 안 바꿉니다.** 컴포넌트는 `experts` 배열의 구조만 알고, 그 데이터가 어디서 왔는지는 신경 쓰지 않기 때문입니다.

### 가짜 데이터는 AI에게 부탁하면 됩니다

목업 데이터를 손으로 하나하나 적을 필요는 없습니다. AI에게 **"내 화면에 쓸 그럴듯한 가짜 데이터를 만들어 줘"**라고 평소 말하듯 부탁하면 됩니다. 여러분이 알려줄 것은 딱 두 가지뿐입니다.

- **어떤 화면인지** — 예: "쇼핑몰 상품 목록", "맛집 추천 목록"
- **무엇을 보여줄지** — 예: 상품이라면 이름, 가격, 사진 설명, 품절 여부

여기에 "실제 인물이나 기관 이름은 빼고 가상의 값으로 채워 줘"만 덧붙이면, 화면 테스트에 딱 좋은 "진짜 같은 가짜"가 몇 초 만에 나옵니다.

**데이터는 보통 'JSON'으로 옵니다 - 알아보는 정도면 충분**

AI가 돌려주는 데이터는 대개 JSON이라는 형식입니다. 겁먹을 것 없습니다. **이름표와 값을 짝지어 적어 둔, 사람도 눈으로 읽을 수 있는 목록**일 뿐입니다.

```json
{ "이름": "딸기 생크림 케이크", "가격": 32000, "품절": false }
```

"이름: 딸기 생크림 케이크", "가격: 32000"처럼 **이름표와 값이 짝지어 묶여 있는 것**, 이게 JSON입니다. 따옴표를 어디 붙이는지 같은 세세한 규칙은 AI가 알아서 지키니 외울 필요 없습니다. **"데이터는 이런 이름표-값 묶음으로 오는구나" 정도만 알아보면 충분합니다.**

> 💡 **한 가지 요령** — 평범한 데이터만 말고 **극단적인 경우도 섞어 달라**고 해보세요. "목록이 텅 비었을 때", "이름이 유난히 길 때"처럼요. 그래야 그런 상황에서도 화면이 깨지지 않는지 미리 확인할 수 있습니다.

### 목업에서 진짜로 - 언제, 어떻게 바꾸나

목업 데이터로 화면을 다 만들었다면, 다음 질문은 "언제 진짜 API로 바꾸나?"입니다. 답은: **백엔드 API가 준비되었을 때, 한 곳만 바꿉니다.**

**교체가 쉬운 구조 vs 어려운 구조**

**❌ 교체가 어려운 구조** — 컴포넌트 안에 데이터를 직접 박아넣었을 때:

```jsx
// 나쁜 예: 데이터가 컴포넌트 안에 섞여 있음
function ExpertList() {
  const experts = [
    { id: 1, name: '김민준', specialty: '형사' },
    { id: 2, name: '이서연', specialty: '민사' },
  ];
  // ... 화면 코드
}
```

이 구조에서는 백엔드로 바꿀 때 컴포넌트를 열어서 데이터 부분을 찾아 고쳐야 합니다. 컴포넌트가 열 개면 열 곳을 뒤져야 합니다.

**✅ 교체가 쉬운 구조** — 데이터를 별도 파일로 빼두었을 때:

```jsx
// 좋은 예: 데이터를 별도 파일(mockData.js)에서 가져옴
import mockExperts from './mockData'; // ← 이 한 줄만 바꾸면 끝

function ExpertList() {
  const experts = mockExperts; // → const experts = useFetch('/api/experts')
  // ... 화면 코드는 그대로
}
```

데이터가 별도 파일에 있으면, 백엔드가 생겼을 때 `import` 한 줄을 API 호출로 바꾸기만 하면 됩니다. 화면 코드는 손대지 않습니다. 이것이 **관심사의 분리(separation of concerns)** — 지난 시간에 배운 원칙의 실전 적용입니다.

**AI에게 교체를 요청하는 프롬프트**

```
지금 mockData.js에서 데이터를 가져오는 부분을
진짜 API 호출로 바꿔줘.

API 엔드포인트: /api/experts
응답 형식: { experts: [{ id, name, specialty, years, bio }], total: number }

로딩 중일 때는 "불러오는 중..."을 보여주고,
실패했을 때는 "데이터를 불러오지 못했습니다. 다시 시도해 주세요."를 보여줘.
```

이 프롬프트 하나로 AI는 `import mockExperts`를 `fetch` 호출로 바꾸고, 로딩 상태와 에러 처리까지 추가해 줍니다. 목업으로 만든 화면 구조는 그대로 살아 있습니다.

> 🧪 **실습 제안** — 오늘 만든 목업 데이터 화면을 나중에 백엔드가 준비되면 연결할 때, 이 교체 과정을 직접 해보게 됩니다. "한 줄을 바꿨더니 진짜 데이터가 들어왔다"는 경험이 여러분의 첫 백엔드 연결이 될 것입니다.
