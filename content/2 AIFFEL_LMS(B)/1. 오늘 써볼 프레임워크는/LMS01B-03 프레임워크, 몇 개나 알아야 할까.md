# [1.오늘 써볼 프레임워크는?] - 3. 프레임워크, 몇 개나 알아야 할까

---

## "다 알아야 하나요?" - 아니요, 대신 판단할 수 있어야 합니다

![[swiss-army-knife-open.jpg]]
*출처: Wikimedia Commons, "Swiss army knife open." 스위스 아미 나이프 하나가 모든 상황에 완벽하지 않듯, 프레임워크도 각자 겨냥하는 문제가 다르다. 이름 하나가 아니라 자료·도구·배포·커뮤니티까지 포함해 선택한다.*

프레임워크가 다양하다는 것은, "최고"가 하나가 아니라 "조건에 맞는 최선"이 여럿이라는 뜻입니다. 먼저 객관적인 사용 데이터를 살펴보겠습니다.

[Stack Overflow Developer Survey 2025](https://survey.stackoverflow.co/2025/technology)의 "Web frameworks and technologies" 문항에서 React와 Next.js는 널리 사용·관심을 받는 후보로 나타납니다. 이 문항은 지난 1년간의 광범위한 개발 경험과 다음 1년의 사용 희망을 묻고, 응답 집단별 결과를 나누어 보여 줍니다. 같은 조사 안에서도 만족도와 사용률은 다르게 움직입니다. 즉, "많이 쓴다"와 "내 프로젝트에 맞다"는 같은 말이 아닙니다.

공식 문서를 기준으로 이름을 분류해 보겠습니다. 오늘은 문법을 배우지 않기 때문에, 이름과 역할만 잡습니다.

| 범주 | 예시 | 큰 그림 |
| :--- | :--- | :--- |
| UI 라이브러리·프레임워크 | React, Vue, Svelte, Angular, Solid, Qwik | 화면 조각, 상태, 렌더링 규칙을 다룹니다 |
| 메타프레임워크 | Next.js, Nuxt, SvelteKit | 라우팅, 서버 렌더링, 빌드, 배포 흐름까지 묶습니다 |
| 주변 생태계 | 라우터, 상태관리, UI 컴포넌트, 테스트 도구 | 실제 프로젝트에서 함께 선택됩니다 |

한 줄로 구분하면 **React(UI 라이브러리) → Next.js(React 기반 애플리케이션/메타프레임워크)** 이고, **Vite는 이들과 같은 종류의 대안이 아니라 개발·빌드 도구** 입니다. React만 쓸 때는 라우팅·데이터 처리·배포 방식을 더 직접 조합하고, Next.js는 그 선택 일부를 기본 흐름으로 묶어 줍니다.

각 도구의 공식 문서가 스스로를 어떻게 설명하는지 한 번 더 보겠습니다. 이 차이가 곧 "무엇을 다르게 풀고 싶은가"를 보여 줍니다.

- **React** — "UI를 렌더링하는 JavaScript 라이브러리." 화면을 컴포넌트로 나누는 사고를 널리 퍼뜨렸습니다.
- **Vue** — "UI를 만들기 위한 JavaScript 프레임워크." 점진적으로 도입할 수 있는 구조를 앞세웁니다.
- **Angular** — Google이 유지하는 웹 프레임워크로, 라우팅·폼·업데이트 도구 묶음이 강합니다. 큰 조직에서 장기 운영하는 서비스에 자주 쓰입니다.
- **Svelte** — 컴파일러를 활용해 브라우저에서 해야 할 일을 줄이는 방향을 내세웁니다.
- **Solid** — 반응형 UI의 성능을 극한까지 밉니다.
- **Qwik** — 서버 렌더링 상태를 브라우저에서 이어받는 resumability를 강조합니다.

이름마다 문제를 푸는 관점이 다릅니다. "어떤 문제를 푸는가"를 보면, 왜 하나만 정답이 아닌지가 보입니다.

### 문법은 AI가 짠다 - 그래서 '무엇을 고르냐'가 더 중요해졌다

먼저 안심하세요. React든 Vue든 Svelte든, **코드 문법은 여러분이 외울 필요가 없습니다.** "상품 목록 컴포넌트 만들어 줘"라고 하면 AI가 그 프레임워크 문법으로 정확히 써 줍니다. 프레임워크마다 생김새는 달라도, 화면을 조각(컴포넌트)으로 나누고 데이터(상태)로 갱신한다는 뼈대는 다 같습니다.

그런데 "AI가 다 짜주니 아무거나 골라도 되겠네?"는 오해입니다. 오히려 선택이 더 중요해졌습니다 — AI가 프레임워크마다 코드를 짜는 **정확도가 실제로 다르기** 때문입니다.

**근거 ① — AI는 자료 많은 프레임워크를 더 정확히 짠다**

프런트엔드 코드 생성을 평가한 학술 벤치마크 [[designbench-arxiv2506.06251.pdf|DesignBench, arXiv:2506.06251]]에서, 최신 AI 모델들은 React·Vue로는 컴파일 성공률이 0.83을 넘겼지만 Angular는 0.69~0.76으로 눈에 띄게 낮았습니다. AI 코딩 벤치마크들이 기준 프레임워크로 React를 자주 고르는 이유도 "학습 데이터에 가장 많이 담겨 있어서"입니다. 즉, **공개 자료가 많은 프레임워크일수록 AI의 첫 코드가 정확합니다.**

**근거 ② — 규칙이 일관된 프레임워크일수록 AI가 일관되게 짠다**

"이건 이렇게 하는 게 정석"이라는 규칙이 강한 프레임워크는 AI가 매번 비슷한 구조로 코드를 냅니다. 반대로 자유도가 아주 높은 도구는 부를 때마다 구조가 달라져, 여러분이 검토하고 고칠 게 많아집니다.

**그럼 뭘 고르나 - "가장 많이 쓴다 ≠ 가장 좋다"**

**가장 많이 쓰는 건 React입니다.** Stack Overflow 2025 개발자 설문(4.9만 명)에서 프런트엔드 사용률은 React 44.7%로 1위(2위 Angular 18.2%, Vue 17.6%), 메타프레임워크 Next.js는 21.5%였습니다. 사용자가 많다는 것은 자료·예제·AI 학습 데이터가 가장 많다는 뜻이기도 합니다.

**하지만 "인기 = 정답"은 아닙니다.** 정작 개발자 만족도는 Svelte가 가장 높고(약 74%), React 만족도는 62%로 내려가는 중입니다(출처: State of JS 2024). 어제 배운 그대로입니다 — 많이 쓰는 것과 내 조건에 맞는 것은 다릅니다.

정리하면, 문법은 안 외워도 됩니다. 대신 이렇게 판단하세요 — **자료와 AI 지원을 최우선으로 친다면 React 계열이 무난한 출발점**이고, 코드 간결함이나 개발 경험을 중시한다면 Svelte 같은 선택도 충분히 합리적입니다. 정답 하나는 없고, 아래 판단 축으로 내 조건에 맞춰 고르면 됩니다.

> 🔬 **직접 확인하는 법** — 후보가 정해졌다면 AI에게 같은 요청("상품 목록 화면 만들어 줘")을 세 번 시켜 보세요. 세 번 다 구조가 비슷하면 그 프레임워크는 AI와 궁합이 좋은 것이고, 매번 딴판이면 나중에 고치기 어려워집니다.

### "다 알아야 하나"에 대한 정직한 답

다 알 필요는 없습니다. 특히 비전공자가 처음 웹서비스를 만들 때 목표는 "프레임워크 전문가"가 되는 것이 아니라 **내 서비스가 어떤 조건을 갖고 있는지 설명하고, 추천의 근거를 검토하는 사람**이 되는 것입니다.

| 판단 축 | 질문 | 왜 중요한가요 |
| :--- | :--- | :--- |
| AI 친화도 | AI가 이 프레임워크로 정확한 코드를 잘 짜나요? (학습 데이터가 많고 규칙이 일관적인가) | 2026년엔 첫 코드 품질과 리뷰 부담을 가장 크게 좌우합니다 |
| 러닝커브 | 지금 팀이 HTML/CSS/JS 다음으로 받아들일 수 있는가요? | 빠른 시작과 장기 이해 사이의 균형입니다 |
| 생태계 | 필요한 인증, 차트, 폼, UI, 배포 예제가 충분한가요? | AI가 만든 코드도 자료가 많을수록 검토하기 수월합니다 |
| 일자리·자료 | 채용 공고, 한국어/영어 자료, 커뮤니티가 있는가요? | 혼자 막혔을 때 회복 속도와 관련됩니다 |
| 장기 유지보수 | 업데이트 정책, 보안 패치, 팀 확장에 맞는가요? | 서비스는 만든 뒤에도 계속 바뀝니다 |
| 트레이드오프 | 얻는 것 대신 잃는 것은 무엇인가요? | 성능, 복잡도, 배포 방식, 자유도는 서로 영향을 줍니다 |

정답 하나를 찾으려 하면 금방 지칩니다. 후보를 2~3개로 좁히고, 근거를 비교하는 방식이 현실적입니다.

### Next.js를 후보에 넣을 때 한 번 더 볼 것

Next.js는 React에 라우팅·서버 렌더링·배포까지 묶은 메타프레임워크입니다. 로그인·데이터·검색 노출이 중요한 서비스에는 강점이지만, 단순한 소개 페이지에는 과할 수 있습니다. App Router, 서버/클라이언트 컴포넌트 같은 세부 개념은 실제로 만들 때 [공식 문서](https://nextjs.org/docs/app)를 보며 익히면 됩니다.

### 자문

여러분의 프로젝트에서 위 다섯 축 중 가장 중요한 축 두 개를 고르세요.

| 내 프로젝트 | 1순위 판단 축 | 2순위 판단 축 | 이유 |
| :--- | :--- | :--- | :--- |
| | | | |

예를 들어 실무 부서에서 오래 쓸 내부 도구라면 장기 유지보수와 생태계가 앞설 수 있습니다. 2주 안에 데모를 보여줘야 한다면 러닝커브와 배포 자료가 앞설 수 있습니다.
