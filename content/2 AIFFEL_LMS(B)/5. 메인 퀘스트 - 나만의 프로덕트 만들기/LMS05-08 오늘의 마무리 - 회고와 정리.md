## 오늘의 마무리 - 회고와 정리

### 오늘의 회고

- 오늘 "자르기"가 가장 아까웠던 기능은? 그래도 자른 이유는?
- 막혔을 때 나를 가장 도와준 규율(한 번에 하나 / 작동하면 저장 / 막히면 리셋 / 이해한 것만 배포)은?
- 완성까지, 지금 가장 겁나는 부분은 무엇인가?

### 출처 - 더 찾아보기

- MVP 범위 정하기: [Softvery Solutions, "How to Scope MVPs Right."](https://www.softverysolutions.com/post/how-to-do-the-right-mvp-scope-so-it-doesn-t-fall-apart-after-launch)
- 스코프 크립 피하기: [Topflight Apps, "How to Avoid Scope Creep and Build MVP App."](https://topflightapps.com/ideas/avoid-scope-creep/)
- 바이브 코딩 워크플로: [vibecoding.app, "How Vibe Coding Works: AI-First Development Workflow (2026)."](https://vibecoding.app/blog/how-vibe-coding-works)
- AI 코딩과 구조의 중요성(Andrew Ng): [Google Cloud, "What is vibe coding?"](https://cloud.google.com/discover/what-is-vibe-coding)
- 첫 버전 범위 잡기: [thinslices, "Build the right first version by mastering MVP scoping."](https://www.thinslices.com/insights/build-the-right-first-version-by-mastering-mvp-scoping)
- 첫 버전 인용의 맥락: "If you're not embarrassed by the first version of your product, you've launched too late."는 Reid Hoffman에게 널리 귀속되는 발언입니다.
- AI 코드 보안 수치: [Veracode, 2025 GenAI Code Security Report](https://www.veracode.com/resources/analyst-reports/2025-genai-code-security-report/) - 조사 대상 AI 생성 코드에서 보안 결함이 발견된 비율 45%; 표본·스캔 기준의 결과입니다.
- MVP 학습 관점: Eric Ries, 《The Lean Startup》, 2011.

### 핵심 정리

| 오늘 배운 것 | 한 문장 정리 | 내가 할 수 있는 행동 |
| :--- | :--- | :--- |
| 메인퀘스트 방향 | 제출물·루브릭을 착수 때 본다 | 한 문장 정의·프롬프트·대화를 남겨 둔다 |
| 배운 조각의 연결 | PRD·화면·저장·도구가 네 단계로 꿴다 | 한 문장 정의에서 출발해 순서대로 잇는다 |
| 모범 사례 따라하기 | 완전히 풀린 보기를 먼저 한 바퀴 돌린다 | 절차를 익히고 나서 내 도메인으로 옮긴다 |
| 범위 좁히기 | MVP는 작지만 하나는 끝까지 되는 것 | Must 3개·Won't 5개로 범위를 못 박는다 |
| 다섯 단계 | PRD→작업대→화면→저장→배포로 나아간다 | 한 단계씩, 멈춰도 되는 지점을 안다 |
| 막혔을 때 규율 | 한 번에 하나·작동 시 저장·막히면 리셋·이해한 것만 배포 | 랜덤 수정 대신 요약으로 AI 초점을 맞춘다 |
