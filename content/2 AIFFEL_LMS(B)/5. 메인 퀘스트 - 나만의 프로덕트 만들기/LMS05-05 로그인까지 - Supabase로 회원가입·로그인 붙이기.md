## 로그인까지 - Supabase로 회원가입·로그인 붙이기

1단계 PRD에서 '이번엔 이름만, 로그인은 다음 단계'로 정해 뒀죠. 이제 계획해 둔 그 다음 탈것을 올릴 차례입니다 - 스케이트보드(이름만) 다음의 자전거처럼요. '누구나 이름만 넣고 신청'에서 '로그인한 사람이 신청하고 자기 내역만 보는' 서비스로 넓힙니다. 이걸 밑바닥부터 만들면 지난 시간에 배운 비밀번호 저장·세션·보안을 다 신경 써야 해서 무겁습니다. 그래서 요즘은 **Supabase 같은 백엔드 서비스(BaaS)** 에 맡깁니다 - 무료로 시작하는 백엔드에 DB·회원가입·로그인·권한이 딸려 오고, 우리가 짠 서버 로직을 돌리는 기능(Edge Functions, DB 함수)까지 있습니다.

지난 시간에 "로그인은 직접 만들지 말고 검증된 서비스에 맡기라"고 했죠. Supabase가 그 자리를 채웁니다. 비밀번호 해시·세션·토큰은 Supabase가 알아서 하고, 우리는 **'무엇을'** 만 정합니다.

이번 확장은 선택입니다. 오늘의 MVP(정원 신청)가 이미 굴러가면 그대로도 충분하고, 로그인은 1단계에서 계획해 둔 다음 단계로 올릴 때 옵니다.

### 붙이는 순서 - 프로젝트 만들고, 인증 켜고, 신청을 '내 것'으로

**1. Supabase 무료 프로젝트 만들기.** supabase.com에서 무료 프로젝트를 하나 만들면 DB와 인증이 함께 생깁니다. 설정 화면에서 **Project URL**과 **공개 키(publishable/anon key)** 를 받아 `.env`에 넣습니다(코드에 박지 말 것 - 지난 시간의 비밀값 규칙).

Claude Code를 쓴다면, 공식 **Supabase 플러그인(MCP)** 을 붙이면 AI가 내 Supabase에 직접 접속해 표·인증·정책까지 만들어 줍니다(지난 시간에 배운 MCP·플러그인이 여기서 쓰입니다). `/plugin marketplace add anthropics/claude-plugins-official` 로 등록해 supabase 플러그인을 켜거나, 뒤의 실전 기록처럼 `claude mcp add` 로 붙입니다 - 둘 중 하나면 됩니다. 접속 정보를 넣어 주면 됩니다.

**명령(의도만)**: "우리 앱에 Supabase를 붙여 줘. Project URL과 공개 키는 내가 .env에 넣을게. 연결만 잡아 줘."

**2. 회원가입·로그인 붙이기.** Supabase가 이메일·비밀번호 회원가입과 로그인을 기본 제공합니다. 화면과 연결만 하면 됩니다.

**명령(의도만)**: "이메일·비밀번호로 회원가입하고 로그인하는 화면을 Supabase 인증으로 붙여 줘. 로그인하면 신청 화면이 보이고 로그아웃 버튼도 있게."

**3. 신청을 '로그인한 사람'과 잇고, 남의 것은 못 건드리게.** 신청을 누가 했는지(로그인한 사용자)와 연결하고, **자기 신청만 보고 취소할 수 있게** 막습니다. 여기서 지난 시간에 배운 **행 수준 보안(RLS)** 이 나옵니다 - Supabase는 이걸 켜지 않으면 로그인한 아무나 남의 데이터를 볼 수 있어 **반드시 켜야** 합니다.

**명령(의도만)**: "신청을 로그인한 사용자와 연결하고, 각자 자기 신청만 보거나 취소할 수 있게 해 줘. 다른 사람 신청은 못 건드리게 행 수준 보안을 켜 줘. 정원 초과 방지는 그대로 지켜야 해."

**확인(직접 눈으로)**: (1) 로그인해 신청하면 **내 신청 내역**에 뜨는가 (2) **다른 계정**으로 로그인하면 앞 사람 신청이 안 보이는가 (3) **정원 초과 방지가 여전히** 지켜지는가. 통과하면 커밋.

(출처: Supabase Docs, ["Password-based Auth"](https://supabase.com/docs/guides/auth/passwords); ["Row Level Security"](https://supabase.com/docs/guides/database/postgres/row-level-security))

### 여기서 막힙니다 - 미리 알면 안 당하는 함정 넷

이 튜토리얼을 실제로 붙여 보며 걸린 지점들입니다. 미리 알아 두면 시간을 아낍니다.

- **가짜 이메일은 거부됩니다.** `test@example.com` 같은 주소로 가입하면 Supabase가 `email_address_invalid`로 막습니다(존재하지 않는 도메인 거부). 실제로 받을 수 있는 이메일을 쓰거나, 개발 중엔 아래처럼 이메일 확인을 끄세요.
- **가입하자마자 로그인하면 실패합니다.** 기본 설정은 **이메일 확인** 을 요구해서, 확인 메일의 링크를 누르기 전에는 로그인이 안 됩니다(`Email not confirmed`). 게다가 무료 티어의 확인 메일은 **시간당 몇 통으로 제한** 됩니다. 수업 중 빠르게 테스트하려면 Supabase 대시보드의 Authentication 설정에서 **'Confirm email'을 잠시 꺼** 두면 즉시 가입·로그인됩니다(배포 전엔 다시 켜기).
- **실제 사용자에게 메일을 보내려면 커스텀 SMTP를 붙입니다.** 기본 내장 메일은 테스트용이라 프로젝트 팀 멤버 주소로만, 시간당 두어 통만 나갑니다(그 이상은 `over_email_send_rate_limit`). 학생들 이메일로 확인 메일을 실제로 보내려면 **커스텀 SMTP** 를 설정하세요. Resend, SendGrid, Amazon SES, Postmark처럼 여러 이메일 서비스가 SMTP 접속 정보를 제공하니, 대시보드 Authentication 설정에 그 값을 넣으면(토글) 발송 한도도 직접 정할 수 있습니다. 수업 데모처럼 메일이 굳이 필요 없으면 'Confirm email'을 끄는 편이 빠릅니다.
- **확인 메일 링크가 localhost로 돌아가면** Site URL 설정 탓입니다. 대시보드 Authentication의 **Site URL** 과 Redirect URLs를 배포한 주소로 바꾸면, 링크가 배포된 앱으로 정상 복귀합니다.
- **RLS를 안 켜면 남의 데이터가 다 보입니다.** Supabase 표는 행 수준 보안을 켜기 전엔 로그인한 누구나 전체를 읽습니다. 3단계에서 꼭 켜세요.
- **키 두 개를 구분하세요.** 공개 키(publishable/anon)는 화면에 쓰여도 되지만(그래도 `.env`로), 비밀 키(secret/service_role)는 절대 코드나 git·채팅에 올리지 마세요. 노출되면 RLS를 우회해 DB 전체가 열립니다 - 실수로 올렸다면 즉시 대시보드에서 폐기(재발급)하세요.

Supabase 인증을 붙이면 이런 흐름이 됩니다 - 회원가입 → 로그인 → 로그인한 상태로 신청하고 내 내역 확인. (화면은 디자인 예시입니다.)

### 잠깐 멈춰 정리 - 무엇을 손에 익혔나

방금 익힌 건 '클래스 신청 앱' 자체가 아닙니다. **다섯 단계의 절차**(PRD → 작업대 → 화면 → 저장 → 한 바퀴+배포)입니다. 그 위에 다음 탈것으로 로그인(Supabase)을 얹어 봤고, 에이전트와 스펙부터 대화해 배포·관리자까지 가는 실전 흐름도 봤죠. 핵심은 이 절차 - 어떤 서비스를 만들든 그대로 통합니다.

다음 단원에서는 이 절차를 **각자의 도메인**으로 옮깁니다. 앞에서 통째로 주어진 틀을 이제 여러분이 직접 잡습니다 - 처음엔 틀(빈칸)을 주고, 점점 그 틀을 걷어 가며, 결국 혼자서 한 바퀴를 돌게 됩니다.
