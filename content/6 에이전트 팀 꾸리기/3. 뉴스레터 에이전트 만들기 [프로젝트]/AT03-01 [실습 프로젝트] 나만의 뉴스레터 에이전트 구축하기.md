## [실습 프로젝트] 나만의 뉴스레터 에이전트 구축하기

이전에 구축해 본 에이전트 워크플로우를 바탕으로, 나만의 맞춤형 뉴스레터 에이전트를 완성하는 프로젝트입니다. 관심 있는 분야를 직접 선정하여 매일 아침 정보를 수집하고, 핵심 소식을 선별·요약·검수하여 최종 발행까지 완료하는 자동화 시스템을 구현해 봅니다.

구현 방식은 자유롭되, 아래 5가지 핵심 단계는 시스템 내에 반드시 포함되어야 합니다.

### 📌 필수 구현 5단계

1. **자료 수집**
   - 최소 3개 이상의 소스에서 데이터를 수집하도록 구현합니다.
	   - 다음 목록은 제외하고 수집해주세요.
	     - OpenAI - [https://openai.com/blog/rss.xml](https://openai.com/blog/rss.xml)
	     - DeepMind - [https://deepmind.google/blog/rss.xml](https://deepmind.google/blog/rss.xml)
	     - TechCrunch - [https://techcrunch.com/category/artificial-intelligence/feed/](https://techcrunch.com/category/artificial-intelligence/feed/)
	     - The Verge - [https://www.theverge.com/rss/ai-artificial-intelligence/index.xml](https://www.theverge.com/rss/ai-artificial-intelligence/index.xml)
	     - MIT TR - [https://www.technologyreview.com/feed/](https://www.technologyreview.com/feed/)
	     - AI타임스 - [https://www.aitimes.com/rss/allArticle.xml](https://www.aitimes.com/rss/allArticle.xml)
   - 특정 소스를 채택하거나 탈락시킨 이유와 기준을 명확히 검증합니다.
2. **자료 선별**
   - 수집된 전체 데이터 중 타깃 독자에게 유용한 핵심 뉴스 3~5건을 골라냅니다.
   - 명확한 선별 기준을 제시하고, 해당 기준이 의도대로 동작했음을 증명할 근거(로그, 라벨 등)를 남깁니다.
3. **요약 및 인사이트 추출**
   - 선별된 기사의 본문을 확인하고 단순 요약을 넘어 독자 관점의 의미 있는 인사이트를 가공합니다.
4. **자동 검수 및 예외 처리**
   - AI가 생성한 요약본에 할루시네이션(환각)이나 오류가 없는지 검증하는 절차를 구현합니다.
   - 검수 결과 통과하지 못했을 때 실행할 대안(재생성, 스킵 등)을 함께 마련합니다.
5. **최종 발행**
   - 검수를 최종 통과한 콘텐츠가 목표 채널에 문제없이 전달 및 발행되는지 확인합니다.

### 📂 제출물 및 디렉토리 구조

프로젝트 제출 시 아래의 파일 구조를 참고해서 전체 실행 파일과 REPORT.md가 포함된 깃헙 주소를 제출해주세요.
(아래 디렉토리 구조는 예시입니다.)

```
my-newsletter/
├── graph.py                # LangGraph 에이전트 워크플로우 메인 로직
├── run.py                  # 파이프라인 실행 스크립트
├── audience.yaml           # 타깃 독자, 중요도 기준, 제외 조건 설정 파일
├── requirements.txt        # 의존성 패키지 목록
├── store/metrics.jsonl     # 파이프라인 실행 및 검수 기록 데이터
└── REPORT.md               # 프로젝트 수행 결과 보고서
```

### 📝 REPORT.md 작성 가이드

REPORT.md에는 프로젝트 진행 과정과 설계 판단을 다음 5가지 항목으로 구분해 정리해 주세요.

- **분야 및 독자 정의**: 해당 분야를 선택한 배경과 타깃 독자 페르소나 설정
-  **소스 채택표**: 검토한 소스 후보 전체 목록, 측정 데이터, 채택·탈락 여부와 수치적 근거
-  **선별 로직 설계**: 중요도 판단 문장, 예선/본선 2단계 구조 및 묶음(Batch) 크기 설정 이유
-  **파이프라인 구조도**: LangGraph 노드 및 상태(State) 흐름을 한눈에 파악할 수 있는 전체 아키텍처 다이어그램 (Mermaid 코드 또는 이미지)
-  **실행 기록**: 최종 검수를 거쳐 정상 발행된 결과 화면 캡처
-  **프로젝트 회고**: 개발 시 가장 공들인 부분과 향후 보완하고 싶은 개선점
