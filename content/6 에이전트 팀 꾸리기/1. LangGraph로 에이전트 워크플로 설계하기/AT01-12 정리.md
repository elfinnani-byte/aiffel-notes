# [에이전트 팀 꾸리기] - 12. 정리

---

## 정리

- '에이전트'라는 모호한 말을 워크플로와 에이전트로 구분해서 설명했습니다.
- LangGraph의 기본 요소인 State, Node, Edge를 직접 만들고 실행해보았습니다.
- LLM에 원하는 도구를 쥐어주고 스스로 도구를 호출하는 ReAct 구조를 간단하게 구현해봤습니다.
- 5가지 에이전트 워크플로 패턴을 구현해보았습니다.

| 패턴 | 문제의 특성 | 그래프 구성의 핵심 | 실무적 대가 및 주의점 |
| :--- | :--- | :--- | :--- |
| 프롬프트 체이닝 | 단계별 순서가 존재하며 중간 점검이 필수적일 때 | 순차 노드 연결 + 결정적 코드 게이트 | 단계 수만큼 전체 지연시간(Latency) 증가 |
| 라우팅 | 입력 유형별로 완전히 다른 프롬프트/모델이 필요할 때 | 분류 노드 + 점선(선택) 조건부 엣지 | 분류 노드의 오류가 전체 결과를 망침 (단일 실패 지점) |
| 병렬화 | 독립적인 하위 작업이며, 작업의 개수를 사전에 알 때 | 실선(동시) 팬아웃 + 리듀서(Reducer) | 시간은 단축되나, 호출 횟수만큼 API 토큰 비용 증가 |
| 오케스트레이터-워커 | 입력에 따라 하위 작업의 개수와 내용이 동적으로 변할 때 | 오케스트레이터 + Send API를 통한 노드 복제 | 오케스트레이터의 계획 품질이 상한선 결정, 비용 예측 불가 |
| 평가자-최적화자 | 명확한 기준이 있고 피드백 반영 시 품질이 상승할 때 | 생성/평가 노드간의 순환(Loop) 엣지 | 라운드마다 비용 곱절 증가, 무한 루프 상한 필수 |

> [!question]+ 주관식 퀴즈
> Q. 아이스브레이킹에서 'AI 에이전트가 대신해 주면 좋겠는 반복 작업'과 그에 필요한 조회·행동 목록을 적었습니다. 그 답을 다시 꺼내 보세요. 오늘 배운 다섯 패턴 중 그 작업에는 어떤 패턴이 맞을까요?

### 📚 오늘 나온 자료 모아보기 + 다음 학습 자료

- [Anthropic — Building Effective Agents](https://www.anthropic.com/engineering/building-effective-agents) — 오늘 배운 다섯 패턴의 원전. 하루를 마친 지금 다시 읽으면 처음과 완전히 다르게 읽힌다. 꼭 다시 보길 권한다
- [Chip Huyen — Agents](https://huyenchip.com/2025/01/07/agents.html) — 도구 선택·계획 능력·실패 유형을 깊게 다룬다. 오늘 실습으로 감각을 잡았으니 이제 이 글의 세부가 이해될 것이다
- [LangGraph 공식 문서 — Workflows and agents](https://docs.langchain.com/oss/python/langgraph/workflows-agents) — 다섯 패턴의 공식 예제 코드. 오늘 만든 것과 비교하며 다른 구현 방식을 확인해 보자
- [LangChain Academy — Introduction to LangGraph (무료)](https://academy.langchain.com/courses/intro-to-langgraph) — LangChain이 직접 만든 무료 강의다. 오늘 내용과 겹치는 부분이 많아 복습용으로 좋고, 뒷부분은 오늘 다루지 않은 주제로 이어진다
- [LangGraph 가이드북(한국어) — 에이전트 RAG with 랭그래프](https://wikidocs.net/book/16723) — 한국어로 LangGraph를 처음부터 다루는 무료 온라인 책이다. 영어 문서가 부담될 때 같은 개념을 우리말로 확인할 수 있다
