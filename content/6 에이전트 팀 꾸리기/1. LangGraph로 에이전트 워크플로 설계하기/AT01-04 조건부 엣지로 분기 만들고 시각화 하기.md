## 갈림길 만들기: 조건부 엣지(Conditional Edge)

처음 만들어본 그래프는 일직선이었지만, 실제 시스템에서는 조건에 따라서 동작이 달라져야 하는 경우가 있습니다. 예를 들면, "노트가 너무 짧으면 출제를 보류하고, 충분하면 출제 대기열에 넣는다"처럼 갈림길이 필요합니다.

**조건부 엣지**는 이러한 갈림길을 만들어주는 엣지입니다. 출발 노드 실행 후 상태를 보고 다음 목적지를 반환합니다. 한번 만들어서 확인해볼까요?

**실습: 조건부 엣지로 갈림길 만들기**

```python
from typing import Literal
from typing_extensions import TypedDict
from langgraph.graph import StateGraph, START, END

class TriageState(TypedDict):
    text: str
    decision: str
    note: str

MIN_LENGTH = 60   # 이보다 짧으면 문항을 만들 재료가 부족하다고 본다

def receive(state: TriageState):
    print(f"[receive] 노트 접수: {state['text'][:32]!r}… ({len(state['text'])}자)")
    return {}                      # 상태를 바꾸지 않아도 빈 딕셔너리를 반환하면 된다

# ── 라우터 함수: 상태를 읽고 '다음에 갈 곳의 이름'을 문자열로 반환한다
def triage(state: TriageState) -> Literal["flag_too_short", "accept"]:
    if len(state["text"].strip()) < MIN_LENGTH:
        return "flag_too_short"
    return "accept"

def flag_too_short(state: TriageState):
    return {"decision": "출제 보류",
            "note": f"내용이 {MIN_LENGTH}자 미만입니다. 개념 정의와 예시를 보강해 주세요."}

def accept(state: TriageState):
    return {"decision": "출제 가능",
            "note": "출제 대기열에 넣었습니다. 복습 문항을 생성하겠습니다."}

builder = StateGraph(TriageState)
builder.add_node("receive", receive)
builder.add_node("flag_too_short", flag_too_short)
builder.add_node("accept", accept)

builder.add_edge(START, "receive")
# ── 조건부 엣지: receive가 끝나면 triage()를 호출해 다음 목적지를 결정한다
builder.add_conditional_edges("receive", triage, ["flag_too_short", "accept"])
builder.add_edge("flag_too_short", END)
builder.add_edge("accept", END)

triage_graph = builder.compile()

for text in [
    "State는 딕셔너리다.",
    "State는 노드들이 공유하는 딕셔너리다. 노드는 바꾼 키만 돌려주고 LangGraph가 병합한다. "
    "같은 키에 두 노드가 동시에 쓰면 리듀서가 필요하다.",
]:
    out = triage_graph.invoke({"text": text})
    print(f"  → 판정: {out['decision']}\n  → 안내: {out['note']}\n")
```

조건부 엣지(conditional edge)는 "한 노드가 끝난 뒤, 상태를 보고 다음 목적지를 그때그때 결정하는" 엣지입니다. `add_conditional_edges(출발노드, 라우터함수, 목적지목록)` 형태로 씁니다.

`builder.add_conditional_edges("receive", triage, ["flag_too_short", "accept"])` 이 예시를 살펴보면, receive 노드의 실행이 끝나면, triage()라는 라우터 함수를 호출합니다. 라우터 함수가 반환한 문자열을 노드 이름으로 보고, 그 노드로 이동합니다.

`add_conditional_edges`의 세 번째 인자는 두 가지 형태로 쓸 수 있습니다.
방금처럼 리스트 `["flag_too_short", "accept"]`를 주면 라우터의 반환값을 노드 이름으로 바로 씁니다. 딕셔너리 `{"보류": "flag_too_short", "통과": "accept"}`를 주면 라우터가 반환한 라벨을 노드 이름으로 번역해 줍니다. 딕셔너리 방식은 라우터가 "합격"/"불합격" 처럼 의미 있는 한국어 라벨을 반환하게 하고 싶을 때 유용합니다.

```python
def triage(state: TriageState) -> Literal["flag_too_short", "accept"]:
    if len(state["text"].strip()) < MIN_LENGTH:
        return "보류"
    return "통과"

builder.add_conditional_edges("receive", triage, {"보류": "flag_too_short", "통과": "accept"})
```

조건부 엣지는 단순히 길을 나누는 걸 넘어서, 이미 지나온 노드로 되돌아가는 루프(반복)을 만들 수도 있습니다.

```
add_conditional_edges("evaluate", decide, {"통과": END, "재시도": "generate"})
```

위처럼 쓰면 evaluate 에서 generate 로 돌아가는 순환이 생깁니다. 이것이 LangGraph에서 반복 루프를 만드는 방법입니다.

즉 조건부 엣지 하나로 분기와 반복을 모두 표현할 수 있습니다.

### 만든 그래프를 눈으로 확인하기

그래프가 커지면 코드만 보고 구조를 파악하기가 어려워집니다. LangGraph는 컴파일된 그래프에서 구조를 뽑아내 그림으로 그려 주는 기능을 내장하고 있습니다. `graph.get_graph()`로 구조 객체를 얻은 뒤, 시각화할 수 있습니다.

- draw_mermaid() — Mermaid 문법의 **텍스트**를 돌려줍니다. 이 텍스트를 문서나 README에 붙여 넣으면 GitHub·Notion 등에서 다이어그램으로 렌더링됩니다. 네트워크가 필요 없습니다.
- draw_mermaid_png() — Mermaid를 실제 PNG 이미지로 렌더링합니다. 기본 설정에서는 외부 렌더링 서비스를 호출하므로 **네트워크가 필요**합니다. 주피터 환경에서 가장 보기 좋습니다.

**실습: 그래프 시각화 세 가지 방법**

```python
from IPython.display import Image, display

g = triage_graph.get_graph()

print("\n── draw_mermaid() (문서에 붙여넣을 텍스트) ──")
print(g.draw_mermaid())

print("\n── draw_mermaid_png() (네트워크 필요) ──")
display(Image(g.draw_mermaid_png()))
```

draw_mermaid() 출력에서 눈여겨볼 부분은 화살표의 **모양**입니다.

```
__start__ --> receive;
receive -.-> accept;
receive -.-> flag_too_short;
accept --> __end__;
flag_too_short --> __end__;
```

`-->`는 실선이고 `-.->`는 점선입니다. Mermaid에서 점선은 조건부 엣지를 나타냅니다. 즉 점선 화살표는 항상 지나가는 길이 아니라, 조건에 따라 선택되는 길 이라는 뜻입니다. receive 에서 나가는 두 화살표가 점선인 것은 라우터의 반환값에 따라 둘 중 하나만 선택된다는 의미입니다.

화살표에 **라벨이 붙지 않은 것**도 눈여겨보세요. 목적지를 리스트로 줬기 때문에 라우터의 반환값이 곧 노드 이름이고, 이름과 같은 라벨은 생략됩니다. 목적지를 딕셔너리로 주어 노드 이름과 다른 라벨을 붙이면 `evaluate -. accept .-> __end__`처럼 라벨이 그림에 나타납니다.

### 🚀 더 해보기 — 분기를 한 걸음 밀어붙이기

**1. 분기를 세 갈래로 늘리기**

- 접근 힌트: triage() 가 flag_too_short / accept / flag_too_long 세 값을 반환하도록 고치고, 3000자를 넘는 노트는 split_note 노드로 보내 보세요. 긴 노트는 문항 하나로 덮을 수 없어 쪼개야 하기 때문입니다. add_conditional_edges 의 목적지 리스트에 새 노드 이름을 추가하는 것을 잊지 마세요.
- 성공하면: 조건부 엣지가 두 갈래에 국한되지 않으며, 목적지 개수만큼 자유롭게 늘릴 수 있다는 것을 확인할 수 있습니다.

**2. 라벨 매핑 방식으로 바꿔 보기**

- 접근 힌트: 목적지를 리스트 대신 딕셔너리 {"보류": "flag_too_short", "통과": "accept"} 로 주고, 라우터가 한국어 라벨을 반환하도록 고쳐 보세요. 그 뒤 draw_mermaid() 출력의 화살표를 앞의 결과와 비교하세요.
- 성공하면: 라벨이 노드 이름과 달라지는 순간 receive -. 보류 .-> flag_too_short 처럼 **화살표에 라벨이 나타납니다.** 방금 실습에서 라벨이 보이지 않았던 이유를 직접 확인하게 되고, 노드 '이름'은 영문으로 두고 '라벨'만 한국어로 하는 절충안을 배울 수 있습니다.

**3. 일부러 루프를 만들어 보기**

- 접근 힌트: flag_too_short 가 END 로 가는 대신 receive 로 돌아가게 엣지를 바꿔 보세요. 그러면 짧은 노트는 영원히 순환합니다. 실행할 때 graph.invoke(입력, {"recursion_limit": 6}) 처럼 제한을 걸어 보세요.
- 성공하면: GraphRecursionError 가 발생하는 것을 직접 보게 됩니다. 루프를 만들 때 반드시 종료 조건과 상한이 필요하다는 걸 확인할 수 있습니다.
