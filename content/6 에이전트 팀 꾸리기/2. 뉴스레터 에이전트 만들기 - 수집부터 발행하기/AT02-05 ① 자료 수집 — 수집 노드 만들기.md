## 수집 노드 만들기

소스가 정해졌으니 섹션 2의 빈 collect 를 채울 차례입니다. 할 일은 세 가지예요.

소스 목록을 돌며 글을 가져오고, 정해진 시간 창 안의 것만 남기고, 같은 글이 두 번 들어오지 않게 거릅니다. 소스 한 곳이 응답하지 않아도 나머지는 계속 모을 수 있게 예외처리까지 해보겠습니다.

바꾸는 건 collect 함수 하나뿐이고 State도 그래프도 건드리지 않습니다.

**실습: 수집 노드를 채우고 그래프를 다시 돌리기 (키 불필요)**

```python
import feedparser, requests, re
from datetime import datetime, timedelta, timezone

UA = {"User-Agent": "Mozilla/5.0 (newsletter-agent-course)"}
SOURCES = [
    ("OpenAI",     "https://openai.com/blog/rss.xml"),
    ("DeepMind",   "https://deepmind.google/blog/rss.xml"),
    ("TechCrunch", "https://techcrunch.com/category/artificial-intelligence/feed/"),
    ("The Verge",  "https://www.theverge.com/rss/ai-artificial-intelligence/index.xml"),
    ("AI타임스",    "https://www.aitimes.com/rss/allArticle.xml"),
]

def strip_tags(s):
    return re.sub(r"<[^>]+>", "", s or "").strip()

def published_at(entry):
    t = entry.get("published_parsed")
    return datetime(*t[:6], tzinfo=timezone.utc) if t else None

def collect(s: dict) -> dict:                   # ① 자료 수집 — 빈 노드를 갈아 끼운다
    cutoff = datetime.now(timezone.utc) - timedelta(hours=s["hours"])
    items, dead, seen = [], [], set()
    for name, url in SOURCES:
        try:
            feed = feedparser.parse(requests.get(url, headers=UA, timeout=20).content)
        except Exception:
            dead.append(name)                   # 한 곳이 죽어도 나머지는 계속
            continue
        for e in feed.entries:
            at = published_at(e)
            if not at or at < cutoff:           # 시간 창 밖이거나 날짜가 없으면 버린다
                continue
            key = e.link.split("?")[0].rstrip("/")       # 추적용 꼬리표를 떼고 비교
            if key in seen:
                continue
            seen.add(key)
            items.append({"title": e.title, "url": e.link, "source": name, "at": at,
                          "summary": strip_tags(e.get("summary", ""))[:300]})
    return {"collected": items,
            "log": [f"① 수집   {s['hours']}시간 창 · {len(items)}건"
                    + (f" · 응답 없음 {dead}" if dead else "")]}

for line in run()["log"]:                       # 그래프는 그대로, 노드만 바뀌었다
    print(line)
```

## 무엇을 보게 되나

첫 줄의 숫자가 0에서 벗어났고 나머지 네 줄은 여전히 0입니다. 고친 건 함수 하나뿐이고 build() 가 이름으로 노드를 찾으니 새 collect 가 그대로 들어갑니다.

코드에서 세 군데를 보세요.

if not at or at < cutoff — 시간 창입니다. hours 는 State에서 오니까 나중에 이 값을 48로 바꾸면 같은 함수가 더 넓은 시간 동안 올라온 소스를 탐색합니다. 날짜가 아예 없는 항목도 여기서 함께 버려집니다.

key = e.link.split("?")[0] — 중복 제거입니다. 같은 글이 ?utm_source=... 가 붙은 채로 두 번 들어오는 일이 흔해서 꼬리표를 떼고 비교합니다. 다만 이건 주소가 같은 것만 걸러 냅니다. 매체가 다른데 같은 사건을 다룬 기사는 그대로 통과합니다.

except Exception: dead.append(name) — 소스 하나의 실패를 격리합니다. 한 곳이 죽어도 나머지는 모이고, 죽은 곳은 로그에 남습니다. 이 마지막 한 줄이 없으면 어떻게 되는지가 이 섹션의 마지막 이야기입니다.

### 조용한 실패

실행이 멈추지도 않고 에러도 안 남기는데 결과만 틀리게 나오는 고장을 말합니다. 방금 코드에서 dead 를 로그에 남기지 않았다고 해 봅시다. 소스 한 곳이 조용히 빠지고, 파이프라인은 매일 성공적으로 끝나고, 건수가 조금 줄었다는 사실만 아무도 모릅니다.

자동으로 도는 시스템에서 가장 비싼 고장입니다. 요란하게 죽는 건 그날 바로 고치지만, 조용한 고장은 몇 달 뒤 누군가 "요즘 왜 그 매체 기사가 안 보이지?"라고 물을 때까지 남아 있고, 그때는 몇 달치를 거슬러 올라가야 하거든요.

태어나는 자리는 대개 정해져 있습니다. continue 와 except: pass 입니다. 둘 다 "이건 건너뛴다"는 뜻인데, 건너뛴 사실을 아무 데도 적지 않으면 그 순간부터 증거가 사라져요. 위 코드가 dead 를 모아 로그에 넣는 이유입니다.

다만 모든 continue 에 기록을 붙이면 로그를 읽을 수 없게 됩니다. 기준은 그 건너뜀이 결과물을 바꾸는가예요. 소스 하나가 통째로 빠지는 건 바꾸고, 날짜 없는 항목 한 건이 빠지는 건 바꾸지 않습니다. 섹션 12에서 이 기록을 어디에 쌓을지 정합니다.

### 🚀 더 해보기 — 수집 노드를 흔들어 보기

**1. SOURCES 에 소스를 한 곳 더 추가하고 총 건수가 얼마나 늘어나는지 본다**

- 접근 힌트: Hugging Face 블로그는 https://huggingface.co/blog/feed.xml 이다. 추가 전후 건수를 적어 둔다
- 성공하면: 소스 하나가 하루에 기여하는 건수의 편차가 크다는 것을 알 수 있다. 이 숫자가 섹션 14에서 소스를 평가하는 근거가 된다

**2. INIT 의 hours 를 6과 72로 바꿔 각각 몇 건이 모이는지 기록한다**

- 접근 힌트: 세 번의 결과를 표로 적어 두고 요일을 바꿔 다시 한번 재 본다
- 성공하면: 주말과 평일의 차이가 시간 창보다 클 수 있다는 것을 확인할 수 있다. '기사가 모자라는 날'이 실재한다는 것을 알게 된다. 그런 날 우리 파이프라인은 적게 발행한다

**3. 소스 주소 하나를 일부러 틀리게 바꿔 dead 가 찍히는지 확인한다**

- 접근 힌트: 도메인에서 한 글자를 빼고 돌린다. 그다음 dead.append(name) 줄을 지우고 다시 돌려 본다
- 성공하면: 기록이 있을 때와 없을 때의 차이를 눈으로 본다. 없을 때는 건수가 줄었다는 것 말고 아무 단서가 없다

### 📚 수집 노드를 만들 때 참고할 자료

- [feedparser — Common RSS elements](https://feedparser.readthedocs.io/en/latest/common-rss-elements.html) — entries 안에 어떤 항목이 들어오는지 정리돼 있다. 소스를 새로 추가하기 전에 그 피드가 무엇을 주는지 여기서 대조해 보면 좋다
- [feedparser — Date Parsing](https://feedparser.readthedocs.io/en/latest/date-parsing/) — published_parsed 가 언제 비는지 적혀 있다. 위 코드가 not at 으로 거르는 항목이 바로 그런 경우다
- [MDN — URL.searchParams](https://developer.mozilla.org/en-US/docs/Web/API/URL/searchParams) — ?utm_source=... 같은 꼬리표를 제대로 떼려면 문자열 자르기보다 이쪽이 안전하다. 중복 판정을 더 정확하게 만들고 싶을 때 본다
