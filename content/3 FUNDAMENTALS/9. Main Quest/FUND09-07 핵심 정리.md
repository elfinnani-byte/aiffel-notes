## 핵심 정리

| 항목 | 한 줄 정리 |
| :--- | :--- |
| 출발점 | 도구가 아니라 업무에서 출발합니다. 도구에서 출발하면 업무가 도구에 맞춰집니다 |
| 업무 유형 | 검색, 검사와 판독, 분류와 배분, 입력과 전사. 유형마다 병목이 다르고 도입 근거도 다릅니다 |
| 적용하지 않을 업무 | 판정 기준이 사람마다 다른 일, 되돌릴 수 없는 일, 판정 기록이 없는 일 |
| 성공 기준 | 만들기 전에 정량으로 적습니다. 근거는 지금 사람이 하는 수준입니다 |
| 후보 구성 | 크기가 아니라 종류로 벌립니다. 실행 위치, 만들어진 목적, 결과의 형태 |
| 기준선 | 지금 그 업무를 처리하는 방식을 후보에 넣습니다. 이것이 이기면 그것도 결과입니다 |
| 제외 조건 | 실행 위치와 라이선스로 먼저 걸러냅니다. 점수와 섞으면 쓸 수 없는 후보가 1위가 됩니다 |
| 임계값 | 값 아래를 잘라 내는 경계입니다. 걸 수 있으려면 점수가 순위용이 아니어야 합니다 |
| 신뢰도 | 모델이 확신 정도를 함께 내주는 값입니다. 읽지 않으면 없는 것에 대한 판정이 나옵니다 |
| 값의 검증 | 값을 새로 넣을 때마다 그 값이 의도한 것을 재고 있는지 따로 확인합니다 |
| 촬영과 입력 조건 | 판정 항목을 정하면 자료를 어떻게 모을지가 함께 정해집니다. 모델 교체로 해결되지 않습니다 |
| PoC의 산출물 | 작동하는 물건이 아니라 판단입니다. 기준을 못 넘은 이유도 결과입니다 |

### 오늘의 회고

네 가지를 적어 두십시오.

1. 적은 세 지점 중에서 고른 것과 뺀 것의 차이는 무엇이었습니까?
2. 성공 기준의 숫자를 어디서 가져왔습니까? 현행 수준을 실제로 재 보았습니까?
3. 실행 위치나 라이선스 때문에 제외한 후보가 있었습니까? 그 후보가 점수로는 몇 위였습니까?
4. 기준을 넘지 못한 항목이 있다면, 다음에 무엇을 바꿔 다시 확인하겠습니까?
