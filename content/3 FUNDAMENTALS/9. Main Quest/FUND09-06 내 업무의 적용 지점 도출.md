## 내 업무의 적용 지점 도출

이제 각자 자기 업무로 옮깁니다.

### 후보 목록 만들기

먼저 지점을 셋 이상 적습니다. 하나만 적으면 그것이 최선인지 알 수 없고, 셋을 놓고 보면 어느 것이 PoC로 확인하기 좋은지가 드러납니다.

| 적은 것 | 업무 유형 | 지금 처리 방식 | 병목 | 하루·주당 발생량 | 틀렸을 때 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| | | | | | |
| | | | | | |
| | | | | | |

`업무 유형`은 검색·검사와 판독·분류와 배분·입력과 전사 중에서 고릅니다. 넷 중 어디에도 안 들어가면 그 이유를 적습니다. 새 유형일 수도 있고, 하나의 업무가 아니라 여러 업무가 섞여 있는 것일 수도 있습니다.

`틀렸을 때` 칸을 비워 두지 마십시오. 이 칸이 세 지점 중 무엇을 고를지를 가릅니다. 잘못된 판정이 고객에게 그대로 나가거나 사람에게 영향을 주는 지점은 PoC 대상에서 뒤로 미룹니다.

셋 중 하나를 고르는 기준은 이렇습니다.

- 판정 기준이 이미 정해져 있다
- 지난 판정 기록이 남아 있어 채점할 자료를 만들 수 있다
- 틀렸을 때 되돌릴 수 있다
- 발생량이 충분해서 개선 효과가 눈에 보인다

넷을 다 만족하는 지점이 없으면 가장 많이 만족하는 것을 고르고, 못 만족하는 항목을 제약으로 적어 둡니다.

### 성공 기준 적기

고른 지점에 대해 한 줄을 씁니다. 정량으로 씁니다.

기준의 근거는 지금 사람이 하는 수준입니다. 그 수준을 모르면 먼저 재야 합니다. 스무 건을 담당자에게 처리하게 하고 걸린 시간과 오류 수를 세는 정도로 충분합니다.

### 만들기

후보를 셋 놓고, 실행 위치와 라이선스로 걸러낸 다음, 남은 후보를 자기 자료로 비교합니다. 정답은 돌리기 전에 적어 둡니다.

코드는 코딩 에이전트에게 시킵니다. 지시문에 넣을 것이 다섯 있습니다.

- 모델 이름과 실행 위치, 그리고 자료를 외부로 보내지 말라는 조건
- 판정에 쓰는 값을 전부 인자로 받게 하고 코드에 숫자를 박지 말 것
- 결과에 점수나 신뢰도를 함께 남기고 반올림하지 말 것
- 중간 산출물을 파일로 남기고 다시 돌려도 덮어쓰지 말 것
- 결과를 눈으로 확인할 수 있는 형태로 함께 저장할 것

마지막 항목이 검산을 가능하게 합니다. 숫자만 보고 판단하면 값이 의도한 것을 재고 있지 않은 경우를 놓칩니다.
