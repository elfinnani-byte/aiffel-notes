## 왜 내 노트북으론 벅찰까

파인튜닝쯤 오면 "내 노트북으론 벅차다"가 느껴집니다. 왜일까요? 학습되는 숫자, 곧 **파라미터의 개수**와 그에 따르는 **연산량**이 문제마다 하늘과 땅 차이이기 때문입니다.

| 오늘의 학습            | 파라미터(학습되는 숫자) 규모 | 어디서 도나             |
| :---------------- | :--------------- | :----------------- |
| **카페 선형모델**       | 2개 (w, b)        | 노트북에서 즉시           |
| **MNIST 분류기**     | 수만 ~ 수십만         | 노트북 CPU로도 몇 분      |
| **ResNet18 파인튜닝** | 약 1,100만         | GPU 권장(Colab 등)    |
| **대형 언어모델(LLM)**  | 수십억 ~ 수천억        | GPU 수백~수천 대, 데이터센터 |

학습은 매 스텝마다 "예측 → 오차 → 조정"을 하는데, 그 계산의 대부분이 **방대한 행렬 곱셈**입니다. 파라미터와 데이터가 많아질수록 곱셈 횟수가 폭발적으로 늘죠.

![[Pasted image 20260731101716.png]]
> CPU: 큰 코어 몇 개 · 순서대로 / GPU: 작은 코어 수천 개 · 한꺼번에

**그래서 GPU를 씁니다.** CPU는 복잡한 일을 순서대로 빠르게 처리하는 소수의 코어를 가진 반면, GPU는 단순한 계산을 **동시에** 처리하는 코어를 수천 개 갖고 있습니다. 행렬 곱셈처럼 "같은 계산을 엄청나게 많이 병렬로" 해야 하는 학습에 딱 맞아, 같은 일을 CPU보다 수십~수백 배 빠르게 끝냅니다. 개인 노트북에 이런 GPU가 없으니 우리는 **Colab의 무료 GPU**나 클라우드를 빌려 씁니다(코딩 에이전트에게 "GPU 런타임에서 돌려 줘"라고 부탁하는 것도 이 때문입니다).

규모를 끝까지 밀면 그림이 분명해집니다. 대형 언어모델을 **처음부터** 학습(사전학습)하려면 고성능 GPU 수천 대를 수 주간 돌리고 수백만에서 수억 달러가 듭니다. 그래서 현실의 실무는 대부분 **직접 훈련하지 않습니다**. 이미 학습된 모델을 가져와(파인튜닝) 쓰거나 API로 부릅니다. 오늘 파인튜닝을 체험한 이유가 여기 있습니다. "남이 배운 것을 물려받는" 감각과, 그 아래 깔린 규모·비용의 현실을 함께 아는 것이죠.

**한 걸음 더.** 행렬 곱셈이 병렬에 잘 맞는 건, 그 안의 수많은 곱셈이 서로 독립이라 순서 없이 한꺼번에 계산할 수 있어서입니다. 규모 감각도 붙여 봅시다. LLM의 수천억 개 파라미터를 1초에 하나씩 세기만 해도 수천 년이 걸립니다. 학습은 이 숫자 전부를 수없이 조정하는 일이니, 왜 데이터센터급 장비가 필요한지 짐작이 갑니다.

**🖥️ 깊이 보기 (Colab CLI로 GPU 손에 넣기)**

그렇다면 GPU가 없는 내 노트북에서는 이 실습들을 어떻게 돌릴까요? 가장 손쉬운 길이 구글 코랩(Google Colab)입니다. 브라우저로 노트북을 열면 GPU 한 대를 무료로 빌려 주죠. 그런데 2026년 6월, 구글은 여기에 터미널용 도구를 하나 더 얹었습니다. 바로 **Colab CLI**(공식 패키지 `google-colab-cli`)입니다. 브라우저 탭을 열지 않고도 명령어 한 줄로 Colab의 GPU 런타임을 띄우고, 코드를 돌리고, 끝나면 정리까지 해 줍니다.

쓰는 법은 단출합니다.

```bash
pip install google-colab-cli  # 설치 (uv tool install google-colab-cli 도 가능)
colab run --gpu T4 train.py   # GPU VM 띄움 → train.py 실행 → 자동 반납
```

무료 요금제에서는 보통 T4 GPU가 주어지고, 더 강한 A100·H100이나 TPU는 유료(Pro/Pro+)에서 열립니다.

여기서 오늘의 실습 방식과 딱 맞물리는 점이 있습니다. Colab CLI는 **AI 에이전트가 직접 쓰도록** 설계되어, Claude Code나 Codex 같은 코딩 에이전트가 이 명령을 대신 실행할 수 있습니다. 덕분에 앞의 MNIST·파인튜닝에서 "에이전트에게 프롬프트로 시킨다"가 말뿐이 아니라, **에이전트가 실제 GPU에서 코드를 돌리고 정확도를 받아오는 데까지** 이어집니다. 직접 훈련 코드를 쓰지 않아도, 원리를 아는 사람이 "무엇을·어디서·어떻게 돌릴지"만 지시하면 되는 셈이죠.
