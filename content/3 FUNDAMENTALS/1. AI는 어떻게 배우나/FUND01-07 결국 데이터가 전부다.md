## 결국 데이터가 전부다

오늘 우리는 인공지능이 "배운다"는 것을 세 번 직접 봤습니다.

- **회귀(카페 매출)**: 연속된 숫자를 예측합니다. 예측 → 오차 → 조정으로 직선의 규칙을 데이터에서 찾았죠.
- **분류(MNIST)**: softmax로 후보마다 확률을 매겨 하나를 고름.
- **파인튜닝(개/고양이)**: 남이 사전학습한 특징을 물려받아 적은 데이터로 내 문제에 맞춤.

셋을 관통하는 한 문장은 이것입니다. **모델 구조보다 데이터가 결과를 가른다.** 데이터를 10%로 줄이면 정확도가 떨어졌고, 사전학습된 특징을 물려받으면 적은 데이터로도 잘 됐습니다. 그래서 AI를 다루는 사람의 진짜 일은 "좋은 모델 고르기"보다 **좋은 데이터를 모으고 검증하는 것**에 가깝습니다.

우리는 앞으로 이렇게 직접 학습을 돌릴 일이 많지 않습니다. 하지만 오늘 원리를 봤기에, 코딩 에이전트에게 무엇을 시키고(무슨 데이터로, 어떤 학습을), 나온 결과의 무엇을 의심할지(데이터가 충분한가, 정확도가 왜 이런가) 판단할 수 있습니다. 다음 시간에는 오늘 잠깐 스친 언어모델의 속을 들여다봅니다. 바로 **토큰과 컨텍스트, 그리고 트랜스포머**입니다.

### 🎯 핵심 정리

| 핵심 질문 | 오늘의 답 |
| :--- | :--- |
| 인공지능이 "배운다"는 건 무엇인가요? | 규칙을 손으로 짜는 대신, 데이터에서 예측 → 오차 → 조정을 반복해 패턴을 찾는 것입니다. |
| 회귀와 분류는 무엇이 다른가요? | 회귀는 연속된 값(매출)을, 분류는 어느 범주인지(softmax 확률로)를 예측합니다. |
| softmax는 무슨 일을 하나요? | 여러 후보의 점수를 합이 1인 확률로 바꿔, 확신 정도와 함께 하나를 고르게 합니다. |
| 파인튜닝은 왜 쓰나요? | 사전학습된 특징을 물려받아, 적은 데이터·적은 계산으로 내 문제에 맞추기 위해서입니다. |
| 왜 GPU가 필요한가요? | 학습은 방대한 행렬 곱셈이고, GPU는 이를 대규모 병렬로 처리해 CPU보다 훨씬 빠릅니다. |
| AI 활용가의 진짜 일은? | 모델 고르기보다, 좋은 데이터를 모으고 결과를 의심·검증하는 것입니다. |
