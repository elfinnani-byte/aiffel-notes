## 가장 작은 학습을 코드로 보기

앞 섹션에서 학습을 "예측 → 오차 → 조정"의 반복이라고 했습니다. 말로만 들으면 여전히 추상적이죠. 그래서 여기서는 **가장 작은 학습을 직접 돌려** 봅니다. 파라미터가 **weight 하나, bias 하나**뿐인 가장 단순한 모델에게 데이터만 주고 규칙을 스스로 찾게 하는 것입니다. (0과 1을 가르던 로젠블랫의 퍼셉트론과 친척뻘이지만, 여기서는 계단함수 없이 연속값을 예측하는 선형 모델이라 더 간단합니다. 예측 → 오차 → 조정이라는 원리는 똑같습니다.)

우리는 앞으로도 모델을 직접 훈련하지 않습니다. 이 코드는 "데이터로 학습된다"가 마법이 아니라 **오차를 줄이는 방향으로 숫자를 조금씩 미는 계산**임을 눈으로 확인하려는 것뿐입니다. 이 그림을 한 번 봐 두면 뒤에서 파인튜닝을 판단할 때 훨씬 또렷해집니다.

**torch, 두 개념만 알면 됩니다.**
torch(PyTorch)는 딥러닝에서 가장 널리 쓰는 파이썬 라이브러리입니다. 지금 필요한 건 딱 두 가지입니다. 하나는 **텐서**(tensor)로, 앞에서 본 그 숫자 배열입니다. 벡터와 행렬을 아우른 것이죠. 고마운 점은 같은 코드가 CPU에서도 GPU에서도 그대로 돈다는 것으로, 데이터를 어느 장치(device)에 올리느냐만 바꿔 주면 됩니다. 다른 하나는 **autograd**(자동 미분)입니다. torch는 계산 과정을 속으로 기억해 두었다가 `loss.backward()` 한 줄이면 "각 파라미터가 오차에 얼마나 기여했는지", 곧 **기울기**(gradient)를 알아서 계산해 줍니다. 앞서 말한 역전파를 torch가 대신 밟아 주는 셈이죠.

**상황을 하나 놓고 봅시다.** 작은 카페를 연다고 합시다. 하루 방문객 수를 보면 그날 매출을 얼추 예측하고 싶은데, 가진 것은 지난 30일치 `(방문객 수, 매출)` 기록뿐입니다. 방문객이 많은 날은 매출도 높으니 둘 사이에 대략 직선 관계가 있을 것 같지만, 정확한 식(손님이 얼마를 쓰는지, 기본 매출은 얼마인지)은 모릅니다. 이 관계식을 **데이터만 보고 모델이 찾게** 해보겠습니다.

우리가 할 일은 네 단계입니다. **① 숨은 직선 규칙에서 나온 데이터를 만든다 → ② 그 데이터를 눈으로 본다 → ③ 모델에게 규칙을 안 알려 준 채 스스로 찾게 한다(예측 → 오차 → 조정) → ④ 찾은 규칙과 줄어든 오차를 그래프로 확인한다.** 아래 칸들을 위에서부터 차례로 실행해 보세요. (설치가 필요하면 `pip install torch matplotlib`.)

**① 데이터 만들기.**
아래 칸은 카페 30일치 `(방문객 수, 매출)` 데이터를 만듭니다. 숨은 규칙 `매출 = 2 × 방문객 + 1`에 날마다 다른 잡음을 섞은 것이죠(모델은 이 규칙을 모릅니다). 실행하면 계산에 쓸 장치(CPU/GPU)가 한 줄 출력될 뿐, 아직 눈에 보이는 그림은 없습니다.

```python
import torch
import matplotlib.pyplot as plt

# 같은 코드가 CPU/GPU 어디서든 동작합니다.
device = "cuda" if torch.cuda.is_available() else "cpu"
print("사용 장치:", device)

# 카페 30일치 기록을 흉내 낸 데이터입니다.
# x = 하루 방문객 수(단위: 100명), y = 그날 매출(단위: 100만원)
# 숨은 규칙: 매출 = 2*방문객 + 1 (방문객 100명당 200만원 + 기본 100만원)
# 프로그램은 이 '2'와 '1'을 모른 채 출발해, 데이터만 보고 찾아냅니다.
torch.manual_seed(0)
x = torch.linspace(0, 5, 30, device=device).unsqueeze(1)  # 방문객 수 (0~500명)
y = 2.0 * x + 1.0 + 0.4 * torch.randn_like(x)  # 실제 매출 (날마다 들쭉날쭉)
```

**② 데이터 눈으로 보기.**
모델을 학습시키기 전에 먼저 데이터를 봅니다. 아래를 실행하면 30일치 점이 흩어져 그려집니다. 가로축은 방문객 수, 세로축은 매출입니다. 방문객이 많은 날일수록 매출도 높은, 대략 우상향 직선 추세가 보이죠. 하지만 정확한 관계식(방문객이 늘 때 매출이 얼마나 느는지, 기본 매출은 얼마인지)은 위 코드가 숨겨 두었습니다. 이제 모델이 이 점들만 보고 그 관계를 찾아내는지 지켜봅니다.

```python
# 아직 학습 전입니다. 카페 30일치 데이터를 눈으로 봅니다.
plt.figure(figsize=(5.5, 4))
plt.scatter(x.cpu().numpy().ravel(), y.cpu().numpy().ravel(), s=20)
plt.title("cafe: visitors vs daily sales (before learning)")
plt.xlabel("visitors (x100)"); plt.ylabel("sales (x1M won)")
plt.show()
```

**③ 학습시키기.**
여기가 핵심입니다. weight·bias를 엉뚱한 값(0)에서 출발시켜 `예측 → 오차 → 조정`을 600번 반복합니다(경사하강). 실행하면 마지막에 `학습된 규칙: 매출 = 2.07 * 방문객 + 0.79`처럼 학습된 두 숫자가 출력됩니다. 이 값이 숨은 정답(2, 1)에 가깝다면, 아무도 규칙을 알려 주지 않았는데 **데이터만으로 규칙을 찾아낸 것**입니다.

```python
# 학습할 파라미터: weight 1개, bias 1개. 엉뚱한 값(0)에서 출발합니다.
w = torch.zeros(1, 1, device=device, requires_grad=True)
b = torch.zeros(1, device=device, requires_grad=True)

# 모델: 방문객 수 x를 넣으면 예측 매출을 돌려주는 함수. 학습되는 건 w, b 두 숫자뿐입니다.
def model(x):
    return x @ w + b  # 예측 매출 = w*방문객 + b (@ 는 행렬곱; 데이터가 여러 개라 x를 왼쪽에 둡니다)

lr = 0.03  # 학습률: 한 걸음의 크기
losses = []
for step in range(600):
    pred = model(x)  # 예측
    loss = ((pred - y) ** 2).mean()  # 오차: 평균제곱오차(MSE)
    loss.backward()  # autograd가 w, b의 기울기를 계산 (역전파)
    with torch.no_grad():  # 파라미터 갱신은 기울기 추적 밖에서
        w -= lr * w.grad  # 기울기 반대 방향으로 한 걸음 = 경사하강
        b -= lr * b.grad
    w.grad.zero_()  # 다음 스텝을 위해 기울기 초기화
    b.grad.zero_()
    losses.append(loss.item())

print(f"학습된 규칙: 매출 = {w.item():.2f} * 방문객 + {b.item():.2f} (숨은 정답: 2.00, 1.00)")
```

**④ 결과 그리기.**
아래 칸은 학습 결과를 두 개의 그래프(데이터와 학습된 직선, 그리고 오차(loss) 곡선)로 보여줍니다. 실행한 뒤 이어지는 해설로 그 그래프를 읽어 봅니다.

```python
xs = x.detach().cpu().numpy().ravel()
ys = y.detach().cpu().numpy().ravel()
with torch.no_grad():
    fit = model(x).cpu().numpy().ravel()

fig, ax = plt.subplots(1, 2, figsize=(11, 4))
ax[0].scatter(xs, ys, s=20, label="data (30 days)")
ax[0].plot(xs, fit, "r-", linewidth=2, label="learned line")
ax[0].set_title("cafe sales: data vs learned rule")
ax[0].set_xlabel("visitors (x100)"); ax[0].set_ylabel("sales (x1M won)"); ax[0].legend()

ax[1].plot(losses)
ax[1].set_title("loss goes down as it learns")
ax[1].set_xlabel("step"); ax[1].set_ylabel("loss (MSE)")
plt.tight_layout()
plt.show()
```

실행하면 두 가지가 보입니다. 왼쪽 그래프에서 빨간 직선이 흩어진 점들 한가운데를 지나가고, 오른쪽 그래프에서 오차(loss)가 급히 떨어졌다가 평평해집니다. 학습된 직선의 기울기(약 2.07)는 "방문객이 100명 늘면 매출이 약 207만원 는다"는 뜻입니다. 절편(약 0.8)은 방문객이 0명인 날에도 잡히는 기본 매출 약 80만원, 곧 배달·포장처럼 방문과 무관한 매출로 볼 수 있습니다. 절편이 기울기보다 정답에서 더 흔들리는 건, 절편이 방문객 0명 지점의 값인데 데이터의 중심(평균 방문객 수)에서 멀리 떨어져 있어, 그 먼 지점을 추정하는 일이 잡음에 더 민감하기 때문입니다. 아무도 이 숫자들을 알려 주지 않았는데, **30일치 데이터만 보고 오차를 줄이며 그 관계를 찾아낸 것**입니다. 이것이 "데이터로 학습한다"의 전부입니다.

거대 언어 모델도 다르지 않습니다. 다른 점은 오직 규모입니다. weight·bias가 2개가 아니라 수십억~수천억 개이고, 예측하는 것이 숫자 하나가 아니라 다음 토큰의 확률분포라는 것. 방식은 똑같이 "예측 → 오차 → 조정"의 반복입니다.

> 실무에서는 이 갱신 루프를 손으로 쓰지 않고 `torch.nn.Linear`와 `torch.optim.SGD` 같은 도구로 짧게 줄입니다. 위에서 굳이 손으로 편 이유는 경사하강이 실제로 무엇을 하는지 한 번 보기 위해서입니다. 그리고 이 작은 학습을 웹 전체 규모로 돌린 것이 바로 모델의 **사전학습**(pretraining)입니다.
