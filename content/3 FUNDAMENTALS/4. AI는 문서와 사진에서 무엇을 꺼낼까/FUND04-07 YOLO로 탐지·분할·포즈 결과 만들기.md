# [4.AI는 문서와 사진에서 무엇을 꺼낼까?] - 7. YOLO로 탐지·분할·포즈 결과 만들기

## YOLO로 탐지·분할·포즈 결과 만들기

이번에는 같은 사진에서 세 종류의 결과를 만듭니다. 30분 안에 끝내기 위해 수업은 `ultralytics`와 `gradio`가 설치되고 세 가중치가 `models/yolo`에 배치된 상태에서 시작합니다. 모델을 구현하지 않고 Ultralytics가 제공하는 사전학습 가중치를 가져다 씁니다. 코딩 에이전트에게 실행·저장·화면 구성을 맡기고, 우리는 세 head가 만든 자료형의 차이를 확인합니다.

2026년 현재 Ultralytics의 최신 안정 계열인 YOLO26 가운데 CPU에서 다루기 쉬운 경량 가중치 `yolo26n.pt`, `yolo26n-seg.pt`, `yolo26n-pose.pt`를 사용합니다.

| 시간 | 우선할 일 | 통과선 |
| :--- | :--- | :--- |
| 0~5분 | 준비된 세 가중치 실행 또는 정적 대체 결과 열기 | 세 자료형의 이미지·JSON |
| 5~12분 | 박스·마스크·관절점 비교 | 서로 대신할 수 없는 이유 한 줄 |
| 12~22분 | 기존 실행 함수를 Gradio에 연결 | 직접 추론 또는 읽기 전용 앱 실행 |
| 22~30분 | 임계값 세 값 관찰과 사용 책임 카드 | 관찰 기록과 사람이 쓴 카드 |

직접 추론이 5분 안에 끝나지 않으면 준비된 결과로 넘어갑니다. 설치 해결에 시간을 쓰기보다 앱 조립, 결과 차이와 사용 조건을 판단하는 활동을 우선합니다.

### Ultralytics YOLO는 무엇을 가져다 쓰게 해 주는가

Ultralytics 패키지는 이미지·영상 입력, 사전학습 가중치 다운로드, 추론, 결과 객체, 시각화와 내보내기를 하나의 인터페이스로 묶습니다. 모델 내부를 처음부터 작성하지 않아도 `YOLO("...pt")`로 가중치를 불러와 `predict`를 실행할 수 있습니다.

| 작업 | head가 내는 핵심 결과 | 화면에서 보이는 것 | 어울리는 질문 |
| :--- | :--- | :--- | :--- |
| Detection | 클래스, 박스, 점수 | 사각형 | 무엇이 어디에 몇 개인가 |
| Instance segmentation | 박스와 개체별 마스크 | 대상 윤곽 | 각 대상이 어디까지인가 |
| Pose estimation | 사람 박스와 관절 keypoint | 점과 연결선 | 신체 부위가 어떤 자세인가 |

세 모델은 COCO 같은 공개 데이터셋의 범용 클래스와 사람 관절 정의를 미리 학습한 가중치입니다. 공장 결함, 특수 장비 부품, 회사만의 자세 기준을 자동으로 아는 것은 아닙니다.

도구를 가져다 쓰는 편리함과 사용 권리는 별도 문제입니다. Ultralytics는 AGPL-3.0과 Enterprise의 이중 라이선스 선택지를 안내합니다. 수업용 로컬 체험을 넘어 조직의 비공개 제품이나 서비스에 포함하려면 배포 형태와 라이선스 조건을 먼저 검토합니다.

### 입력 한 장과 실행 조건을 고정합니다

사람이 여러 명 있고 버스처럼 윤곽이 큰 대상이 함께 있는 준비된 예제 이미지를 `input/bus.jpg`로 저장합니다.

공통 조건:

- 입력: 같은 `bus.jpg`
- 이미지 크기: 640
- 신뢰도 임계값: 0.25
- 장치: CPU
- 학습·미세조정·내보내기: 이번 실습에서는 하지 않음

공통 조건을 맞춰도 작업별 head와 학습 목표가 다르므로 출력은 달라집니다.

**AI에게 세 작업을 한 번에 맡깁니다.**

```
input/bus.jpg에 준비된 Ultralytics 사전학습 모델 세 개를 실행해 줘.
환경 명령이 필요하면 uv만 사용.
패키지를 업그레이드하거나 다른 모델로 바꾸지 않고,
아래 로컬 경로가 없으면 다운로드를 시도하지 말고 오류를 기록한다.

모델
- detection: yolo26n.pt
- instance segmentation: yolo26n-seg.pt
- pose estimation: yolo26n-pose.pt

한 작업이 실패해도 나머지는 실행한다.
```

### 결과 객체를 자료형으로 읽습니다

코딩 에이전트가 만든 `raw.json`과 시각화 이미지를 함께 엽니다.

- Detection에서 사람 한 명은 대체로 `class + confidence + [x1,y1,x2,y2]`입니다.
- Segmentation에서는 같은 개체에 박스뿐 아니라 다각형 또는 마스크 정보가 붙습니다.
- Pose에서는 사람별 박스와 함께 관절점의 `x, y`와 선택적인 가시성·점수가 붙습니다.

시각화가 그럴듯해도 원시 결과가 없으면 다음 코드에서 사용할 수 없습니다. 반대로 원시 배열만 있고 그림이 없으면 사람이 빠르게 검수하기 어렵습니다. 둘 다 저장하는 이유입니다.

### 임계값 손잡이를 붙인 작은 앱으로 만듭니다

```
앞에서 만든 세 YOLO 실행 함수를 재사용해 Gradio 앱을 만들어 줘.
모델은 models/yolo의 세 파일만 사용하고, 없으면 다운로드하지 않는다.

- 이미지 업로드
- Detect / Segment / Pose 탭
- confidence 슬라이더 0.05~0.90
- 실행 버튼
- 결과 이미지와 객체 수 표시
- 원시 JSON 다운로드
- 현재 모델명, ultralytics 버전, imgsz, confidence 표시
- 오류가 나면 빈 성공 화면 대신 오류 메시지 표시

앱은 apps/yolo/app.py에 만들고,
```

앱이 열리면 같은 사진에서 임계값을 0.15, 0.25, 0.60으로 바꿔 봅니다. 결과 수가 어떻게 달라졌는지 기록하되, 정답 라벨 없이 어느 값이 더 정확하다고 단정하지 않습니다. 이것은 교차 검증이 아니라 **임계값 민감도 관찰**입니다.

모델 실행이 실패해 대체 결과를 쓴다면 앱은 `fallback/outputs/yolo/thresholds`의 0.15·0.25·0.60 폴더를 선택해 보여 주는 읽기 전용 모드로 만듭니다. 각 임계값 폴더에서 `detect/result.jpg·raw.json`, `segment/result.jpg·raw.json`, `pose/result.jpg·raw.json`, `summary.json`과 `run_manifest.json`을 읽습니다. 화면에 `fallback_used=true`를 표시하고 이미지 업로드와 임의 임계값 실행은 비활성화합니다.

| 관찰 | 이유 |
| :--- | :--- |
| Detection 박스가 몸 주변 배경까지 포함 | 박스 좌표를 맞히도록 학습했기 때문 |
| Segmentation이 사람과 버스 윤곽을 각각 칠함 | 개체별 마스크를 맞히는 손실과 head가 있기 때문 |
| Pose가 버스에는 관절점을 만들지 않음 | 기본 pose 가중치의 keypoint 정의가 사람 몸을 대상으로 하기 때문 |

"YOLO가 이미지를 이해한다"는 한 문장으로 세 결과를 뭉치지 마세요. 같은 패키지를 호출했어도 가중치와 head, 학습 라벨, 출력 자료형이 다릅니다.

### 학습은 어디에 끼어드는가

오늘 사용한 것은 **사전학습 추론**입니다. 이미 COCO 데이터로 학습된 가중치를 새 사진에 적용했습니다. 공장 결함이나 회사 고유 부품처럼 사전학습 클래스에 없는 대상을 계속 놓친다면, 권리가 확인된 이미지와 작업에 맞는 라벨을 모아 fine-tuning을 검토할 수 있습니다. 이번 실습에서는 학습을 실행하지 않고 이 판단 기준만 소개합니다.

**확장 · 학습 명령과 데이터 구조는 어떻게 달라질까**

| 방식 | 언제 생각하는가 | 필요한 것 |
| :--- | :--- | :--- |
| 사전학습 추론 | 기존 클래스와 출력이 업무에 맞음 | 입력과 실행 환경 |
| Fine-tuning | 같은 종류의 실패가 반복되고 회사 고유 대상이 있음 | 권리가 확인된 이미지, 일관된 라벨, train/val 분리 |
| From scratch | 기존 시각 특징까지 맞지 않는 특수 영역 | 매우 많은 데이터·연산·전문성 |

YOLO 학습용 데이터에는 이미지와 라벨뿐 아니라 `data.yaml`이 필요합니다. 여기에는 학습·검증 이미지 경로와 클래스 이름이 들어갑니다. Detection은 박스, segmentation은 다각형, pose는 keypoint 라벨이 필요하므로 작업을 바꾸면 라벨 비용도 바뀝니다.

시간이 남으면 코딩 에이전트에게 다음을 물어봅니다. 실제 학습 명령은 실행하지 않습니다.

```
Ultralytics YOLO detection fine-tuning을 가정해
data.yaml 예시, images/labels 폴더 구조,
학습 명령 한 줄을 보여 줘.

실행하지 말고 다음을 설명해 줘.
- train/val을 왜 분리하는지
- 기존 가중치에서 시작하는 이유
- 과적합을 어떻게 발견하는지
- 이미지와 라벨의 사용 권리를 왜 확인해야 하는지
- detection 라벨을 pose나 segmentation에 그대로 쓸 수 없는 이유
```

**실패를 결과로 남깁니다.**

- 로컬 가중치 없음: 새 다운로드나 다른 모델 전환 없이 오류를 기록합니다.
- CUDA·MPS 오류: CPU로 고정합니다.
- Pose 결과가 0건: 모델을 조용히 바꾸지 않고 입력과 임계값을 기록합니다.
- 마스크가 이상함: 탐지 박스와 나란히 저장해 어느 head에서 차이가 났는지 봅니다.
- 세 모델을 실행할 수 없음: `fallback/outputs/yolo/thresholds`의 0.15·0.25·0.60 결과를 읽는 모드로 전환합니다.
- 직접 추론 앱이 열리지 않음: 읽기 전용 fallback 모드로 다시 열고 비교를 계속합니다.

모든 실패는 `outputs/yolo/failure_log.md`에 남기고, 대체 결과를 쓰면 manifest에 `fallback_used=true`를 기록합니다. 최종 통과에는 직접 추론 모드와 읽기 전용 fallback 모드 중 하나가 실행되어야 합니다. 설치 성공 여부보다 중요한 것은 실패한 지점을 재현할 수 있게 남기는 것입니다.

### 가져다 쓴 모델의 사용 책임도 결과로 남깁니다

학교 출입 안전, 체육 자세 분석, 분리수거 품목 탐지, 과학실 안전 장비 확인 가운데 하나를 고르고, 필요하면 자신의 구체적인 상황으로 바꿉니다. 그런 다음 코딩 에이전트에게 `outputs/yolo/use_case_card.md`를 만들게 합니다. 답 자체는 사람이 정합니다.

```
아래 항목의 빈 양식만 outputs/yolo/use_case_card.md에 만들어 줘.
내 답을 추정하거나 대신 채우지 않는다.

- 탐지 목적과 영향을 받는 사람
- 촬영 대상의 고지·동의 방식
- 이미지와 위치 기록의 보관 장소·기간
- 가장 위험한 오탐과 미탐
- 사람이 검토하고 이의를 제기할 통로

outputs/tool_choice.md에 사진 업무의 선택 기준이 있으면 그대로 옮기고,
이번 결과에서 관찰한 내용과 선택을 유지하거나 바꿀 이유를 적을 빈칸도 만든다.
실험으로 판단할 수 없는 항목은 미확인으로 남긴다.
```

버스 예제의 결과가 잘 나온 것과 실제 사람을 촬영·판정해도 된다는 것은 전혀 다른 결론입니다. 이 카드는 앞에서 본 Joseph Redmon의 문제 제기를 실습의 선택 기준으로 되돌리는 장치입니다.

### 사진 실습 제출물

- detection·segmentation·pose 결과 이미지 각 1장
- 작업별 원시 JSON과 `summary.json`
- 모델명·패키지 버전·입력 해시·실행시간이 든 manifest
- 임계값 3개에서 관찰한 변화
- 직접 추론 또는 읽기 전용 fallback 모드로 실행되는 `apps/yolo/app.py`
- `outputs/yolo/use_case_card.md`
- 세 작업 중 업무 하나를 골라 "왜 이 자료형이 필요한가"를 설명한 두 문장

필수 제출을 마친 뒤 시간이 남으면 옆 사람 앱에 처음 보는 사진 한 장을 넣습니다. 보기 좋은 결과보다 처음 드러난 실패 하나를 발표합니다.
