# [4.AI는 문서와 사진에서 무엇을 꺼낼까?] - 5. AI와 도구 선택 상담하기

---

## 도구를 외우는 대신, AI를 활용해 선택하는 법을 익힙니다

새 모델과 서비스는 자주 나오고, 같은 이름 아래의 기능·가격·라이선스·데이터 처리 조건도 바뀝니다. OCR, 문서 VLM, 범용 멀티모달 모델, 탐지와 분할의 모든 제품을 외운 뒤 고르려 하면 공부가 끝나기 전에 목록이 낡습니다.

Wharton의 Ethan Mollick은 공개 벤치마크만으로는 어떤 AI가 내 일에 맞는지 알기 어렵고, 관련 새 모델이 나오면서 실제 업무 평가도 주기적으로 다시 해야 한다고 설명합니다([Giving your AI a Job Interview](https://www.oneusefulthing.org/p/giving-your-ai-a-job-interview)). 따라서 여기서 익힐 것은 제품 목록이 아니라 **내 일을 설명하고, 현재 후보를 찾고, 실제 자료로 선택을 갱신하는 과정**입니다.

AI는 이 과정에서 질문자와 조사원 역할을 맡습니다. 사람은 목적, 허용할 수 없는 실패, 데이터 반출 여부와 최종 책임을 결정합니다. 아래 프롬프트는 정답으로 인증된 표준 서식이 아니라, 이어서 소개할 연구와 실무 조언을 문서·사진 도구 선택에 적용한 예시입니다.

### 바로 추천받지 말고, 먼저 질문을 받습니다

Mollick은 AI에 충분한 맥락을 주고 원하는 결과를 분명히 하며, 한 번의 답으로 끝내지 말고 왕복 대화를 하라고 조언합니다. 요구사항을 아직 잘 모르면 AI가 질문하게 해도 좋다고 덧붙입니다([Using AI Right Now](https://www.oneusefulthing.org/p/using-ai-right-now-a-quick-guide)).

Vanderbilt의 Jules White 연구팀은 이처럼 AI가 목표 달성에 필요한 질문을 주도하는 방식을 **Flipped Interaction Pattern**으로 정리했습니다. 사용자는 달성할 목표와 질문을 멈출 조건을 알려 주고, 필요하면 질문을 한 번에 하나씩 하도록 지정합니다([Vanderbilt Prompt Patterns](https://www.vanderbilt.edu/generative-ai/prompt-patterns/), [[prompt-patterns-white2023.pdf|원 논문, "A Prompt Pattern Catalog to Enhance Prompt Engineering with ChatGPT," arXiv:2302.11382]]).

```
문서나 사진을 처리할 AI 도구를 고르려고 해.
도구를 추천하기 전에 내 업무와 제약을 이해하도록 질문해 줘.
추천에 필요한 정보가 충분해질 때까지 질문하고,
내가 답하기 쉽도록 한 번에 질문 하나만 해 줘.

내 답을 추정해서 채우지 말고 모르는 것은 미확인으로 남긴다.
질문이 끝나면 네가 이해한 요구사항, 가정한 것, 아직 모르는 것을
구분해 요약하고 내가 확인할 때까지 추천을 시작하지 않는다.
내가 '현재까지 요약해 줘'라고 하면 질문을 멈추고 같은 형식으로 요약한다.

상담 중에는 실제 기밀 파일이나 개인정보 업로드를 요구하지 않는다.
첫 질문을 시작해 줘.
```

### 질문에는 기술 이름이 아니라 업무로 답합니다

"최신 모델을 쓰고 싶다"보다 다음과 같은 업무 정보가 선택에 더 유용합니다. 아래 목록은 Flipped Interaction Pattern의 구성 요소가 아니라, 이 수업의 문서·사진 사례에서 AI에게 알려 줄 맥락의 예입니다.

- 무엇을 입력하고 어떤 형태의 결과를 받아야 하는가
- 잘 나온 예가 아니라 실제로 어려운 입력은 무엇인가
- 무엇을 놓치거나 잘못 만들었을 때 피해가 큰가
- 결과가 원문의 어느 위치에서 왔는지 근거를 남겨야 하는가
- 파일을 외부 서비스로 보내도 되는가
- 처리량, 기다릴 수 있는 시간, 예산과 실행 장치는 무엇인가
- 결과를 누가 검토하고 최종 승인하는가

모르는 조건은 AI가 대신 결정하게 하지 않고 **미확인**으로 둡니다. 외부 전송, 법적 의무, 사람에게 영향을 주는 자동 판정은 담당자가 확인합니다. 이 확인이 끝나기 전에는 공개되었거나 직접 만든 예시만 사용하고 실제 파일, 개인정보, 자격 증명과 내부 주소를 대화에 올리지 않습니다.

### 요구사항을 확인한 뒤 현재 후보를 조사합니다

도구가 자주 바뀌므로 기억에 의존한 추천은 쓰지 않습니다. OpenAI도 모델 답을 최종 출처가 아닌 초안으로 보고, 인용·수치·기술 정보와 외부 문서 참조를 직접 확인하라고 안내합니다([Does ChatGPT tell the truth?](https://help.openai.com/en/articles/8313428-does-chatgpt-tell-the-truth)). 이 원칙을 도구 조사에 적용해 다음처럼 요청할 수 있습니다.

```
내가 확인한 요구사항을 기준으로 오늘 선택할 수 있는 도구를 웹에서 조사해 줘.
기억에만 의존하지 말고 원 논문, 공식 문서와 저장소,
공식 가격·라이선스·데이터 처리 정책을 우선 확인한다.

먼저 내 필수 조건을 충족하지 못해 탈락하는 후보와 이유를 적고,
남은 후보만 비교 가능한 표로 정리한다.
각 후보에는 정확한 제품·모델·패키지 이름, 확인 날짜, 근거 URL,
지원하는 입력과 출력, 로컬·클라우드 실행 조건, 비용·라이선스·데이터 전송,
확인된 사실, 자료에서 한 추론, 아직 모르는 것을 적는다.

웹 검색이나 링크 열기가 불가능하면 조사한 것처럼 답하지 말고
무엇을 확인할 수 없는지 알려 줘.
```

검색할 수 없는 AI에는 이 교안의 '출처와 더 읽을거리'에서 공식 링크를 골라 붙인 뒤, "아래 링크만 읽고 같은 항목을 비교해 줘. 링크에서 확인할 수 없는 내용은 미확인으로 남겨 줘"라고 요청합니다.

AI가 링크를 붙였다는 사실만으로 검증이 끝나지는 않습니다. 링크를 직접 열어 실제 문구와 날짜를 확인합니다. 공식 문서의 "지원한다"는 내 자료에서 "잘된다"는 뜻이 아니므로 성능 판단은 실제 표본 시험으로 넘깁니다.

### 추천을 반박하고, 후보는 실제 과제로 시험합니다

먼저 추천의 논리를 검토합니다. AI는 사용자가 드러낸 견해에 지나치게 동의하는 **아첨 편향**(sycophancy)을 보일 수 있습니다. Anthropic 연구에서는 여러 AI assistant가 사용자의 견해에 맞추는 아첨 행동을 보였고, 인간 평가자와 선호 모델이 사용자의 견해와 일치하는 답을 더 선호하는 경향도 관찰됐습니다. 한쪽 이야기만 들은 개인 상담에서 과도하게 확신하는 답도 위험 사례로 다룹니다([[sycophancy-sharma2023.pdf|"Towards Understanding Sycophancy in Language Models," arXiv:2310.13548]], [개인 상담 연구, Stanford Report](https://news.stanford.edu/stories/2026/03/ai-advice-sycophantic-models-research) / [Science 원문](https://www.science.org/doi/10.1126/science.aec8352)).

```
이 추천을 결론으로 확정하지 말고 다시 검토해 줘.
- 어떤 가정 위에서 추천했는가
- 어떤 사실이 확인되면 추천이 뒤집히는가
- 가장 강한 다른 후보는 무엇이며 어떤 조건에서 더 나은가
- 실제 자료 없이 판단할 수 없는 것은 무엇인가

나의 선호에 맞추지 말고 확인된 사실, 추론, 미확인을 구분해 답해 줘.
```

그다음은 추천의 논리가 아니라 후보의 실제 출력을 시험합니다. Mollick은 공개 벤치마크에만 의존하지 말고 실제 업무와 닮은 과제를 만들고, 모델을 여러 번 실행해 비교하며, 결과를 판단할 수 있는 사람이 평가하라고 제안합니다. 모델마다 과제별 능력과 판단 성향이 다르고 새 모델이 계속 나오므로 이 평가를 주기적으로 반복해야 한다는 설명입니다([Giving your AI a Job Interview](https://www.oneusefulthing.org/p/giving-your-ai-a-job-interview)). AI에게 반론을 잘 쓰게 하는 것과 후보가 실제 자료에서 잘 작동하는지는 서로 다른 검증입니다.

### AI의 조언과 사람의 결정을 분리합니다

AI는 후보 조사, 빠진 조건 찾기와 비교 시험 초안을 도울 수 있습니다. 하지만 파일을 외부로 보낼지, 어떤 오류를 감수할지, 법률·보안 요구를 충족했는지, 사람에게 영향을 주는 결과를 자동 승인할지는 책임 있는 사람이 결정합니다.

NIST AI 위험관리 프레임워크도 조직이 사람과 AI의 역할·감독 책임을 구분하고, 시험·평가·검증 절차와 결과를 문서화하도록 제시합니다([NIST AI RMF Core](https://airc.nist.gov/airmf-resources/airmf/5-sec-core/)). 개인 상담용 절차를 제시하는 문서는 아니지만, AI의 추천과 사람의 책임을 구분해야 한다는 근거로 참고할 수 있습니다.

이 방법을 실제 업무에 적용할 때는 상담 결과를 `outputs/tool_choice.md`와 같은 기록으로 남길 수 있습니다. 파일명은 뒤 실습과 연결하기 위한 수업의 예이며, 인용한 연구가 정한 표준은 아닙니다.

```
지금까지 이 대화에서 확인된 내용만 사용해 Markdown 기록을 만들어 줘.
가능하면 outputs/tool_choice.md에 저장하고, 파일을 만들 수 없으면 본문만 출력한다.

- 조사한 업무와 자료
- 공식 근거를 확인한 후보
- 확인된 사실 / 추론 / 미확인
- AI가 판단할 수 없어 사람이 결정할 사항
- 실제 업무와 닮은 비교 자료와 평가 방법
- 선택을 다시 조사해야 할 변화나 실패

확인하지 않은 정책이나 기준을 추정하지 말고 [사람이 결정]으로 남긴다.
```

### 상담과 실제 시험을 나눠 진행합니다

여기서는 세 프롬프트가 맡는 역할과 순서를 익힙니다. 먼저 AI의 질문으로 요구사항을 분명히 하고, 그 요약을 사람이 확인한 뒤에만 현재 후보를 조사하며, 마지막으로 추천의 가정과 반대안을 검토합니다. 웹 조사와 `outputs/tool_choice.md` 작성, 추천된 후보의 직접 실행은 실제 선택이 필요할 때 이어서 진행합니다.

뒤의 PDF와 YOLO 실습에는 수업을 위해 고정한 도구가 등장합니다. 상담에서 추천받은 후보와 같다는 보장은 없으므로, 그 후보를 검증한다고 말하지 않습니다. 대신 원하는 출력, 남겨야 할 근거, 위험한 오류, 데이터 처리 방식처럼 상담에서 드러난 **평가 기준**을 고정 도구의 실제 출력에 적용해 보는 공통 예제로 사용합니다.

비교에는 잘 나온 자료만 고르지 않습니다. 문서라면 기울어짐·도장 겹침·복잡한 표를, 사진이라면 가림·역광·작은 대상을 포함합니다. 실제 추천 후보를 추가로 실행할 때도 한 번의 좋은 출력만 보고 결정하지 않고 같은 평가 기준으로 결과를 비교합니다.

최신 도구의 이름을 모두 외우는 것이 목표가 아닙니다. AI에게 내 일을 충분히 질문하게 하고, 현재 후보와 공식 근거를 조사하게 한 뒤, 추천받은 후보를 실제 업무와 닮은 과제로 평가하고 사람이 결정합니다. 도구가 바뀌면 같은 과정을 다시 적용하면 됩니다.

모든 학생이 이어지는 PDF 실습과 사진 실습을 모두 수행합니다. 처음 고른 업무와 가까운 실습에서는 자신의 선택 기준을 더 자세히 적용합니다. 수업에서 사용한 도구의 영구 순위를 정하는 활동은 아닙니다.
