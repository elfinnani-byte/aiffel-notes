## 같은 PDF를 네 가지 눈으로 읽기

이번 실습의 목표는 OCR 엔진을 직접 구현하는 것이 아닙니다. 이미 만들어진 기능을 코딩 에이전트에게 연결하게 하고, 같은 페이지가 도구에 따라 어떻게 다른 결과가 되는지 비교하는 것입니다.

비교할 네 갈래는 다음과 같습니다.

- **Tesseract**: 오래된 계보의 가벼운 로컬 OCR 기준선
- **PaddleOCR**: 탐지와 인식을 나눈 현대식 오픈소스 OCR 파이프라인
- **PaddleOCR-VL**: 표·수식·읽기 순서를 함께 복원하려는 문서 전용 VLM
- **Anthropic의 Claude 또는 OpenAI의 ChatGPT**: 문서 외의 질문도 처리하는 범용 멀티모달 모델

"어느 모델이 최고인가"를 세 페이지로 결론 내리지 않습니다. 각 도구가 어떤 자료형을 주고, 어떤 실패를 눈에 보이게 남기며, 데이터가 어디에서 처리되는지를 관찰합니다.

### 실습 흐름과 시작 조건

일반 OCR은 자연어 프롬프트를 받지 않습니다. 따라서 "모든 모델에 동일 프롬프트"라고 부르지 않고, **동일 입력과 동일 산출 계약**을 맞춥니다.

| 시간 | 사람이 정할 것 | AI에게 맡길 것 | 통과 조건 |
| :--- | :--- | :--- | :--- |
| 0~5분 | 입력 PDF와 필수 2쪽 확인 | 폴더·패키지·모델 캐시 점검 | 입력 해시와 페이지 PNG |
| 5~20분 | 한국어 모델과 출력 계약 | Tesseract·PaddleOCR 실행 | 텍스트, 좌표, 오버레이 |
| 20~35분 | 추정 금지 규칙 | PaddleOCR-VL과 범용 VLM 실행 | 페이지별 Markdown |
| 35~50분 | 기준값 6개 | 결과 비교표 생성 | exact·partial·missing·invented |
| 50~60분 | 화면에서 볼 항목 | 준비된 결과를 읽는 Gradio 화면 조립 | AI가 만들어준 코드 실행 및 정상 동작 |

수업 운영자는 학생이 설치부터 시작하지 않도록 다음을 사전에 확인합니다. 실습별 버전 기준 파일을 바탕으로 리허설한 환경을 고정합니다.

- Python 환경과 OCR용 `requirements-ocr.txt`
- Tesseract 5와 `kor`·`eng` 언어 데이터
- 한국어 PP-OCRv5 가중치와 PaddleOCR-VL-1.6 가중치 캐시
- 준비된 GPU 런타임(교내 GPU 또는 Colab)
- 각 경로를 한 번 실행해 본 교사용 결과

이 준비가 끝나지 않았다면 수업 중에 패키지를 즉흥적으로 업그레이드하지 않습니다. 실패 경로는 기록하고, 운영자가 사전 생성한 결과로 비교와 화면 제작부터 이어갑니다.

### 가상환경은 프로젝트마다 따로 쓰는 Python 도구 상자입니다

Python 패키지를 컴퓨터 전체에 한꺼번에 설치하면 한 실습에서 필요한 버전이 다른 실습을 망가뜨릴 수 있습니다. **가상환경**은 프로젝트 전용 폴더 안에 Python과 패키지를 따로 두어 이 충돌을 막습니다. 이번 수업에서 OCR용과 YOLO용 환경을 나눈 이유도 두 도구가 요구하는 패키지 조합이 다를 수 있기 때문입니다.

이 수업은 Astral이 개발하는 오픈소스 Python 환경·패키지 도구 [uv](https://docs.astral.sh/uv/pip/environments/)를 사용합니다. `uv venv`는 전용 환경을 만들고, `uv pip install -r ...`은 그 안에 정해진 패키지를 넣습니다. 이 두 설치 명령은 뜻만 알아두고 수업 중에는 실행하지 않습니다. 운영자가 `requirements-ocr.txt`와 `requirements-yolo.txt`로 환경을 미리 준비합니다.

`activate`는 현재 터미널의 `python`이 해당 도구 상자를 가리키게 하고, `deactivate`는 그 상태에서 나올 뿐 환경을 삭제하지 않습니다. 패키지가 없으면 새로 설치하지 않고 오류를 기록해 대체 결과로 넘어갑니다.

코딩 에이전트는 지시하지 않으면 익숙한 `pip`나 전역 설치를 선택할 수 있습니다. 환경과 관련된 일을 맡길 때는 다음 조건을 프롬프트에 붙입니다.

```
Python 환경을 다룰 때는 uv만 사용해 줘.
```

### 준비된 PDF와 도전 자료

기본 입력은 수업을 위해 직접 만든 3쪽짜리 이미지형 PDF입니다.

- **수업용 OCR 비교 PDF 내려받기** - 내려받은 파일을 적절한 폴더를 만들어 `input/day15_sample.pdf`로 저장합니다.
- 필수 1쪽: 정비 작업 지시서 - 항목·값과 합계표
- 필수 2쪽: 모의평가형 문제 - 두 단 편집, 수식, 선택지
- 확장 3쪽: 시설 점검표 - 병합 셀, 도장 겹침, 간단한 배치도

**수업용 OCR 비교 PDF**와 함께 참고할 실제 문서 예시:

- [현대자동차 메뉴얼](https://ownersmanual.hyundai.com/docview/download/pdf/47e8984a-e288-4b70-a0e8-517daa823e51/OM_FULL)
- [한국교육과정평가원 모의평가 문제 PDF 예시](https://cdn2.kice.re.kr/suneung27mo06/suneung27mo06_2.pdf)

공식 공개 링크라고 해서 재배포 권리까지 생기는 것은 아닙니다. 외부 자료는 원문 링크에서 개인별로 내려받아 수업 안에서만 사용하고, 저장소에는 복사본이나 잘라낸 페이지를 넣지 않습니다. 입력 파일명, 내려받은 날짜와 SHA-256만 실행 기록에 남깁니다.

### 첫 번째 명령: 로컬 OCR 두 종류를 연결합니다

실습파일이 있는 폴더에서 코딩 에이전트에게 아래 지시를 전달합니다.

```
현재 준비된 Python 환경과 uv를 사용해
현재 폴더에 있는 pdf 파일을 아래 내용대로 처리해 줘.

목표
- 두 페이지를 200 dpi PNG로 한 번만 변환하고 같은 PNG를 두 OCR에 넣는다.
- Tesseract 5의 kor+eng 모델을 사용한다.
- PaddleOCR에서는 한국어 지원 PP-OCRv5 인식 모델을 사용한다.
- 실제 선택된 탐지·인식 모델 이름을 기록한다.
```

채팅창에 "완료"라고 나온 것은 통과 조건이 아닙니다. 두 OCR의 원시 결과와 서로 다른 이름의 오버레이 파일을 직접 열어 확인합니다.

### 두 번째 명령: 문서 전용 VLM을 같은 입력에 붙입니다

이 수업의 기본 경로는 **PaddleOCR-VL-1.6 전체 파이프라인을 준비된 GPU 런타임에서 직접 실행하는 것**입니다. 교내 GPU나 Colab에서 모델을 실행할 수 있지만 호스팅 추론 API로 임의 전환하지 않습니다. 운영자는 공식 문서대로 환경을 미리 실행해 가중치를 캐시하고, 사용한 PaddleOCR·PaddlePaddle 버전을 잠급니다.

```
앞에서 만든 두 PNG 파일을
현재 설치된 PaddleOCR-VL-1.6 전체 문서 파싱 파이프라인으로 처리해 줘.

산출 계약
- 페이지별 Markdown으로 저장한다.
- 표는 Markdown 표 또는 구조화 JSON으로 보존한다.
- 수식은 가능한 경우 LaTeX로 보존한다.
- 읽을 수 없는 곳은 [UNCLEAR]로 표시한다.
- 원문에 없는 설명, 요약, 값 보정은 하지 않는다.
- 각 페이지를 ## Page N으로 구분한다.

원시 응답은 outputs/ocr/paddleocr_vl/raw/에 저장한다.
```

모델 구성요소 하나만 호출한 결과와 레이아웃 분석을 포함한 전체 파이프라인 결과는 같지 않을 수 있습니다. 실행 기록에는 반드시 "전체 파이프라인"인지 "구성요소 직접 호출"인지 적습니다.

### 세 번째 명령: Claude 또는 ChatGPT에 같은 계약을 줍니다

Claude는 Anthropic이, ChatGPT는 OpenAI가 제공하는 대화형 제품입니다. 둘 다 제품명 아래에서 실제 사용 모델과 전처리 방식이 바뀔 수 있고, 세부 내부 구조가 모두 공개되어 있지는 않습니다. 문서 전용 OCR에서 출발한 도구가 아니라 범용 언어 모델에 시각 입력 능력을 연결해 문서도 다루게 된 계열입니다.

둘 중 접근 가능한 **한 서비스만 필수**로 사용합니다. 다른 서비스까지의 비교는 확장 과제입니다. 새 대화에 동일한 두 페이지 PNG를 첨부하고 아래와 같이 지시합니다.

```
첨부한 두 페이지를 페이지별 Markdown으로 전사해 주세요.

규칙
1. 표는 행과 열 관계를 유지합니다.
2. 수식은 LaTeX로 적습니다.
3. 읽을 수 없는 곳은 [UNCLEAR]로 표시합니다.
4. 요약, 추정, 맞춤법 보정, 금액 재계산을 하지 않습니다.
5. 각 페이지는 ## Page N으로 구분합니다.
6. 마지막에 확실하지 않았던 위치만 페이지 번호와 함께 목록으로 적습니다.
```

응답 전체를 `outputs/ocr/general_vlm/result.md`에 저장합니다. `outputs/ocr/general_vlm/run_info.json`에는 서비스명, 화면에 표시된 모델명, 실행일, 입력 파일명과 프롬프트를 적습니다. 앱의 비공개 전처리를 완전히 고정할 수 없으므로 이것은 정밀 벤치마크가 아니라 출력 성격을 관찰하는 비교입니다.

### 네 번째 명령: 기준값과 대조해 표로 모읍니다

네 갈래의 필수 결과가 생기면 코딩 에이전트에게 지시합니다.

```
outputs/ocr 아래의 Tesseract, PaddleOCR, PaddleOCR-VL,
general_vlm 결과를 읽고 outputs/ocr/comparison.md를 만들어 줘.
실패해 outputs에 없는 경로만 fallback/outputs/ocr의 같은 경로에서 읽고,
해당 열과 run_manifest에 fallback_used=true를 표시한다.

아래 기준값 6개를 행으로 두고 도구별 결과를 열로 둔다.
원문을 보고 정답을 다시 만들지 말고 제공된 기준값만 사용한다.
exact, partial, missing, invented, unclear 중 하나로 표시한다.

기준값
1. 문서번호: WO-2026-0715
2. 차량번호: 12가 3456
3. 작업 행: 엔진오일 교환 68,000 / 오일필터 교환 15,000 /
   안전 점검 20,000
4. 공급가액 103,000 / 부가세 10,300 / 합계 113,300
5. 2쪽 읽기 순서: 왼쪽 설명과 F = ma를 읽은 뒤 오른쪽 12번 문항
6. 수식 F = ma / 선택한 답 ③

각 판정 옆에는 원문 페이지와 출력 파일 경로를 적는다.
처리시간과 로컬/외부 전송 여부도 마지막 표에 추가한다.
3쪽 확인점은 extension 섹션으로 분리한다.

outputs/tool_choice.md에 문서 업무의 선택 기준이 있으면
'상담 기준으로 다시 보기' 섹션을 추가한다.
기준마다 이번 출력에서 관찰한 결과와 선택을 유지하거나 바꿀 이유를 적고,
실험으로 판단할 수 없는 항목은 미확인으로 남긴다.
```

기준값이 있으므로 "그럴듯해 보인다"가 아니라 무엇이 달라졌는지를 같은 자로 비교할 수 있습니다.

**결과를 볼 때 묻는 네 가지**

| 질문 | 확인 방법 |
| :--- | :--- |
| 글자를 얼마나 보존했는가 | 숫자·기호·띄어쓰기와 `[UNCLEAR]` 위치를 원문과 대조 |
| 구조를 얼마나 보존했는가 | 표 행 정렬, 두 단 읽기 순서, 병합 셀 관계 확인 |
| 근거를 되짚을 수 있는가 | 페이지·좌표·원시 결과에서 출처를 찾을 수 있는지 확인 |
| 모델이 빈자리를 메웠는가 | 원문에 없는 요약·단위·재계산 값이 생겼는지 확인 |

한 도구가 모든 열에서 이길 필요는 없습니다. Tesseract가 좌표와 빠른 로컬 실행에서 유리하고, PaddleOCR가 한국어 글자 영역에서 더 안정적이며, 문서 VLM이 표·수식 구조를 더 잘 보존하고, 범용 VLM이 질문 대응에서 편할 수 있습니다. 실제 결과가 이 예상과 다르면 예상이 아니라 결과를 기록합니다.

### 5분 안에 첫 결과가 안 나오면

수업 중 설치와 다운로드가 학습 목표를 삼키지 않도록 경로별 제한을 둡니다.

- **로컬 OCR 의존성 없음**: 오류를 기록하고 `fallback/outputs/ocr/tesseract` 또는 `paddleocr` 결과를 사용합니다.
- **PaddleOCR-VL GPU·가중치 문제**: 5분 뒤 중단하고 `fallback/outputs/ocr/paddleocr_vl`의 동일 입력 결과를 사용합니다.
- **Claude·ChatGPT 접근 불가**: `fallback/outputs/ocr/general_vlm`의 모델명·실행일이 포함된 결과를 사용합니다.
- **교사용 결과도 없음**: 그 경로를 `not_run`으로 표시하고 나머지 결과로 화면 제작을 계속합니다.

대체 결과 사용은 실패가 아닙니다. 사용 사실을 숨기거나 다른 모델로 조용히 바꾸는 것이 문제입니다. 운영자는 수업 전 리허설 결과를 `fallback/outputs` 구조로 배포하고, 학생은 비교표와 manifest에 `fallback_used=true`를 남깁니다.

### 10분 제작: 네 결과를 한 화면에 놓습니다

필수 비교표가 완성되면 코딩 에이전트에게 다음 기능의 Gradio 앱을 만들게 합니다.

```
기존 outputs를 읽어 한 화면에서 비교하는 Gradio 앱을 만들어 줘.
새 모델 추론은 하지 않는다.

- 왼쪽: 원본 페이지 이미지
- 오른쪽 탭: Tesseract / PaddleOCR / PaddleOCR-VL / General VLM
- 좌표가 있는 결과는 원본 위에 박스를 겹쳐 표시
- Markdown 결과는 페이지별로 표시
- 기준값 6개의 판정을 표로 표시
- 비교표 CSV 다운로드 버튼
- 사용 모델, 버전, 로컬/외부 전송 여부 표시
- outputs에 없는 경로는 fallback/outputs의 같은 경로에서 읽고 대체 결과라고 표시

앱은 apps/ocr/app.py에 만들고,
.venv-day15-ocr/bin/python apps/ocr/app.py로 실행되게 한다.
apps/ocr/README.md에 같은 실행 명령을 적어 줘.
```

Gradio는 현재 Hugging Face 생태계에서 개발되는 오픈소스 Python UI 도구로, 입력·출력 컴포넌트를 준비해 둡니다. 화면 프레임워크를 처음부터 만드는 대신 모델 결과를 연결하는 데 집중할 수 있어 이번 바이브코딩 실습에 적합합니다.

**비교가 공정하려면**

- 네 경로에 같은 원본에서 만든 같은 페이지 PNG를 사용합니다.
- OCR에는 프롬프트가 없으므로 동일 프롬프트가 아니라 동일 산출 계약을 맞춥니다.
- 앱 화면과 API 결과를 한 숫자로 섞어 "모델 성능"이라고 부르지 않습니다.
- 모델 이름, 실행일, 전처리와 원본 해시를 기록합니다.
- 세 페이지 결과로 전체 제품 순위를 단정하지 않습니다.

이 조건을 지켜도 각 서비스의 비공개 전처리 차이는 남습니다. 그래서 결과표의 제목은 "정확도 순위"가 아니라 "이 입력에서 관찰한 차이"입니다.

### 확장: 짝과 바꿔 보는 어려운 한 페이지

다른 사람이 고른 자동차 설명서나 모의평가 페이지 한 장을 받아 네 결과 중 두 경로만 다시 실행합니다. 도구를 더 많이 돌리는 것이 목적이 아니라, 기본 PDF에서 보이지 않았던 실패를 찾는 것이 목적입니다.

다음 중 하나를 고릅니다.

- 작은 각주와 여러 단으로 된 페이지
- 셀 병합이 있는 정비 주기표
- 수식과 그래프가 함께 있는 문제
- 사진 위에 라벨과 화살표가 겹친 페이지

새 페이지에서 처음 나타난 실패를 `new_failure.md`에 한 문장으로 적고, 어느 기술 단계와 관련 있는지 추정합니다. 예: "PaddleOCR 글자는 읽었지만 열 순서를 섞음 - 인식보다 레이아웃 조립 문제로 보임."

**데이터가 어디로 갔는지도 결과입니다**

| 경로 | 기본 실행 위치 | 확인할 것 |
| :--- | :--- | :--- |
| Tesseract | 로컬 | 실행 위치 파일과 라이선스 |
| PaddleOCR | 로컬 실행 가능 | 모델 다운로드 출처, 선택한 가중치 |
| PaddleOCR-VL | 로컬·호스팅 경로가 모두 가능 | 실제 사용 경로, GPU·토큰·서버 위치 |
| Claude·ChatGPT | 앱 외부 서비스 | 업로드 가능한 자료인지, 보존·학습 설정과 조직 정책 |

공개 모델이라는 말은 데이터가 자동으로 로컬에서 처리된다는 뜻이 아닙니다. 호스팅 API를 호출했다면 외부 전송입니다. 반대로 상용 서비스라고 해서 모든 조직의 데이터 정책이 같은 것도 아닙니다. 수업에서는 공개 자료만 사용하고, 업무 자료에는 조직의 계약과 정책을 먼저 적용합니다.

### 문서 실습 체크포인트

다음 파일이 실제로 존재하면 문서 실습을 마칩니다.

- 동일한 1~2쪽 PNG와 입력 SHA-256
- Tesseract와 PaddleOCR의 원시 결과·텍스트·좌표 시각화
- PaddleOCR-VL의 원시 결과와 페이지별 Markdown
- Claude 또는 ChatGPT의 결과와 표시 모델·실행일
- 기준값 6개의 `comparison.md`
- 실패 또는 `[UNCLEAR]` 사례 한 가지
- 데이터가 로컬에 남았는지 외부로 나갔는지 기록
- 기존 결과를 읽는 Gradio 비교 화면

결과가 좋았다는 감상 대신, "어떤 출력이 어떤 다음 작업에 바로 연결되는가"를 한 문장으로 적습니다.

**되돌아보기**

- OCR 엔진이 좌표를 주는데도 문서 VLM이 필요한 경우는 언제였나요?
- 문서 VLM이 표를 잘 복원했는데도 전용 OCR 좌표를 함께 보존할 이유는 무엇인가요?
- Claude·ChatGPT의 답이 가장 읽기 편했다면, 그 편리함과 함께 관리해야 할 것은 무엇인가요?

답은 도구 이름이 아니라 입력, 출력 자료형, 근거와 실패 조건으로 적습니다.

### 제출할 문서 비교 결과
