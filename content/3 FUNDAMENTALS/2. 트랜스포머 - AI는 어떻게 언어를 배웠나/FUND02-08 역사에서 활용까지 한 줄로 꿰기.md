## 역사에서 활용까지 한 줄로 꿰기

오늘 우리는 긴 역사를 한 문장으로 접어 넣을 수 있게 되었습니다. CNN과 초기 언어 모델이 각자의 벽에 부딪혔고, 그 벽을 넘기 위해 어텐션이 나왔고, 어텐션으로 쌓은 트랜스포머가 거대 언어 모델을 낳았으며, 바로 그 어텐션 구조가 토큰과 컨텍스트라는 비용과 한계를 만들었습니다. 그래서 활용가의 일은 더 긴 입력을 넣는 것이 아니라, 필요한 문맥을 검토 가능한 구조로 배치하는 것입니다.

수식 없이 보았다고 얕게 본 것은 아닙니다. 활용가에게 필요한 핵심은 모델 내부의 모든 계산을 재현하는 것이 아니라, 왜 입력 설계가 답의 품질과 비용을 좌우하는지 설명할 수 있는 것입니다. 어텐션이 왜 토큰 수의 제곱에 가까운 비용을 만드는지, 왜 중요한 정보가 중간에 묻히면 놓치기 쉬운지 말할 수 있다면, 그 사람은 코딩 에이전트가 만든 구조를 판단할 수 있습니다.

### ⚠️ 활용가가 기억할 한계

트랜스포머는 문맥을 보는 구조지만, 그것이 사실 확인 능력이나 책임 판단을 보장하지는 않습니다. 긴 컨텍스트에 공식 문서를 넣어도 모델이 잘못 인용할 수 있고, 근거가 서로 충돌하면 그럴듯한 절충안을 만들 수 있습니다. 그래서 컨텍스트 설계에는 항상 검증 장치가 붙어야 합니다.

| 한계 | 대응 |
| :--- | :--- |
| 긴 문서 중 일부를 놓칠 수 있습니다 | 결론마다 근거 위치를 요구하고 샘플을 검수합니다 |
| 토큰 비용이 누적됩니다 | 입력과 출력 예산표를 만들고 반복 지시를 압축합니다 |
| 요약이 근거를 삭제할 수 있습니다 | 위험 정보는 원문 링크나 ID를 보존합니다 |
| 모델별 토큰화가 다릅니다 | 사용하는 모델의 공식 문서와 도구로 확인합니다 |

### 🎯 핵심 정리

| 오늘의 질문 | 가져갈 판단 |
| :--- | :--- |
| 트랜스포머를 왜 알아야 하나 | AI가 문맥을 어떻게 참고하는지 알아야 입력 설계와 실패 원인을 설명할 수 있습니다 |
| 토큰은 왜 중요한가 | 비용과 지연, 컨텍스트 한계가 글자 수보다 토큰 수에 가깝게 움직입니다 |
| 어텐션은 왜 비용이 되나 | 모든 토큰이 서로를 참고하므로 계산이 토큰 수의 제곱에 가깝게 늘어납니다 |
| 컨텍스트 윈도우는 무엇인가 | 한 번에 펼치는 작업대이며, 크기보다 배치와 선별이 중요합니다 |
| 활용가의 역할은 무엇인가 | 코딩 에이전트가 만든 구조에서 토큰 예산, 근거 보존, 위험한 압축을 판단합니다 |

한 문장으로 닫습니다.

> 토큰은 비용을 만들고, 컨텍스트는 한계를 만듭니다. 트랜스포머를 잘 쓰는 일은 더 긴 입력을 넣는 일이 아니라, 필요한 문맥을 검토 가능한 구조로 배치하는 일입니다.

### 🤔 오늘의 회고

자기 노트에 세 줄로 남깁니다.

- **머리**: 트랜스포머 구조가 왜 곧 비용과 한계가 되는지, 어제와 달라진 관점을 한 문장으로 적어 봅니다.
- **손**: 오늘 만든 토큰 예산표와 컨텍스트 설계 캔버스에서 가장 중요한 칸은 무엇이었는지 적어 봅니다.
- **마음**: 내 도메인에서 "비용을 줄이자"는 제안을 받았을 때, 어떤 근거만은 지키겠다고 마음먹었는지 적어 봅니다.
