# [7.[프로젝트] 공간을 다루는 AI] - 8. [과제] 공개할 수 있는 공간을 골라 올립니다

## 공개할 수 있는 공간을 골라 올립니다

주소에 올라간 것이 자기 방이면 링크를 보낼 때마다 한 번씩 망설이게 됩니다. 과제는 그 망설임이 없는 것을 하나 만드는 일입니다. **밖에서 공간을 하나 골라 같은 길로 올리고, 주소를 제출합니다.** 페이지는 이미 있으니 새로 만들 것이 없습니다. 바뀌는 것은 찍는 자리와, 그 자리를 고르는 판단입니다.

걸음은 넷입니다. 손이 많이 가는 자리는 전부 앞에서 한 번씩 지나온 곳이라, 새로 배울 것은 첫 걸음 하나뿐입니다.

### 1단계, 찍어도 되는 곳을 고릅니다

두 조건을 동시에 만족하는 곳을 찾아야 합니다. **남에게 보여도 되는 곳**이면서 **시차가 쌓이는 곳**입니다. 서로 다른 조건이라 하나만 맞으면 과제가 안 끝납니다.

**남에게 보여도 되는 곳.** 결과는 주소를 아는 사람이면 누구나 여는 자리에 올라갑니다. 그러니 화면에 들어오면 곤란한 것부터 셉니다. 지나가는 사람의 얼굴, 세워 둔 차의 번호판, 현관의 문패와 호수, 가게 안 손님, 책상 위 서류가 그렇습니다. **사람이 프레임에 들어오면 그 사람이 그대로 올라간다고 보면 됩니다.** 그리고 사유지와 상업 시설 중에는 촬영을 제한하는 곳이 있습니다. 미술관과 공연장, 일부 매장이 그렇고, 안내판이 붙어 있거나 직원에게 물으면 답을 줍니다. 물어서 안 된다고 하면 다른 데로 가면 됩니다. 회사 건물 안이라면 보안 규정을 먼저 보십시오.

**시차가 쌓이는 곳.** 방이 잘 나왔던 이유가 그대로 기준이 됩니다. 벽과 물건이 가까이 있어서 몇 걸음만 옮겨도 화면이 크게 밀렸고, 무늬가 넘쳐서 두 장에서 같은 지점을 알아볼 수 있었습니다. 전망대에서 먼 풍경을 찍으면 이 둘이 한꺼번에 사라집니다. 몇 걸음 옮겨도 산은 그 자리에 있어서 밀린 양이 안 생기고, 밀린 양이 없으면 거리도 안 나옵니다. **둘레를 돌 수 있는 것이나 안쪽이 감싸인 자리**를 고르십시오.

밖에서 새로 생기는 함정은 둘입니다. **하나는 움직이는 것입니다.** 사람이 지나가고 나뭇잎이 흔들리고 물이 흐르면 두 장에서 같은 지점을 찾는 계산이 그 자리에서 어긋납니다. 사람이 적은 시간을 고르고, 바람 부는 날 나무 앞은 피하는 편이 낫습니다. **다른 하나는 빛입니다.** 해를 마주 보고 서면 화면이 하얗게 날아가고, 날아간 자리에는 무늬가 남지 않습니다. 해를 등지고 도는 편이 낫고 흐린 날이 오히려 고르게 나옵니다.

| 고를 만한 곳 | 왜 나오나 | 조심할 것 |
| :--- | :--- | :--- |
| 공원의 조형물이나 정자 | 둘레를 한 바퀴 돌 수 있어 시차가 크게 쌓입니다 | 받침에 새겨진 이름, 옆 벤치의 사람 |
| 벽화나 간판이 있는 좁은 골목 | 벽이 가까워 몇 걸음에 크게 밀리고 무늬가 많습니다 | 주택가면 문패와 호수가 들어옵니다 |
| 야외 계단참과 난간 | 형태가 뚜렷하고 그늘과 빛이 갈려 무늬가 삽니다 | 오르내리는 사람 |
| 열려 있는 로비나 통로 | 실내라 빛이 고르고 벽이 가깝습니다 | 촬영 정책과 사람 |

매끈한 유리벽, 잔잔한 물, 하늘, 고르게 깔린 잔디는 어느 곳에서든 안 나오는 자리입니다. 잡을 무늬가 없어서 같은 지점을 못 찾습니다.

### 2단계, 찍어서 알갱이 파일까지 만듭니다

찍는 규칙은 그대로입니다. **걸어 다니면서 십오 초에서 이십 초, 천천히, 1080p.** 대상 하나를 골랐으면 그 둘레를 한 바퀴 돌고, 감싸인 자리라면 안에서 크게 원을 그리며 걷습니다.

그다음은 앞에서 쓴 노트를 처음부터 다시 돌리면 끝납니다. 프레임 스물네 장을 뽑고, 점을 만들고, 남은 칸을 채워 알갱이 `.ply` 를 얻습니다. **판정하는 자리도 그대로입니다.** 카메라가 퍼진 정도가 0.1 아래로 나오면 화면을 열어 볼 것도 없이 몇 걸음 더 옮겨 다니며 다시 찍는 것이 가장 빠른 길입니다.

### 3단계, 형식 셋으로 뽑아 견줍니다

> 내 스플랫 `.ply` 를 형식 셋으로 각각 변환하고 비교표를 만들어 주세요.
>
> - `npx -y @playcanvas/splat-transform@latest` 를 씁니다. 설치는 하지 않습니다. 다시 돌릴 일이 많으니 `-w` 를 붙여 덮어쓰게 해 주세요.
> - `.compressed.ply` 와 `.sog` 와 `.spz` 셋으로 각각 변환해 주세요.
> - 형식마다 **파일 크기(바이트), 변환에 걸린 시간, 알갱이 개수**를 표로 뽑고, **파일 크기를 알갱이 개수로 나눈 값**을 한 칸 더 넣어 주세요.
> - 앞서 만든 페이지가 **파일을 화면에 끌어다 놓으면 그것으로 다시 그리게** 고쳐 주세요. 확장자를 형식 이름으로 옮기는 대응표가 셋 다 있어야 합니다.

세 파일에서 **알갱이 개수가 같아야 합니다.** 다르면 형식을 바꾼 것이 아니라 솎아 낸 파일과 바꿔 든 것입니다.

### 4단계, 저장소에 올리고 주소를 제출합니다

파일 둘을 올리고 Pages를 켜는 순서는 앞에서 한 그대로입니다. 저장소를 새로 하나 만들어도 되고, 이미 있는 저장소에 폴더를 하나 더 두어도 됩니다. **올릴 것은 줄인 파일입니다.** 100MiB를 넘는 파일은 애초에 안 올라갑니다.

```
my-open-space/
├── index.html       앞에서 만든 페이지 그대로
├── scene.sog        줄인 알갱이 파일
├── README.md        아래 양식
└── shots/
    └── viewer.png   화면을 갈무리한 것 한 장
```

README 양식입니다. 복사해 채우면 됩니다.

```markdown
# 고른 공간

## 주소
https://아이디.github.io/저장소이름/

## 어디를 골랐나
- 어떤 곳인지 한두 줄
- 공개해도 되는 곳이라고 판단한 근거

## 어떻게 찍었나
- 길이 OO초, 1080p, 뽑은 장수 24장
- 카메라가 퍼진 정도 O.OO (0.1이 기준선)
- 나온 점 OOO만 개

## 형식별로 잰 값
| 형식 | 파일 크기 | 알갱이 개수 | 알갱이당 바이트 |
|---|---|---|---|
| .ply | | | |
| .compressed.ply | | | |
| .sog | | | |
| .spz | | | |

## 폰에서 첫 화면까지
- 내 폰 O초, 남의 폰 O초

## 안 나온 자리
- 검은 얼룩이 남은 곳과 그 이유
```

제출은 두 줄입니다. **Pages 주소 한 줄과 저장소 주소 한 줄.** 보내기 전에 주소 뒤에 `/scene.sog` 를 붙여 파일이 직접 내려오는지 확인하십시오. 페이지는 떠도 파일이 안 내려오면 화면이 빕니다.

### 무엇을 보고 채점하나

셋을 봅니다.

**하나, 주소가 열리고 남에게 보낼 수 있는가.** 링크를 받은 사람의 폰에서 화면이 뜨는지를 먼저 보고, 그 화면에 남의 얼굴이나 문패가 안 들어갔는지를 그다음에 봅니다. 그 곳을 고른 근거가 README에 한 줄 있어야 합니다.

**둘, 눈이 아니라 숫자로 판정했는가.** 카메라가 퍼진 정도, 알갱이당 바이트, 형식별 크기와 알갱이 개수가 README에 적혀 있어야 합니다. `.ply` 를 알갱이 개수로 나눈 값이 68이면 각도별 색이 비어 있는 것이고, 재서 채운 파일은 그것이 정상입니다.

**셋, 안 나온 자리를 설명할 수 있는가.** 검은 얼룩이 왜 거기 남았는지, 앞뒤가 뒤집힌다면 무엇이 어긋난 것인지를 시차와 정렬 순서 같은 낱말로 적으면 됩니다.

**끝까지 못 가도 괜찮습니다.** 주소에 이미 올라간 것은 여기서 무엇이 안 되든 그대로 남습니다. 어디서 왜 막혔는지를 설명할 수 있으면 그것으로 충분합니다.
