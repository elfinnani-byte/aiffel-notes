# [6.여러 입력을 처리하는 모델들] - 4. 내 노트북에서 돌아가는 것 고르기

## 내 노트북에서 돌아가는 것 고르기

계보는 여기까지입니다. 이제 실무로 내려오겠습니다.

### 한국어에서는 작은 모델을 못 씁니다

앞 절 마지막에 이름을 기억해 두라고 한 **Whisper**는 크기를 여러 가지로 내놓았습니다. 작은 것부터 tiny, base, small, medium, large 순이고 뒤로 갈수록 정확한 대신 무겁습니다. **어느 크기를 고르느냐가 한국어에서는 특히 크게 갈립니다.**

크기마다 무게와 정확도가 어떻게 갈리는지 한 표에 모았습니다.

| 크기 | 파라미터 | 내려받기 용량 | 돌릴 때 쓰는 메모리 | 한국어 글자 오류율 |
| :--- | :--- | :--- | :--- | :--- |
| tiny | 3,900만 | 78MB | 0.7GB | 36.6% |
| base | 7,400만 | 148MB | 0.9GB | 40.6% |
| small | 2억 4,400만 | 486MB | 1.4GB | 17.5% |
| medium | 7억 6,900만 | 1.5GB | 2.4GB | 13.9% |
| large-v3 | 15억 5,000만 | 3.1GB | 3.8GB | 8.0% |
| large-v3의 빠른 판(turbo) | 8억 900만 | 1.6GB | 미측정 | 10.8% |

숫자를 어떻게 읽어야 하는지 세 가지만 짚겠습니다.

**내려받기 용량은 8비트로 줄인 판본 기준입니다.** 8비트로 줄인다는 것은 계산에 쓰는 숫자의 자릿수를 깎아 메모리와 시간을 아끼는 것입니다. 정확도를 조금 내주고 무게를 크게 덜어냅니다. 원본은 이보다 두 배 넘게 큽니다. 오늘 쓰는 도구가 8비트 판본을 받아 오므로 표의 값이 실제로 디스크에 쌓이는 양입니다.

**여러분 노트북에 무엇이 들어가는지는 이렇게 보십시오.** 운영체제와 브라우저가 이미 몇 GB를 쓰고 있다는 것을 감안해야 합니다. 램 8GB면 small까지가 편하고 medium은 다른 프로그램을 닫아야 돌아갑니다. 16GB면 medium이 편하고 large-v3도 됩니다. large-v3는 무게보다 **시간**이 먼저 걸립니다. 뒤에 나오는 실측에서 보시게 됩니다.

> 📚 파라미터 수는 ["Whisper," GitHub](https://github.com/openai/whisper)의 크기별 표에서, 내려받기 용량은 [faster-whisper 모델 저장소, Hugging Face](https://huggingface.co/Systran)에 올라온 실제 파일 크기에서 가져왔습니다. turbo는 다른 곳에서 배포됩니다.

이제 오류율 쪽을 보겠습니다. **tiny와 base는 한국어에서 쓸 수 없습니다.** 열 글자에 네 글자가 틀리면 받아쓰기가 아니라 소설입니다. 영어 예제에서 흔히 보이는 크기라 그대로 따라 하면 첫 실습부터 좌절합니다.

**빠른 판을 보십시오.** large-v3를 빠르게 만든 것인데 한국어 오류율은 오히려 커졌습니다. 속도를 얻으면 무엇을 내주는지가 이 한 줄에 있습니다.

> 📚 오류율은 한국어 여덟 개 시험 자료로 잰 것이고, [whisper-medium-komixv2 모델 카드, Hugging Face](https://huggingface.co/seastar105/whisper-medium-komixv2)에 측정 조건과 함께 실려 있습니다.

그리고 표에 없는 한 줄이 더 있습니다. 같은 자료로 잰 값 중에 **한국어로 다시 학습한 base가 8.7%** 입니다. 파라미터 7,400만짜리가, 스무 배 넘게 큰 large-v3의 8.0%에 거의 붙었습니다. 내려받기 148MB짜리가 3.1GB짜리와 비슷한 성적을 낸 것입니다. 크기보다 **그 언어를 봤느냐**가 먼저입니다.

### 숫자를 볼 때 단위를 먼저 확인하십시오

같은 모델, 같은 한국어 자료인데 어떤 문서는 3%대라 하고 어떤 문서는 14%대라고 합니다. 네 배 넘게 차이 나는데 둘 다 맞습니다. **글자 단위로 셌느냐 단어 단위로 셌느냐**의 차이입니다.

한국어는 띄어쓰기가 유연해서 단어 단위로 세면 실제보다 나빠 보입니다. "할 수 있다"를 "할수있다"로 받아쓰면 내용은 맞는데 단어 기준으로는 전부 오답이 됩니다. 그래서 한국어는 **글자 단위**로 보는 것이 맞습니다. 한국어 음성 인식 결과를 모아 놓은 곳들도 같은 이유를 들어 글자 단위를 씁니다.

어떤 도구가 "한국어 정확도 97%"라고 광고하면 무엇을 기준으로 센 것인지부터 물어보십시오.

### 내 노트북에서 돌아갈까

가장 궁금하실 부분입니다. 사양별로 정리했습니다. 표의 시간은 **1시간짜리 녹음 하나를 처리하는 데 걸리는 시간**입니다.

| 내 컴퓨터 | 쓸 수 있는 것 | 1시간 녹음 처리 | 비고 |
| :--- | :--- | :--- | :--- |
| 그래픽카드 없는 윈도우 노트북 | small 크기, 8비트로 줄여서 | 8분 남짓 | 한국어 오류율 17.5%라 초안용 |
| 애플 실리콘 | small은 편하게, large는 무리 | small 6분 / large 85분 | 아래 35분 실측을 1시간으로 환산(첫 내려받기 포함) |
| 외장 그래픽카드(VRAM 6GB 이상) | medium까지 편하게 | 5분 안팎 | 8비트로 줄이면 3GB에도 들어감 |
| 무료 코랩 | large-v3까지 | 10분 안팎 | 브라우저에서 남의 GPU를 빌려 쓴다. 세션이 끊기면 처음부터 |

표의 **VRAM**은 그래픽카드가 가진 자기 메모리입니다. 모델이 여기에 다 들어가야 빨라집니다.

**애플 실리콘 실측이 특히 참고할 만합니다.** 한국어 회의 녹음 35분 45초를 여러 크기로 돌려 본 기록이 있습니다.

| 모델 | 걸린 시간 |
| :--- | :--- |
| small | 3분 28초 |
| turbo(large의 빠른 판) | 10분 43초 |
| medium | 11분 11초 |
| large-v3 | **50분 41초** |

turbo가 small보다 느린 것이 이상해 보일 수 있는데, **turbo는 small의 빠른 판이 아니라 large의 빠른 판**입니다. large-v3가 50분 걸리던 것을 10분으로 줄인 것이지 small보다 빠른 것이 아닙니다.

large-v3는 35분짜리를 처리하는 데 50분이 걸렸습니다. 다만 이 값에는 모델을 처음 내려받는 시간이 함께 들어 있습니다. 순수 계산만 따지면 녹음 길이와 비슷한 수준입니다. 어느 쪽이든 수업 중에 돌릴 물건은 아닙니다.

중간 크기를 고를 때는 이름만 보고 정하지 마십시오. 빠른 판으로 나온 것들이 있는데, 속도는 확실히 빠르지만 **한국어 정확도는 모델마다 제각각**입니다. 앞의 한국어 오류율 표를 보면 어떤 빠른 판은 large-v3보다 오류가 눈에 띄게 큽니다. 속도를 얻는 대신 무엇을 내주는지는 여러분 자료로 직접 재 봐야 압니다.

**설치는 한 줄입니다.**

```bash
pip install faster-whisper
```

파이썬은 **3.11 이상**을 쓰십시오. 딸려 오는 실행 라이브러리가 3.11부터 지원합니다. 코랩은 이미 조건을 만족합니다.

이름에서 짐작하셨겠지만 **앞에서 본 그 모델을 더 빠르게 돌려 주는 구현**입니다. 모델은 같고 실행하는 쪽을 다시 만든 것입니다. 이 도구를 고른 이유가 있습니다. 음성을 다루는 도구는 대개 `ffmpeg`이라는 별도 프로그램을 먼저 깔아야 하는데, 윈도우에서 이게 만만치 않습니다. 경로를 잡아 주다가 첫 단계에서 포기하는 분이 실제로 많습니다.

`faster-whisper`는 그게 필요 없습니다. 오디오를 읽는 기능이 안에 들어 있습니다. 속도도 준수한 편인데, 어느 도구가 가장 빠른지는 기기에 따라 달라지니 필요하면 직접 재 보십시오.

> 📚 [faster-whisper, GitHub](https://github.com/SYSTRAN/faster-whisper)에 구현별 속도 비교가 있습니다.
