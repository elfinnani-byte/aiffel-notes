# [5.[프로젝트] 이미지 생성 어플리케이션 만들기] - 3. 브라우저만으로 첫 장을 뽑습니다

## 브라우저만으로 첫 장을 뽑습니다

설치도 결제도 없이 시작하겠습니다. 그래픽카드가 없어도 되고, 맥이든 윈도우든 상관없습니다.

허깅페이스(Hugging Face)는 머신러닝 모델과 데이터를 공유하는 곳인데, 여기에는 모델을 바로 써 볼 수 있는 데모 페이지를 올릴 수 있습니다. 이런 데모를 **Space**라고 부릅니다. 그중 일부는 허깅페이스가 GPU를 대 주는 방식으로 돌아가고, 그래서 **여러분 컴퓨터의 성능과 무관하게** 결과가 나옵니다.

> 🖼 [FLUX.2-klein 4B 데모, Hugging Face Spaces](https://huggingface.co/spaces/black-forest-labs/FLUX.2-klein-4B)를 열어 보십시오. Black Forest Labs가 아파치 2.0 라이선스로 공개한 40억 파라미터짜리 이미지 생성 모델입니다. 잠시 뒤 모델을 고르는 절에서 다시 볼 이름이지만, 지금은 빠르게 한 장 뽑아 보는 용도라고만 알고 시작하겠습니다.

* **실습 모델:** FLUX.2-klein 4B 데모 (Black Forest Labs가 아파치 2.0 라이선스로 공개한 40억 파라미터짜리 이미지 생성 모델)
* **GPU 사용 시간 한도:** 
  * 로그인하지 않으면 하루 2분
  * 무료 계정으로 로그인하면 하루 5분 (한 장에 몇 초 소요되므로 5분이면 수십 장 생성 가능)
  * 한도는 사용 시점 기준 24시간 뒤 회복되므로 **계정을 만들어 두는 것을 추천**합니다.

## 여섯 칸을 하나씩 채워 봅니다

첫 실습은 앞에서 본 대조 실험을 여러분 손으로 재현하는 것입니다. 중요한 것은 **한 번에 다 적지 않는 것**입니다. 한 칸씩 채우면서 무엇이 언제 바뀌는지 봐야 감이 잡힙니다.

* **시드(Seed) 고정:** 가능하면 시드를 고정하십시오. 데모 화면에 시드를 입력하는 칸이 있으면 아무 숫자나 넣고 그대로 두시면 됩니다. 그래야 결과의 차이가 프롬프트 때문이라고 말할 수 있습니다.
* **업무에 가까운 장면을 정해 아래 순서로 5번 만들어 보기:**

|  차례   | 채울 칸          | 예시                                                                                                                        |
| :---: | :------------ | :------------------------------------------------------------------------------------------------------------------------ |
| **1** | **피사체만**      | `a factory worker`                                                                                                        |
| **2** | **+ 환경**      | `a factory worker at an inspection line inside a manufacturing plant`                                                     |
| **3** | **+ 동작과 끝점**  | `...leans over the line and stops with one hand resting on the rail`                                                      |
| **4** | **+ 카메라**     | `Medium shot, static camera, 50mm lens. ...`                                                                              |
| **5** | **+ 조명과 스타일** | `... Soft morning light from tall windows on the left. Photorealistic documentary photography, muted industrial palette.` |

> **💡 핵심 질문:** 다섯 장을 나란히 놓고 *"어느 단계에서 가장 크게 바뀌었습니까?"* 스스로에게 물어보십시오. 대개 카메라를 적은 **4번**에서 가장 크게 바뀝니다. 그때까지 모델이 마음대로 정하고 있던 것이 바로 그 칸이기 때문입니다.

## 무엇을 관찰해야 하는가
그림이 예쁜지 보는 것이 아니라 **적은 것이 반영됐는지** 보는 연습입니다. 아래 세 가지를 확인하십시오.

1. **적은 것이 들어왔는가:** 50mm 렌즈라고 적었으면 화각이 그럴듯해졌는지, 왼쪽 조명이라 적었으면 그림자가 오른쪽으로 떨어지는지 봅니다. 안 들어왔다면 모델이 못 알아듣는 표현이므로 다른 말로 바꿔 적어야 합니다.
2. **안 적은 것이 이상하게 채워졌는가:** 나이나 성별을 안 적었다면 모델이 임의로 고릅니다. 의도와 다르다면 모델이 틀린 게 아니라 안 적은 것입니다.
3. **요소를 더할수록 무너지지 않는가:** 한 장면에 사람 다섯, 사건 셋을 넣으면 어느 순간부터 모델이 감당하지 못합니다. **이 경계가 어디쯤인지 손으로 알아내는 것**이 실습의 목적입니다. 무너지기 시작하면 프롬프트를 늘리는 대신 장면을 나눠 여러 번 만들어야 합니다.

## 한국어로 적어도 될까

* 한번 시험해 보십시오. 같은 내용을 한국어로 적었을 때와 영어로 적었을 때를 비교해 보시기 바랍니다.
* 대체로 학습 데이터 캡션이 영어에 치우쳐 있어 **영어 쪽이 안정적**입니다.
* 다만 최근 모델들은 다국어를 다루는 언어모델이 텍스트 인코더로 들어가 있어 한국어도 훨씬 잘 받습니다.
* **실용적인 절충안:** **한국어로 장면을 정리한 다음 코딩 에이전트에게 영어 프롬프트로 옮겨 달라고 하는 것**입니다.

## 일부러 무너뜨려 보기

성공하는 프롬프트만 써 보면 경계를 모릅니다. 어디서부터 안 되는지를 알아야 실무에서 계획을 세울 수 있습니다.

1. **요소를 계속 더해 봅니다**
   * 인물을 하나씩 더 넣고 각자 다른 동작을 시켜보며 감당 한계를 확인합니다.
   ![[Pasted image 20260730155130.png]]
   * 인물 넷에 각기 다른 동작 넷과 배경의 지게차, 벽의 경고 표지판까지 한꺼번에 요청한 결과입니다. 다섯 명이 나왔고, 아무도 시킨 동작을 하지 않으며, 손과 얼굴이 뭉개졌고, 표지판 글자는 낙서가 됐습니다. 사진으로 요청했는데 화풍까지 일러스트 쪽으로 미끄러졌습니다.
   ![[Pasted image 20260730155140.png]]
   * 오류 패턴:* 인물 수 변경, 몸 없는 얼굴이나 주인 없는 손 발생, 동작 뒤섞임, 화면 안 글자가 낙서로 변함, 화풍 벗어남 등.
   * **주의할 점:** 이때 프롬프트를 더 길게 쓰면("손가락 다섯 개", "정확히 네 명" 등) 오히려 나빠집니다. 답은 **장면을 나누는 것**입니다. 네 명이 필요하면 두 명씩 두 번 만들어 붙이거나, 애초에 한 명이 나오는 구도로 바꿉니다.
   
2. **화면 안에 글자를 넣어 봅니다**
   * 안전 표지판에 "점검 중"이라고 적히게 해 보고, 영어로도 시켜 봅니다.
   * 특히 한글은 영어보다 어렵습니다. 글자 생성의 한계를 확인해 두면 "글자는 나중에 넣자"는 실무 판단을 내릴 수 있습니다.

## 6. 기록해 두십시오 (실습 정리 표)
도구의 성격을 적어 두고, 나중에 다른 도구로 옮길 때 비교하는 용도입니다.

| 항목 | 내가 확인한 것 |
| :--- | :--- |
| **어느 칸을 채웠을 때 가장 크게 바뀌었나** | |
| **이 도구가 못 알아듣는 표현이 있었나** | |
| **인물이나 사물을 몇 개까지 넣으니 무너지기 시작했나** | |
| **화면 안 글자는 어느 정도까지 되나 (영어 / 한글)** | |
| **한국어 프롬프트와 영어 프롬프트의 차이** | |
| **같은 프롬프트를 다시 넣었을 때 얼마나 비슷하게 나오나** | |

> **📌 실무 팁:** 시드를 고정하지 않으면 같은 문장으로도 매번 다른 그림이 나오는데, 그 편차가 얼마나 큰지가 도구마다 다릅니다. 편차가 크면 "괜찮은 게 나올 때까지 여러 번 뽑는" 전략이 통하고, 편차가 작으면 프롬프트 자체를 고쳐야 합니다.
