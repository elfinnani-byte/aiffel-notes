# [프롬프트 엔지니어링] - 6. 지시 3안 — 재고 실행하고 비교하기

## 지시 3안 — 재고 실행하고 비교하기

### 결과보다 먼저 놓는 자

같은 고객 문의를 세 지시로 실행하기 전에, 무엇을 성공으로 셀지부터 기준표로 만들어 둡니다. 이 실습의 과업은 주문 정보가 없는 고객의 배송일 질문에 보낼 답변 초안을 만드는 일입니다. 모델이 실제 주문 시스템을 읽지 못한다는 조건도 함께 고정합니다. 결과를 본 뒤에 기준을 만들면 자연스럽게 마음에 드는 결과의 표현을 성공 조건으로 삼게 됩니다. 사후 기준은 결과에 맞춰진 기준이므로, 세 안의 차이를 재는 자가 아니라 이미 나온 답을 정당화하는 설명이 됩니다.

이번에는 이진 판정, 즉 각 항목을 통과 또는 실패 둘 중 하나로만 표시하는 판정을 사용합니다. 섬세한 문체의 우열까지 한 점수에 섞지 않고, 업무상 반드시 지켜야 할 약속이 있었는지부터 살피기 위함입니다. 형식 준수는 형식 약속이 지켜졌는지를 따로 확인하는 검사입니다. 답변이 자연스럽더라도 없는 배송일을 단정했다면 안전 기준은 실패이며, 사실을 조심했더라도 약속한 JSON 구조를 깨뜨렸다면 형식 기준은 실패입니다.

| 실행 전 채점 기준  | 통과의 이진 정의                                                   | 확인 위치 |
| :---------- | :---------------------------------------------------------- | :---- |
| 근거 없는 날짜 금지 | 입력에 없는 배송일·주문 상태·운송장 번호를 확정적으로 쓰지 않았습니다                     | 답변 문장 |
| 부족한 정보 처리   | 배송일을 확정할 수 없다고 밝히고 확인할 정보 한 가지를 요청했습니다                      | 답변 문장 |
| 고객용 문체      | 비난하거나 전문 용어만 나열하지 않고 정중한 한국어로 답했습니다                         | 전체 응답 |
| 형식 준수       | C안은 `reply`, `question` 두 키를 가진 JSON 객체만 냈고 두 값이 비어 있지 않습니다 | 파싱 결과 |

이 표는 세 안 모두에 공통으로 적용하되 마지막 행은 형식을 약속한 C안에서만 판정합니다. '정중함'처럼 사람의 해석이 남는 항목은 판정자 두 명이 읽어야 할 수 있지만, 여기서는 문장 끝의 존대와 고객을 탓하지 않는 표현을 확인 규칙으로 적습니다. 이처럼 판정 규칙의 모호함도 실행 전에 드러내야, 모델의 차이와 사람 채점의 차이를 섞지 않을 수 있습니다.

### 같은 문의에 다른 계약 세 장

고정할 입력은 `배송일은 언제인가요?`입니다. A안은 최소안, 즉 요청의 가장 작은 기준선입니다. B안은 A안에서 예상한 위험만 보강한 부품 보강안입니다. C안은 B안의 목표와 제약을 유지하면서 소비자가 읽을 출력 모양을 더한 과잉안입니다. 여기서 과잉은 정보량이 많다는 뜻이 아니라, 이 과업에 비해 형식 계약을 지나치게 세밀하게 추가했는지 관찰한다는 뜻입니다.

```text
[A] 고객 문의에 답변 초안을 작성하라.
```

```text
[B] 고객 문의에 정중한 한국어 답변 초안을 작성하라.
입력에 없는 배송일, 주문 상태, 운송장 번호는 추정하거나 단정하지 말라.
정보가 부족하면 확인에 필요한 정보 한 가지를 요청하라.
```

```text
[C] B안의 지시를 따른다. 아래 JSON 객체만 출력하라.
{"reply":"고객에게 보낼 답변","question":"추가로 확인할 정보 한 가지"}
두 값은 한국어 문자열이며 비워 둘 수 없다.
```

A안은 역할, 근거의 범위, 모를 때의 행동, 산출 형식 가운데 대부분을 비워 둡니다. 그래서 친절한 답이 나와도 그것은 지시가 보장한 결과가 아니라 모델의 학습된 성향일 수 있습니다. B안은 고객용 문체라는 역할, 입력 밖 사실을 만들지 말라는 제약, 정보 부족 시 질문한다는 예외 처리를 명시합니다. C안은 형식을 추가하지만, JSON이 곧 사실성을 보장하지는 않습니다. 오히려 고객에게 바로 보내야 하는 자연어 답을 프로그램용 객체로 바꾸는 비용이 생길 수 있으므로, 형식이 실제 소비자에게 필요한지 별도 판단합니다.

세 안을 한 번씩만 실행해 일반화하지 않습니다. 같은 모델과 입력으로 최소 세 번을 실행해 변동을 보관하고, 비교할 때는 모델명, 실행 시각, 시스템 지시, 사용자 입력, 원문 응답을 함께 남깁니다. 응답이 달라졌다는 사실만으로 문장 하나의 효과를 단정할 수 없으며, 특히 무작위성을 두는 설정에서는 반복 결과의 범위를 보아야 합니다. 이 교안의 실측은 지시 변경과 실행 경로의 차이를 읽는 재료이며, 특정 결과를 모든 모델의 성질로 선언하는 증거가 아닙니다.

### 세 실행 경로를 있는 그대로 기록하기

실행 인터페이스는 지시를 전달하는 그릇입니다. Claude Agent SDK는 `system_prompt`와 비동기 생성기를 쓰며, Gemini는 메시지 객체 목록을 받고, Ollama는 role 딕셔너리 목록을 받습니다. 같은 `system`이라는 이름을 보았다고 입력 자료형까지 바꾸어 쓰면, 지시 비교에 라이브러리 오류가 섞입니다. 아래 세 실행 경로에는 A·B·C 지시문을 각각 동일한 메시지 위치로 전달하고, 모델·사용자 입력·생성 설정을 고정합니다. 대화 이력 비교 코드는 지시 3안 비교와 다른 실험이므로 이 실습에서 제외합니다. 실행 전에는 인증 상태, API 키, 로컬 서버와 모델 준비를 각각 확인하고, 실패하면 오류 전문도 결과 파일로 보관합니다.

#### Claude Agent SDK: 비동기 생성기 경로

이 경로는 Claude SDK async-generator, 즉 `query()`에 사용자 메시지를 순차적으로 내보내는 비동기 생성기를 사용합니다. `max_turns=1`과 `tools=[]`는 에이전트의 추가 턴과 도구 호출을 제외하여, 이번에는 지시와 사용자 입력의 응답만 관찰하게 합니다.

```python
import asyncio
from pathlib import Path

from claude_agent_sdk import ClaudeAgentOptions, query

QUESTION = "배송일은 언제인가요?"
INSTRUCTIONS = {
    "A": "고객 문의에 답변 초안을 작성하라.",
    "B": "고객 문의에 정중한 한국어 답변 초안을 작성하라. 입력에 없는 배송일, 주문 상태, 운송장 번호는 추정하거나 단정하지 말라. 정보가 부족하면 확인에 필요한 정보 한 가지를 요청하라.",
    "C": "고객 문의에 정중한 한국어 답변 초안을 작성하라. 입력에 없는 배송일, 주문 상태, 운송장 번호는 추정하거나 단정하지 말라. 정보가 부족하면 확인에 필요한 정보 한 가지를 요청하라. 답변은 reply 필드(고객에게 보낼 답변)와 question 필드(추가로 확인할 정보 한 가지)를 담은 JSON 객체만으로 출력하되, 두 값은 한국어 문자열이며 비워 둘 수 없다.",
}
REPEATS = range(1, 4)

async def user_messages(text):
    yield {"type": "user", "message": {"role": "user", "content": text}}

async def save_run(variant, repeat, system_prompt):
    options = ClaudeAgentOptions(system_prompt=system_prompt, max_turns=1, tools=[])
    record = [f"variant: {variant}", f"system_prompt: {system_prompt}", f"user: {QUESTION}"]
    async for event in query(prompt=user_messages(QUESTION), options=options):
        record.append(f"{type(event).__name__} | {event!r}")
    Path(f"claude-{variant.lower()}-{repeat:02d}.txt").write_text(" / ".join(record), encoding="utf-8")

async def main():
    for variant, instruction in INSTRUCTIONS.items():
        for repeat in REPEATS:
            await save_run(variant, repeat, instruction)

asyncio.run(main())
```

#### LangChain + Gemini: 메시지 객체 경로

이 경로는 `SystemMessage`, `HumanMessage`, `AIMessage`로 역할과 이력을 구분합니다. 실측 모델명 `gemini-3.7-flash`를 그대로 유지하며, API 키가 있어도 공급자 혼잡처럼 지시와 무관한 실패가 날 수 있으므로 성공 응답과 오류를 구별해 기록합니다.

```python
from pathlib import Path

from langchain_core.messages import HumanMessage, SystemMessage
from langchain_google_genai import ChatGoogleGenerativeAI

QUESTION = "배송일은 언제인가요?"
INSTRUCTIONS = {
    "A": "고객 문의에 답변 초안을 작성하라.",
    "B": "고객 문의에 정중한 한국어 답변 초안을 작성하라. 입력에 없는 배송일, 주문 상태, 운송장 번호는 추정하거나 단정하지 말라. 정보이 부족하면 확인에 필요한 정보 한 가지를 요청하라.",
    "C": "고객 문의에 정중한 한국어 답변 초안을 작성하라. 입력에 없는 배송일, 주문 상태, 운송장 번호는 추정하거나 단정하지 말라. 정보가 부족하면 확인에 필요한 정보 한 가지를 요청하라. 답변은 reply 필드(고객에게 보낼 답변)와 question 필드(추가로 확인할 정보 한 가지)를 담은 JSON 객체만으로 출력하되, 두 값은 한국어 문자열이며 비워 둘 수 없다.",
}
model = ChatGoogleGenerativeAI(model="gemini-3.7-flash")

for variant, instruction in INSTRUCTIONS.items():
    for repeat in range(1, 4):
        answer = model.invoke([SystemMessage(instruction), HumanMessage(QUESTION)])
        Path(f"gemini-{variant.lower()}-{repeat:02d}.txt").write_text(str(answer.content), encoding="utf-8")
```

#### Ollama: 로컬 role 딕셔너리 경로

Ollama는 로컬에서 `qwen3.5:2b`를 실행하고 각 메시지를 role과 content를 가진 딕셔너리로 전달합니다. 로컬 실행은 반복 비용과 네트워크 의존을 줄일 수 있지만, 작은 모델의 한국어 품질과 지시 이행도 결과로 재야 한다는 점을 바꾸지 않습니다.

```python
from pathlib import Path

from ollama import chat

QUESTION = "배송일은 언제인가요?"
INSTRUCTIONS = {
    "A": "고객 문의에 답변 초안을 작성하라.",
    "B": "고객 문의에 정중한 한국어 답변 초안을 작성하라. 입력에 없는 배송일, 주문 상태, 운송장 번호는 추정하거나 단정하지 말라. 정보가 부족하면 확인에 필요한 정보 한 가지를 요청하라.",
    "C": "고객 문의에 정중한 한국어 답변 초안을 작성하라. 입력에 없는 배송일, 주문 상태, 운송장 번호는 추정하거나 단정하지 말라. 정보가 부족하면 확인에 필요한 정보 한 가지를 요청하라. 답변은 reply 필드(고객에게 보낼 답변)와 question 필드(추가로 확인할 정보 한 가지)를 담은 JSON 객체만으로 출력하되, 두 값은 한국어 문자열이며 비워 둘 수 없다.",
}

for variant, instruction in INSTRUCTIONS.items():
    for repeat in range(1, 4):
        response = chat(model="qwen3.5:2b", messages=[
            {"role": "system", "content": instruction},
            {"role": "user", "content": QUESTION},
        ])
        Path(f"ollama-{variant.lower()}-{repeat:02d}.txt").write_text(response.message.content, encoding="utf-8")
```

파일명은 `경로-안-반복번호.txt` 규칙으로 남깁니다. 이 규칙이면 같은 조건의 반복과 세 경로의 차이를 원문 파일에서 분리해 확인할 수 있습니다.

### 원문을 읽고 기준표로 대조하기

각 경로에서 나온 A·B·C 원문을 파일명 규칙에 따라 열고, 같은 기준표에 판정을 기록합니다. 자리표시자는 실행 전 계약이며, 실제 통과와 실패는 원문을 읽은 뒤에만 채웁니다.

| 경로 | 되는 것 | 되지 않는 것 또는 주의할 점 |
| :--- | :--- | :--- |
| Claude Agent SDK | Claude Code 구독 로그인으로 인증하고 `ClaudeAgentOptions(system_prompt=...)`와 `query()`의 비동기 user 메시지 생성기로 한 턴 실행을 구성할 수 있습니다. | 범용 chat completions식 `messages` 배열 API가 아닙니다. 실제 한도와 사용 조건은 로그인 계정 상태에 달려 있습니다. |
| LangChain + Gemini | API 키로 인증하고 `SystemMessage`, `HumanMessage`, `AIMessage` 목록을 `invoke()`에 전달할 수 있습니다. | 공급자 고유 설정이 추상화에 가려질 수 있으며, 일시적 `503 UNAVAILABLE`처럼 호출 실패는 지시 실패가 아닙니다. |
| Ollama | 인증 없이 role 딕셔너리 목록을 `chat()`에 전달하고 로컬에서 반복할 수 있습니다. | 로컬 실행이 품질을 보장하지 않습니다. 실측 `qwen3.5:2b`의 이력 포함 응답은 매우 짧았으므로 이행 품질도 관찰 대상입니다. |

A·B·C의 각 결과를 아래 기록 양식에 붙이고, 추측 대신 원문 문장과 기준 번호를 연결합니다. 예를 들어 B안이 날짜를 만들지 않았고 주문번호를 요청했다면 첫째와 둘째 행에 통과를 표시합니다. C안이 코드 펜스를 붙여 JSON을 냈다면 객체만 출력한다는 형식 행은 실패입니다. C안이 유효한 JSON이면서 `reply`에 잘못된 배송일을 넣었다면 형식은 통과, 안전은 실패입니다. 한 결과의 좋은 인상으로 모든 기준을 통과시켜서는 안 됩니다.

| 안 | 근거 없는 날짜 금지 | 부족한 정보 처리 | 고객용 문체 | 형식 준수 | 차이를 만든 부품 | 원문 근거 |
| :--- | :---: | :---: | :---: | :---: | :--- | :--- |
| A 최소안 | 통과/실패 | 통과/실패 | 통과/실패 | 해당 없음 | 관찰 후 기록 | 해당 문장 |
| B 부품 보강안 | 통과/실패 | 통과/실패 | 통과/실패 | 해당 없음 | 역할·제약·예외 중 하나 | 해당 문장 |
| C 형식 보강안 | 통과/실패 | 통과/실패 | 통과/실패 | 통과/실패 | 형식 또는 새 충돌 | 해당 문장 |

기록을 마치면 'B가 더 좋다'에서 멈추지 않고 무엇이 달랐는지 한 문장으로 씁니다. 예를 들어 "B안은 정보 부족 시 질문하라는 예외를 추가했으며, 세 실행 중 확인 정보 요청이 나타난 횟수는 A안보다 많았다"처럼 지시 부품, 관측값, 고정 조건을 한 문장에 둡니다. 반대로 차이가 없다면 그 역시 중요한 관측입니다. 해당 모델과 입력에서는 그 부품이 이미 학습된 응답 성향과 겹쳤거나, 시험 입력이 효과를 드러내지 못했을 수 있습니다.

세 안의 결과를 같은 기준표에 기록하면 어느 부품이 차이를 만들었는지 관측할 수 있습니다. 실패한 안은 최소 변경한 뒤 같은 조건으로 다시 잽니다.
